根目录是插件对宿主的单一发布边界：`package.json` 的 `main`/`exports` 定义三个入口——服务端 `lib/index.js`（cordis 插件，注册工具与 `/learnhub/api` 路由）、客户端 `lib/client.js`（CJS 单文件，经 `window.__ModuleLoader__.load` 握手并由宿主提供 react/@deepseek-ai 依赖）、独立引擎 `lib/engine.js`（不含 cordis HTTP 层，供脚本/测试消费）。`build.mjs` 串联四个阶段：先构建 `ui/` Vite SPA 到 `web/dist` 并拷贝 katex/three 到 `web/vendor`，再用 esbuild 编译三产物并清理空白行，最后将 `skills/` 同步到 `DSH_HOME/skills` 供所有会话扫描。运行时通过 `peerDependencies` + `scripts/link-peers.mjs` 注入宿主 profile，使本插件与宿主私有包在同一 node_modules 解析域工作；`cordis.patch.yml` 在宿主启动时注入 vault/provider/model 等机器级配置。子模块按此契约分工：`src/` 提供引擎与宿主面，`ui/` 仅产出静态 SPA 并通过 `/learnhub/api` 通信，`tests/` 基于 Node `node:test` 对引擎、路由、UI 组件与架构门做回归，`docs/` 集中 ADR 与 Agent 章程被 `scripts/` 的门与 `AGENTS.md` 引用，`preset_skills/` 随构建分发到宿主 skills 目录。
