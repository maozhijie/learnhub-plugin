# 调研:节点内课程生成质量提升

- 日期:2026-09-07
- 状态:定稿(调研任务,不含实施决策)
- 评价维度排序:学习效果 > 可读性 > 生成时间/重试率
- 源材料:同目录三份笔记([vault-audit.md](vault-audit.md) / [learning-science.md](learning-science.md) / [industry-scan.md](industry-scan.md));共识由 grill 会话达成,方向清单见 §6

## 0. TL;DR

1. **弹性缺失的第一杠杆不在内容 prompt,而在图层**:280 个节点的 est 挤在 10–35 分钟(80% 在 20–25),est 实际是"档位感常数"而非复杂度度量。不改 est/难度信号,任何内容侧弹性都会失锚。
2. **膨胀有实证**:est=20min 的入门概率节点被规划 8 个节段(≈2.5 分钟/节);学习科学甜蜜区是 3–6 分钟/段、全文按 est 推导 1–6 段。
3. **重试多的病理是三层叠加**:flash+不思考直出长结构化内容 × 十余条机械格式门禁(plot 纯 JSON、### 禁用等)× "全文重写仅一轮"的修复策略。行业参照:Khanmigo 约 31% 生成项需人改或弃用——高首过失败率是常态,优化目标是**首过率+廉价修复**,不是完美模型。
4. **"每节段强制可视化"与一致性原则冲突**;六类节段菜单(概念/例题/演示/小结/练习/交互)中的例题/演示有样例效应背书,应保留但**指导密度随节点难度伸缩**。
5. 题量弹性:大纲阶段按 est/difficulty 分档给每节段目标题量;收尾难题只对高难度节点启用。

## 1. 现状管线(代码事实)

生成由 host 层编排,分三步,每步过手写校验门禁:

1. **大纲**:上下文包 + `课程大纲` prompt → LLM → 节段清单 manifest(全 pending),落盘为节点 frontmatter `content.sections`
2. **逐节正文**:每个节段一次 LLM 调用,输出 Markdown(`## 类型:标题` 起头);门禁失败触发唯一一条自动重试回路
3. **出题**:每内容节 2 道(有练习节时 1 道)+ 综合测验固定 3 道;出题侧无重试,单题校验失败即丢弃

## 2. 问题诊断

### 2.1 弹性缺失:约束藏在哪

节数在 prompt v5 已松绑("节的划分、数量、顺序与类型配比完全由你判断"),真正写死的数量约束只有三处:

1. **题量**——每内容节 2 道(有练习节 1 道)在 `src/engine/index.ts:1098-1099` 写死;综合测验 3 道在 `src/index.ts:295` 写死。
2. **过时残留口径**——上下文包 §6 仍发"练习 基础 2–4 / 变式 2–3 / 挑战 0–2"(`src/engine/content.ts:168`),与正文 prompt"练习由题库与练习节承载"(`:273`)互相矛盾,同一 prompt 内两套指令争抢注意力。
3. **软锚定失真**——大纲 prompt"通常 3–8 节"没有复杂度依据;实测(§3)est=20min 的入门节点取了上限 8 节。"每节段至少一个可视化"(`:262-329` 硬约束)+ 150 字纪律在低复杂度节点上进一步放大膨胀感。

### 2.2 重试多的根因组合

重试仅发生在节正文门禁失败(`GATE_FAILED`),不是 JSON 解析失败。根因是三层叠加:

- **模型层**:flash + `effort: off` 直出长结构化内容,格式纪律"偶发违反"是常态(代码注释自认:`src/index.ts:196-198`)
- **门禁层**:10+ 种 findings 来源,大半是**格式级**而非语义级——对 LLM 最脆的恰好是必死的:plot/chart 必须纯 JSON(尾随逗号即死)、`###` 子标题禁用、正文 >2000 字、mermaid 引号、别名不一致、交互件 200KB/外联/缺 LEARNHUB_COMPLETE
- **修复层**:唯一回路是"全文回灌重写一轮"——不带错误行定位、重写自身可引入新违规,表现为"反复卡同一节、修完又坏"

配套问题:出题侧**零重试**、纯丢弃式容错(单题失败 `skipped++`,单节 YAML 非法 `continue`);`max_tokens` 截断只 warn 不重试(`src/index.ts:170-173`)。

行业参照:Khanmigo 约 31% 的 AI 生成项需人工修改或弃用(The Learning Standard);Duolingo 同样是多阶段人审流水线。**高首过失败率是行业常态,方向应是首过率提升 + 廉价程序性修复 + 人审锚点,而非指望模型完美。**

### 2.3 学习效果无反馈通道

mastery、练习证据、FSRS 作答数据都在积累,但没有任何通道回流生成侧;mastery 计算方案本身"仍在探索中"(CONTEXT.md)。行业里难度自适应的成熟形态(如 Duolingo Birdbrain)恰恰是**作答期**从题池选题,而非生成期决定——支持把闭环列为远期单独立项(共识 Q6)。

### 2.4 管线测试覆盖为零

`tests/` 只有图结构质量(S1-S4)与健康分共 13 个用例;内容管线全部纯静态函数(`parseOutline`/`gateReport`/`checkSectionShape`/`checkVisualBlocks`/`validateBank`/重试回路)零覆盖。任何门禁放宽都可能无声破坏既有行为——这是所有改动的前置风险。

## 3. Vault 实证审计

> 全文:[vault-audit.md](vault-audit.md)。数据源:学习中心数学课(280 节点)+ `state/` 运行痕迹。

**核心限制**:课程四天内重造三轮(MathForGames→MathToDev→现名),当前 280 个节点全部未生成内容;历史产物随重置丢失。节段/题目分布统计做不了,实证=图层数据+3 个生成个案+1 份完整质检报告。

- **est 无区分度(最重要发现)**:280 节点 est 直方图 10/15/20/25/30/35 → 3/34/129/95/18/1,p25=20、中位 20、p75=25。est 与图深度相关 0.365、与 pre 数 0.278、与 difficulty 0.520;同难度内 est 几乎无离散。est 在实践中是"档位感常数"。
- **膨胀个案**:est=20min、difficulty=2 的入门概率节点规划 **8 节段**(≈2.5min/段)且大纲重排一次仍是 8 节;est=15 的向量入门节点 6 节段。
- **失败实锤**:该概率节点任务 failed,质检报告两条硬伤均为格式级:`plot 第 1 块不是合法 JSON`、`### 子标题`;⚠ 正文 1936 字(150 字纪律与 8 节段规划互相拉扯的产物)。
- **速度基线**:向量节点 6 节段约 2 分钟(15–25 秒/节段调用)——通过时很快,**时间都耗在重试与失败上,优化重点是首过率**。
- 其他:difficulty 分布 1–5=11/43/116/101/9;bloom 集中在"应用 170/理解 87";enc 边全课程为 0(上下文包 enc 区块恒空);practice 节点 0 个(交互件规范暂无真实 exercising)。

## 4. 学习科学视角

> 全文:[learning-science.md](learning-science.md)(含全部文献出处)。此处只列映射结论。

| 原则 | 对本系统的映射 |
|---|---|
| 分段原则(Mayer):3–6 分钟/段完播最优 | 节段数应**由 est 推导**(est 20min → 4–6 段),幅度 1–6,取代"通常 3–8" |
| 样例效应 + 专业度反转:新手受益于完整指导,熟练后指导变冗余 | "例题/演示"节段保留;**指导密度随节点 difficulty/bloom 伸缩**——低难度节点不必配齐演示+例题+小结,这正是"简单节点膨胀"的教学法解药 |
| 一致性原则:可视化是手段不是配额 | "每节段至少一个可视化"改为"大多数节段应有",允许纯文字说明节 |
| 测试效应 + 前向测试效应:检索练习增强后续学习 | 节段末低配检索点值得保留;题量不必恒定,题型偏回忆而非纯再认 |
| 合意困难(Bjork):困难须在可成功前提下 | 收尾难度 3 题只对高难度节点启用;简单节点全难度 1–2 |
| ICAP 框架:Interactive>Constructive>Active>Passive | practice 交互件是顶格资产;反思/开放题"少用"引导与 ICAP 不冲突 |
| 掌握学习 | 难度自适应最终应基于学习者数据——远期闭环的文献依据 |

## 5. 行业对照

> 全文:[industry-scan.md](industry-scan.md)(含全部来源)。

- **Duolingo**:LLM 一课生成 10 题(数量同样固定)→ 多阶段人工专家审校 → Birdbrain 在**作答期**按学习者水平从题池选题。启示:数量固定不是原罪,与内容无关的固定才是;按复杂度分档的模板即可达行业水准。
- **Khanmigo**:grounding 在人审内容库,约 31% 生成项需人改/弃用。启示:高失败率常态,人审锚点(与 ADR-0003 同构)是公允设计;上下文包方向正确。
- **Brilliant**:问题先行、最简版本出发、即时反馈;AI 定位为"把设计师意图展开成内容"而非自主决定内容。
- **共性**:①结构模板 + 人工锚点,没有一家完全交给模型;②质量控制是流水线(生成→程序校验→人审→数据反馈),不是单点门禁。

## 6. 改进方向(按优先级)

### P0 复杂度信号重建(一切弹性的前置)

est 已被证明无区分度(§3)。重建方案:

- **短期**:改用 `difficulty(1–5) × bloom × 图深度` 做分层主信号,est 仅作容量上界(节点 ≤30min 是领域约定)。
- **伴随**:图生成侧修 est 标注纪律(健康分已有 est 覆盖检查,可加"分布压缩"检查项)。
- 传导机制:上下文包新增"复杂度档案"区块 → prompt 锚定节段数与篇幅(如 difficulty 1–2 → 1–3 段、difficulty 4–5 → 4–6 段,由 est 修正);门禁只拦方向性极端(如 est<10min 却 8 节)。学习科学依据:§4 分段原则;行业依据:Duolingo 分档模板。

### P1 门禁改革 + 修复升级(重试率的直接解)

- 格式类 findings **程序性修复优先**:plot/chart JSON 尾随逗号/空白容忍(解析前清洗)、mermaid 引号自动转义——能代码修的不麻烦模型。
- 不可程序修复的格式类(### 子标题等)**降级为 warn 或定向修复**;门禁 findings 聚焦语义(超纲引用、交互件完整性)。
- 修复轮从"全文重写"改为**带错误定位的局部修补**:把 findings + 违规行摘录回灌,要求只重写违规块。
- 前置风险:内容管线测试为零(§2.4),改门禁前先补 `gateReport`/`checkSectionShape`/`checkVisualBlocks`/`validateBank` 单测(全部纯静态函数,可测性极好)。

### P2 弹性结构(大纲与正文)

- 节段数幅度改为 1–6 且由复杂度档案推导;"小结"节段不再是隐性必配。
- "每节段至少一个可视化"→"最多一个,大多数节段应有";150 字纪律改为随档位伸缩(如低档 ≤150 字、高档 ≤400 字,>600 字维持 warn)。
- 六类节段菜单保留(样例效应背书 + parseOutline 硬校验是有价值脚手架);"自定义出口"列为观察项,当前证据不足以放开。

### P3 题量弹性

- 大纲阶段为每节段附带目标题量(按复杂度分档,如低档每段 0–1 题、高档 2–3 题);综合题数随 est 伸缩(1–5 道)而非恒 3。
- validateBank 维持只管形状;题型菜单保持开放,"反思/开放题少用"维持引导(ICAP 不冲突)。
- 收尾难度 3 仅对 difficulty≥3 的节点要求。

### P4 分层档位(时间换质量)

- 简单节点维持 flash/effort off;difficulty≥4 或深度深的节点升思考档(至少大纲与修复轮升档,正文可维持 fast)。
- 依据:速度基线显示通过时单节段仅 15–25 秒,升档的成本集中在复杂节点,可控。

### 次级:practice 交互件

同管线改进(P1 修复策略、P4 档位)天然外溢;交互件特有约束(单文件、200KB、LEARNHUB_COMPLETE)在真实 practice 节点出现后再单独评估(当前课程 0 个 practice 节点,无 exercising 数据)。

### 远期(单独立项)

作答数据回流生成(全错题→正文重写/补节段)与 Birdbrain 式作答期难度自适应;前置条件是 mastery 计算方案稳定。

## 7. 成功度量

- 门禁首过率(节正文一次通过比例)、每节段平均模型调用数(现上限 2)
- 节段数/正文字数与 difficulty×est 的相关性(弹性真实生效,目标:强正相关)
- 低难度节点(est≤15 或 difficulty≤2)中位节段数(膨胀消退,目标 ≤3)
- 题量与节点复杂度的相关性;题型分布(反思/开放题占比)
- 人工抽检可读性(锚点人审,量表待定义)
