# 节质检门分层：契约类硬拦、倾向类 warn、满编放行

节生成质检门（`content.ts::gateReport` + `sectionApply` 的落盘门）此前把所有 finding 一律硬拦：正文过长（单节预算 ×2 拒收线）、可视化块超上限、plot/chart 非法 JSON、svg 形状、别名、交互件契约混在一张清单里，配一轮自动修复，仍败则任务 failed。真实运行数据（vault 运行日志 2026-09-04 → 09-12 一周，18,772 行门相关日志）显示这套门的主要产出是**制造失败而不是保证质量**：同一个节因「```plot 第 1 块不是合法 JSON 对象」留下 4,149 次重复失败快照（面板只是降级为源码显示，模型一轮修复修不好）；低档节正文 606 字超 500 字拒收线（预算 250×2）反复触发，而节点已满编 8 节，拆节阶梯（ADR-0054 修复末级）走到死路——压缩、拆节、重写三条路都封死，任务只能 failed。

理由：门的 finding/warn 分层此前没有说破的判据，逐条拍阈值导致「面板显示降级」和「字数略超」这类倾向性问题与「承诺的可视化根本不渲染」这类契约问题同罪。而修复阶梯的真实结构是：契约类（可视化块、predict 块）程序可定位可修补（`blockPatchPlan` 块级局部修补已存在），倾向类（长度、子标题）在阶梯尽头只能靠放行。判据不立，门就会继续把修不好的东西硬拦到任务失败。

关键裁决：

- **硬拦 = 输出契约的结构合法性。** 可视化块（plot/chart/svg/交互件）与 learnhub-predict 预测门是模板向学习者**声明了的消费面契约**：非法意味着声明的东西根本不渲染，是「承诺了却没兑现」——保留硬拦，阈值一律不动（可视化 ≤2、拒收线 = 预算 ×2）。
- **warn = 教学质量与预算倾向。** ### 子标题（上轮「门禁改革」已降）、正文偏长/过长、超纲引用、uses 标注——影响的是学习体验倾向，不是契约兑现。倾向类的最后裁决权在人审（正文落盘本就是 draft 状态待人审）。
- **满编放行。** 节清单已到 `MAX_SECTIONS`（8）时，「正文过长」的拒收没有修复阶梯可走（压缩修复轮已试败、拆节需新增节会越上限）——此时长度 finding 降为 warn 放行落盘：`demoteCapLengthFindings` 纯函数执行，摘要（N 字超拒收线 M 字、满编、人工复核兜底）进 journal `content_section` 条目与任务 message 留痕。findings 混入任何非长度项（契约类）时不降级——契约未兑现仍然拦；未满编时拆节阶梯仍有效，行为不变。
- **契约类 finding 说明增强。** plot/chart 非法 JSON 的 finding 附解析器原始报错与期望形态最小示例，svg 附块首行原文，predict 附期望四行字段骨架——给块级修补轮足够信息一次修对（一周 4,149 次重复失败的核心病灶是修复轮拿不到可执行的错误描述）。finding 前缀「```<lang> 第 N 块」逐字保留，`BLOCK_FINDING_RE` 的块级修补定位口径不变。
- **提示词去重。** 模板散文里的门禁机械规则（1.3/2 倍阈值、可视化 ≤2 拒收句、### 子标题提示句）删除——阈值以质检门为单源，散文只留设计导向（1–2 屏、硬约束、可视化为主、预算见 §9），防两处漂移（### 子标题文案曾与门实际行为脱节）。四个模板 bump v11→v12，`PROMPT_CHANGELOG` 已登记。量规锚点同步：节正文量规「篇幅预算」判据的原句锚点随散文删除而漂移，改锚到存留句「字数额度见上下文包 §9 复杂度档案」（#221 锚门执法，测试当场变红揭出——锚点机制本身证明了去重的必要：阈值散文正是会漂移的那部分）。

边界：

- **修复轮数不变。** `OUTPUT_CONTRACTS` 登记的 2 轮修复阶梯（块级局部修补 + 整节压缩修复升 deep 档）一字不动；说明增强预期提升首轮命中率，命中率数据积累后再议加轮。
- **冒烟面板的「正文质检门」检查项不动**（`host/smoke.ts` 只读消费 `contentCheck`）；离线质量评审（量规 lane，ADR-0070）与出题门禁零变化。
- **`fixRichBlocks` 程序化修复不动**——它仍是落盘前的第一道双保险，本 ADR 的说明增强是它之后的第二道。
- **不做配置化。** 阈值与降级规则是常量 + 测试（仓库纪律）：满编放行不是可调参的宽容度，是「阶梯尽头不挡交付」的结构性裁决。

替代方案（否决）：

- **plot/chart 非法 JSON 降 warn**——面板降级为源码显示确实无害，但它同时是修复轮最该修的东西；降 warn 等于把「声明了可视化却交付了源码」的节放进学习页。否决：保留硬拦 + 说明增强。
- **拒收线加低档地板（如 ≥600 字）或倍率放宽到 ×2.5**——09-12 的失败根因不是阈值紧，是满编后无路可走；阈值本身有拆节阶梯兜着。放宽阈值会让所有节变长（「可视化为主」的导向靠 warn 引导已够）。否决：阈值不动，只修死路。
- **满编时改走人工确认（暂停任务等人点头）**——队列单并发，等人会把整条生成链挂起；且正文落盘本就是 draft 待人审，多一道确认是把同一道人审付两次。否决：warn 放行 + 留痕。
- **门禁阈值做成机器配置项**——与仓库「阈值是常量 + 测试」的纪律相悖，多一个没人校准的面。否决。
