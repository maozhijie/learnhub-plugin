# 宿主 runtime：显式对象承载全部可变态

`src/index.ts` 3029 行、仓库最大文件、**零测试覆盖**，8 处模块级可变状态（`engine` 引用约 286 处、`genJobs` 30、`CENTER_REL` 11、`VAULT` 9、`genQueuePaused` 6、`quizJobResults` 5、`genPumping` 4、`lastSessionStartAt` 3）让队列泵、路由表、工具面**既无法抽层也无法单测**。代价已实测吃到：一次宿主抽离漏了 14 个标识符（host 模块没 export、宿主没回引），而 707 个测试全绿、`npm run build` 通过（esbuild 只剥类型）、`node --check` 只验语法——**只有运行时才会炸**。本 ADR 定宿主状态与装配的形态：引入 `createHostRuntime(ctx, config): HostRuntime` **显式对象**，含全部可变态；技术层函数一律收 runtime 参数；除常量外宿主模块级 `let` 归零。宿主因此第一次可测：造一个 runtime 就能断言队列泵状态机与「路由 ↔ 工具」对账。

理由：8 处可变态是「无法单测」的**直接原因**，不是附带现象——队列泵的状态机（入队 → 执行 → 终态 → 保留期清扫）、暂停／恢复、`quizJobResults` 的等待语义，全部读写这些模块级 `let`／`Map`；测试要断言它们就必须能造出一份隔离的状态，而模块级状态在同一个 Node 进程里**无法隔离**（并行会话与测试互相污染）。同时，这 8 处状态把技术层与「谁在何时改它」绑死在文件级，导致 `handleApi`（990 行／120 条路由）、工具区（941 行／111 个工具）、队列泵都长在同一份隐式全局上。最后，ADR-0045 的命令注册表投递侧需要一个**显式 runtime 作为依赖注入的落点**——把它先立起来，注册表的数据化才有地方挂。

关键裁决：

- **形态：显式 runtime 对象。** `createHostRuntime(ctx, config): HostRuntime`，字段分三组：`engine`（门面实例）、`vault`／`centerRel`（部署路径）、`jobs`（生成任务注册表 + 结果表）与 `flags`（`queuePaused`／`pumping`／`lastSessionStartAt`）。**类型可命名、可导出**——这是它能被测的原因。
- **除常量外，宿主模块级 `let` 归零。** 保留为模块级 `const` 的：`AGENT_GUIDE`、`GRAPH_JOB_PHASES`、`LOG_LIMIT`、`API`、`PAGE`（常量与常量表，无运行时可变性）。8 处可变态全部进 runtime。
- **技术层函数一律收 runtime 参数**（不在函数体内引用模块级状态），因此每个技术层函数在测试里都可用自造 runtime 直接调用。
- **文件划分**：`runtime.ts`（构造与装配）／`jobs.ts`（入队、泵、保留期清扫、job runner）／`api.ts`（路由表 + 分发）／`static.ts`（面板与 vendor 伺服）／`tools.ts`（工具面注册）+ **薄 `index.ts`**（`apply` 只做装配）。
- **路由表数据化为 runtime 的下一刀**：表项 `{ method, route, handler }`，**预留 ADR-0045 命令注册表投递侧的字段位**；POST 段的 73 个内嵌分支拆为子表。**120 条路由的行为与响应形状逐字不变**（公共面零改动）。路由表是 ADR-0045 骨架 A 的前置——数据化后应**直接演进为命令注册表的投递侧**，而不是先造一遍再改（#165 已如此裁定）。
- **工具面按域分组**：注册循环不变，**111 个工具名与 schema 逐字不变**；只把 941 行平铺改成按域（学习／图谱／题库／项目／学习者产出／实验室／通道／维护）的分组表。分组是**适配器的组织方式**，不改变工具面本身。
- **宿主首次可测（本形态的直接收益）**：造 runtime 断言队列泵状态机（入队 → 执行 → 终态 → 保留期清扫）、暂停／恢复、`quizJobResults` 等待语义、路由表（表项唯一、方法／路径格式、未命中行为），以及**路由 ↔ 工具对账基线**（ADR-0045 实测：84 个共享引擎入口／工具独有 26／路由独有 49），作为命令注册表迁移的回归网。
- **本形态是 #154 一批宿主类票的前置，且是双重身份**（#154 的更正评论已记）：既是重构前置，也是**测试前置**——#154 假设的「既有 HTTP 测试面」实测不存在（`tests/` 零命中 `handleApi`／`/learnhub/api`／`createServer`／`fetch`），唯一 HTTP 检查是手跑的 `scripts/smoke-panel.mjs`。因此按规格与 #154 的边：**本票阻塞 #157／#160／#161 的宿主侧部分**，与「路由表数据化」票（阻塞 #156／#158 的宿主侧部分）分开切票。

边界：

- **公共面零改动**：8 处可变态的收拢、路由表化、工具分组都不得改变门面签名、host／UI／测试调用点、路由行为、工具名与 schema。
- **不改变队列语义**（FIFO、可取消、重启可恢复、阻尼）——本 ADR 只把状态**搬家并显式化**，不改行为。
- 宿主端到端／浏览器测试不在本轮（`scripts/smoke-panel.mjs`／`e2e.mjs` 已覆盖面板冒烟）；本 ADR 只到 runtime 单测与静态门。
- **不引 WS 栈**：面板通知保持纯客户端轮询（App 级 10s 任务注册表 diff + 60s 复诊在途 diff），ADR-0038 已否决 allo 的同步长请求 + WS 形态。
- `src/index.ts:1964-1965` 的 `mkdirSync`／`writeFileSync`（首启 seed `learnhub.json`）随本票一并收进 runtime 的构造路径（见 ADR-0046 边界）。
- 本 ADR 不裁命令注册表的表项形状（见 ADR-0045），也不裁门的清单与刚性（见 ADR-0047）。

替代方案（否决）：

- **state 模块**（引出 `state.ts`，导出可变的 `let`／`Map`，各技术层 import 它）——只是把模块级可变状态换了个文件，**仍是全局单例**：并行会话与测试照样互相污染，「谁能改」仍无类型约束，加载顺序依赖依旧隐式；而它唯一的收益（改动最小）恰好就是它的问题所在。
- **工厂闭包**（`createHost(ctx)` 返回一组闭包，状态藏在闭包变量里）——状态确实私有，但每加一个技术层就要多穿一层闭包参数，**类型无法命名**（`HostRuntime` 导不出来，测试无法对 runtime 结构做断言），测试要读状态只能为每个字段手写 accessor——等于把类型面的活重做一遍且做得更差。
- **保持模块级 `let`，只做文件拆分**——「抽离漏 14 个标识符而 707 测试全绿」就是这个前提的反证：8 处可变态正是无法单测的根因，只拆文件不解决它，而且拆出的技术层仍要靠隐式全局互相发现。
- **全量搬进一个类**（`class Host { ... }`，全部状态变 `this`）——为 3029 行引入一个巨型类与满屏 `this`，与 ADR-0043 对 mixin 的否决同理：文件会瘦，但职责边界更糊、类型跳转与调试栈失焦，且「哪些字段是队列的、哪些是路由的」依然无结构。显式 runtime 对象用三组字段就把这层结构表达了。
- **让 runtime 持有 `ctx`**（把宿主 ctx 也塞进 runtime，技术层直接从 runtime 取 ctx）——会把投递层与宿主 API 的耦合面从 `apply` 一个点扩散到全部技术层，ADR-0044 的层次划分随之破。`ctx` 应只出现在 `apply` 与真正的适配器文件（`host/llm.ts` 等）。
