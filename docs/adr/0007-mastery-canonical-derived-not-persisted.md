# 掌握度口径收敛：派生值唯一 canonical，正确率不是掌握度

引擎里曾并存两套「掌握度」口径：题库正确率聚合（原 `nodeMastery`，Σcorrect/Σattempts）与 FSRS 稳定度 + 练习证据 EMA 的复合派生值（`masteryOfFm`）。决议（#19 / #31，2026-09-08）：**后者是唯一 canonical**——Mastery 一词只指 `masteryOfFm`；它是读侧派生的视图，**不落盘**（frontmatter 的 `mastery` 键退役为可选旧字段，`nodeComplete` 不再写回，新笔记不带该键）；题库正确率立为独立词汇「作答正确率」，只服务完成门禁与单题作答统计，任何界面不再把它展示为掌握度；完成门禁（PASS_SCORE 及格判定）与 Mastery 彻底解耦，继续用正确率，语义是「这次学得够不够」，不是「已掌握」。

理由：CONTEXT.md 对 Mastery 的定义（主要参考 FSRS、复合状态、忠实表达实际掌握）只有派生值满足；正确率会因一次全对会话饱和到 1.0，表达不了长期记忆状态；且两口径并存已造成同一存储字段写读不一致（`nodeComplete` 写 A、分析侧用 B 重算）。代价要有预期：LessonView 头部的掌握度在全对首学后只在三成附近、随复习渐近满分（防饱和设计使然，不是 bug），节点级「正确率」读数从头部与作答响应撤下。配套约束：节点 frontmatter 的聚合代表 `fsrs` 必须随后续复习回刷，否则派生值的稳定度分量停在完成时刻——这是本决议成立的前提，见对应实施工单。
