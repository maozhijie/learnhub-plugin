# ADR-0073: 生成语料补齐工具调用载荷（回路站的产物在语料里可见）

> **落盘形态已被 ADR-0103 取代**（2026-09-17）：工具调用载荷改入「调用记录」的响应载荷块；本篇的段式落盘与读侧段界不再适用，「回路站产物在存档里可见」的意图由新形态承接。

日期：2026-09-13 ｜ 票：#236 ｜ 总纲：#212 ｜ 依赖：#213（生成语料捕获/ADR-0060）、#222+#224（离线评审器与图质量面审计/ADR-0070）

## 背景与问题

生成语料（#213 / ADR-0060）只记两样东西：**文本输出**（缝出口的 `output: r.text`）与工具的**名字**（回路提示词的逐轮渲染写成「（请求工具：submit）」）。于是以工具调用承载实质产物的站——教练回合 `agentLoop` 的裁决 op、罗盘画线、判卷之外的回路站——在语料里成了一件「outcome=ok、reply_chars=0、原始输出（空输出）」的**空壳**。#224 图质量面审计的教练轴实跑实测：教练生长 4 件捕获里 3 件如此，审计可评率只剩 1 件（而教练生长是图质量面唯一的语料站）。

后果是三用途同时失效：语料作为**解析器回归 fixture 源**、**质量评审抽样池**、**换模型/换供应商的格式漂移标本**，在回路站上都看不见模型真正的产物；#216 工具通道 spike 的结论（自愿调用工具的收益/代价）在语料侧也无法复核——工具臂的载荷没留档。

## 裁决

### 1. 记录侧：`CorpusRecordInput.toolCalls`（`{name, arguments}`，arguments 原文）

适配器缝出口的 `withCapture` 泛型加 `toolCalls?: LlmToolCall[]`（可选，补全缝天然没有），成功分支把载荷随行落进捕获记录。**调用 id 不进档**（id 是会话内标识：回路回灌需要它，归档无意义——端口返回形状因此不变，`llmStreamSeam` 仍原样回传 `r.toolCalls`）。调用级失败分支不落载荷：那时没有产物，audit 价值在失败码本身（原纪律）。

### 2. 落盘侧：`## 工具调用` 段，逐条一行 JSON

`renderMd` 在 `## 原始输出` 之后追加 `## 工具调用` 段，每行一条 `{"name":…,"arguments":…}`；arguments 原文**不清洗、不截断**（与「原始输出」同级的原文留档纪律）。段**只在有载荷时出现**——无工具调用的站文件形态与 #213 逐字一致，历史语料与既有夹具不受扰动。

**为什么逐条一行而不是一个 JSON 数组**：一行一条把坏行的影响面压到最小（读侧按行兜底），且人读时一行一次调用；数组形态一处语法坏就整段不可读。

### 3. 读侧：`parseCorpusFile` 增返 `toolCalls`；段界重算

段界从「`## 原始输出` 到 EOF」改为「到下一个段标记」——否则新段整个被输出段吞掉，载荷会静默变成产物文本的一部分（正是「静默失效」类缺陷）。**旧格式兼容**：段缺席 = 空数组（历史语料照读）。段内坏行**不静默丢**：以 `（未解析）` 占位保留原文——一条坏行不该让整件载荷从读侧消失。

### 4. 回路提示词段：工具调用带参数原文（`renderLoopPrompt`）

旧渲染只记名，于是**后续轮次**的提示词段读不出上一轮的裁决载荷（回路历史里只剩「请求过 submit」）。改为逐条 JSON（与落盘段同形）。这是**观测面改动**：真实请求走 `toDshMessage`，本就带 arguments，提示词段只是它的可读副本。

### 5. 消费侧：受评对象 = 文本 + 工具调用载荷的**合并视图**

`artifactTextOf(sample)` 是唯一取数口径（文本在前、`[工具调用 <name>]` + arguments 逐条在后），三处消费随之统一：

- `isScoreable`：**两者皆空**才不可评——文本为空而载荷在场**可评**（产物在参数里，不是没有产物）；
- 两期提示词的「被评产物原文」块：正是合并视图；
- 证据定位核对（`evidenceLocated`）：以合并视图为产物原文，引文落在载荷里同样算定位成功。

**防锚定纪律不动**：一期仍不给生成提示词与元数据（#222 的匿名纪律不因产物形态变化而松动）。

### 6. 边界（如实登记）

- **诊断面不动**：outcome 三态、环形封顶（ok 25 / bad 200）、补标迁桶、G8/G9 裁决（单文件观测写、不入 runWriteUnit、不写 journal）一律不变——本票只加内容段。
- **冒烟站表未跟**：`host/smoke.ts` 的站表仍只读 frontmatter 的 `reply_chars`；工具调用件的文本侧**确实**为 0，这是如实读数而非缺项（载荷本体在文件里、读侧可取）。要让站表直接显示载荷，需再加 `tool_calls: N` frontmatter 键——本票不做：同一事实两处落档是漂移源，且票面规格的「三处对齐」（记录/渲染/读侧）不含 frontmatter。
- **历史空壳不可追认**：修复前落盘的捕获件没有载荷段，读侧只能读成「不可评」——可评率回升**只对修复后的新捕获成立**（票面验收「真跑一轮教练生长后」即此口径）。
- **教练站的工具调用是取证轮、不是裁决轮**（实跑抓出，如实登记）：教练工具面是只读白名单（`graph_view`/`node_card`/…），裁决 op 仍以文本回程。故本票对教练生长期的收益是**取证可见**（查了哪张视图、按哪个真节点名查），不是「裁决载荷恢复」。由此的候选发现（不在本票）：回路站受评对象可再分取证轮/裁决轮，否则可评率回升会把取证轮混进「教练回合」裁决轴的抽样池。

## 工程影响

记录侧 `withCapture` 泛型加宽 + 载荷随行（`host/llm.ts`）、落盘段与读侧解析（`host/corpus.ts`，含段界重算与坏行兜底）、样本投影随行 `toolCalls`（`host/quality-review.ts`）、受评对象合并视图与三处消费（`engine/quality-review.ts`）、门面重导出 `artifactTextOf` + `TOOL_CALLS_MARKER`/`parseCorpusFile` 读侧常量（`engine/index.ts`）；ADR-0060 §5 的「工具调用只记名」按本 ADR 修订。

G5 基线同提交迁移（4 个受控文件，全部是本票净增内容）：`host/corpus.ts 291→341`（段渲染 + 段界重算 + 坏行兜底 + 常量与注释）、`host/llm.ts 371→385`（泛型加宽 + 载荷映射 + 提示词渲染）、`engine/quality-review.ts 615→630`（合并视图 + 可评分判据 + 文档）、`host/quality-review.ts 253→255`（投影随行）。

实测链：`tests/corpus.test.ts` +2（段落档与逐条回读；旧格式照读 + 坏行占位）、`tests/llm-capture.test.ts` +2（回路轮载荷落档且端口返回形状不变；上一轮参数进下一轮提示词段）、`tests/quality-review.test.ts` +5（可评分性三态；合并视图；一期盲评含载荷且仍不给生成提示词；证据定位以合并视图为产物原文含对照；宿主读侧投影直通可评）、`tests/quality-review-runner.test.ts` +1（端到端：文本为空而载荷在场 → 不列未评分件、载荷进一期受评对象）。

**真实链路实跑**（自建 profile + 临时 vault + 真 provider，用户宿主未动）：教练生长 16 件捕获中 7 件文本为空而载荷在场、9 件带载荷段；同一 corpus 可评率 56%（修复前口径 9/16）→ **100%（16/16）**；真评审器一轮 pool 16 / selected 4 / **unscoreable 0** / failures 0。装置、逐件读数与「教练站工具调用是取证轮而非裁决轮」的修正见 `docs/research/2026-09-13-corpus-tool-call-payload.md`。
