# ADR-0065: 提示词契约后置——单拼装缝 + 契约段末位 + 变更登记

日期：2026-09-13 ｜ 票：#218 ｜ 总纲：#212（生成管线稳定性与内容质量工作流）｜ 依赖：#227（节间连贯注入，已落地）

## 背景与问题

轴2 审计（#212 §四.1）的系统性发现：**所有站的拼接顺序都是 `模板 + --- + 上下文包/材料`**，而输出契约段（`## 输出` + 「只输出 X」）坐在模板末尾 = 最终 prompt 的**中段**，其后拖着最重的材料（全节点正文数千字、查重块、概念清单、禁止概念 ≤200、图面）。lost-in-middle 的研究方向明确：契约应离生成点最近。全仓唯一反例是回执评审——契约住在 system 提示词里（#88 / ADR-0016 落地时就是那个形状）——它恰好是「契约离生成点最近」的现成先例，也是本 ADR 的参照物。

## 裁决

### 1. 一个拼装缝，全部站点共用（`src/engine/prompt-assembly.ts`）

`withContractLast(tpl, materials)` 是最终 prompt 的唯一出口：把模板切成 `[前段 | 契约段]`（契约段 = 最后一个 `## 输出…` 一级标题到模板末尾），材料插在两者之间。**零依赖叶子**（同 `io.ts` 形态）：`content.ts`（整节修复轮）与 `seed.ts`（种子修复轮）都要用它，而 `content.ts → seed.ts` 已有边——切分逻辑必须住在两边都能引、又不成环的地方，否则两处各自实现一遍切分必然漂移。

**为什么是「切模板」而不是「改调用点字符串」**：14 处调用点各写一遍段序，等于把「契约在后」这个不变量复制 14 份，改一处漏一处没人知道。切模板把它变成一条：模板只要末节是 `## 输出…`，段序自动正确。

修复轮同构：`sectionRepairPrompt` / `seedRepairPrompt` / `decompileRepairPrompt` 都改成收「模板 + 材料」两半，回灌块（上次输出、质检清单、压缩目标、受理门反馈）算**材料**——修复轮里模型最后读到的依旧是「只输出 X」，质检清单不占契约的位置。里程碑草案站的包由门面方法整体拼装（调用方拿不到两半），走 `withContractLast(已拼装包, 反馈块)`：切分对「模板」与「已拼装 prompt」是同一个操作（都切最后一个 `## 输出…`），所以不需要第二个函数。

7 个模板为满足「末节即契约段」做了结构手术（契约句从 `## 硬约束 1` 里拎出来独立成 `## 输出`，或把已有的 `## 输出` 段与后续段换序），文本**逐字搬移**、不重写语义——所有既有模板锚点断言（`tests/prompt-contract.test.ts`）零改动通过，这是「只搬不改」的证据。

### 2. 门（`tests/output-contract.test.ts` 同门扩三条 + 一条文本门）

- **契约段形状门**：① 模板末节必须是 `## 输出…`；② 该站契约句必须落在**契约段里**——判据从「模板里出现过」收紧为「在最终 prompt 的末段里」，因为前者恰好漏掉本次要治的形态（schema 被挪回中段）；③ 契约段里除注册表声明的输出结构块（markdown-blocks 四块——它描述的是**产出**的一级节）外不得再有一级节，这是「材料拖在契约之后」的机器判据；④ 拼装产物以契约段收尾、材料在它之前。契约住 system 的站按注册表 `contractLocation` 推导豁免，不硬编码模板名。
- **拼装缝文本门**：`src/` 下零 `` `${tpl…` `` / `` `${template…` `` 形态（模板变量直接拼进 prompt 的旧签名），属性访问（`${tpl.title}`）不误咬。自检：注入必然违规样本断言被看见 + 收集面 >50 文件（防恒过）。
- **变更登记门**：见 §3。
- 四条门各带自检（ADR-0047 铁律①）：契约段后加一节、契约段改名、幽灵机制、见证串改坏、收集面塌缩，各自必须变红。

### 3. 变更登记（#220 的字段格式手工落位）

#220（提示词 changelog 纪律）未落地，本票按它的字段格式**手工登记**在契约注册表里：`PROMPT_CHANGELOG`（键 = PROMPT_KINDS 键，条目 = `version / date / changeType / expectedDelta`）。`expectedDelta` = **预期输出增量**——「这次改动预期模型输出发生什么变化」，供 #213 语料回放与 #222 评审对照对账「变了没有、变得对不对」。

不变式（门在执法）：**每个模板键的最高登记版本 == 模板头 `<!-- learnhub:prompt/vN -->` 的现行版本**——bump 了模板却没补条目 = 红。拼装侧重排改的是段序、模板文本未动，那些站的登记版本写现行版本、changeType 注明「拼装侧」，**不冒充一次模板内容变更**。本表自 #218 起计：之前的版本线没有登记面，编不出一份诚实的表；#220 落地后按同字段格式接管完整纪律（含「bump 决定必须来自提交」的历史面），本表并入。

改模板的 9 个站：`课程大纲 v11`（+完整输出示例）、`题目生成 v14`（+完整输出示例、section 示例占位化）、`项目里程碑计划 v8`、`项目里程碑产物 v7`、`项目目标反编译 v10`、`错误对比卡 v8`、`罗盘初画 v2`、`教练回合 v6`、`种子提案 v4`（契约句独立成节并置尾）。

### 4. 稀释治理（两处，逐条裁决）

- **上下文包 §5 禁止概念 ≤200**：**位置保留**——§5 是 §4 领域边界的展开，挪走要把 §6–§13 全部重编号，而模板按号引用 §8/§9/§10/§11，重编号会改掉那些锚点，收益无实测支撑；真正的 lost-in-middle 修复是整包前移（§1）。**截断策略改为显式**：上限提为命名常量 `FORBIDDEN_CONCEPT_CAP`，深度降序截取，**截断时如实告知**「本清单按图深度降序截取前 N 条，共 M 条；未列出的节点同样未学，同样不得出现或引用」——旧版静默截断，模型会把清单读成穷举。
- **反编译既有节点名清单**：按「区 · 块」**分段**（括号内给该组节点数），**不截断**。截断在这里是有害的：该清单是名字对账的**取值域**，门拿全集判、模型却按子集选，截断直接制造「拒收→回灌」循环。分段保住完备性，同时把千行平铺名单变成可扫读的结构。

### 5. few-shot：大纲与出题各补一个完整输出示例

#212 §四.2：#212 的 14 站里只有种子提案有操作化正反例，而 1–2 个格式精确示例是最强的格式稳定器。本票给**大纲与出题**两个高风险站各补一个完整输出示例，且示例内容全部改用**占位域素材**（甲/乙/丙），并在示例前明写「不得把示例值回填进你的输出」——旧版大纲 schema 里的示例值是真实内容（「整数与自然数的分界」），有被回填的风险，本次一并占位化。示例写作 `## 输出` 段内的 `### 子标题`：一级节的末位必须留给契约段本身（§2 的形状门），且示例里出现的 `## 给定` 一类块名是**产出**的一级节、不是模板的一级节，混用会让形状门失去分辨力。

## 后果

- 契约句在最终 prompt 的末段成为**机器可判**的形态；模板把 schema 挪回中段、材料拖在契约后，`npm test` 即红。
- 代价：模板多了一处「末节必须是 `## 输出…`」的形状约束，新站模板若把契约写在别处会被门拦下——这正是目的。
- 回执评审站零改动：它本来就是对的，本 ADR 把它从「孤例」变成「规范」。
- **效果结论不入本 ADR**（票面增补：格式随机化约束，FormatSpread arXiv:2310.11324）。本票给出的是**机制与门**；重排对解析成功率与多样性的影响需要多格式变体、多批重复的对照实验，单格式单变体的读数不构成结论。可用的量尺：#213 语料回放（解析成功率）与 #230 多样性仪表（ADR-0064：题面 self-BLEU / 干扰项编辑距离 / 题型分布熵 + 平均对相似度），两者都在重排前后同口径可复算；**本仓当前零真模型语料**（`state/生成语料` 空、`tests/fixtures/` 只有题库与多样性基线快照），所以「重排前后对照」与「冒烟成功率不降」（票面验收的一项，消费 #215，未落地）都**未执行**，如实登记为待测项，不冒充已验。
- 同口径可复算的部分本票已跑：多样性基线回放（`tests/question-diversity.test.ts`）与全部行为快照在重排后**逐值不变**——这只证明「测量面未被改动」，不证明「生成行为未变」；后者要真模型语料。
