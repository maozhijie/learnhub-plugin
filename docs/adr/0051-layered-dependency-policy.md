# 依赖三层政策：门零依赖、测试 devDep 逐票许可、运行时依赖论证制

「零新增依赖」在本仓**从未被整体裁决过**。它是两条各有限定域的局部裁决被逐票复述泛化的产物：ADR-0042 否决 eslint-boundaries／dependency-cruiser，裁的是**门的执法工具**用 node:test 零依赖实现；ADR-0045 §98 写「不引 zod／ajv／代码生成器／运行时输出校验；不新增任何依赖」，裁的是**注册表那一票的操作范围**。ADR-0049 把前者的复述升格为「零依赖口径」一词；到 #183 的验收标准，它成了 blanket 的「零新增依赖、零构建步骤变更」——立法源头限定域尽失，只剩禁令本身。

三件事实说明这条 blanket 规则既过宽又过窄：

- **过窄**：#154 依它裁了「不为此引入前端测试框架」之后，UI 的安全网只剩 tsc strict + 三条文本门 + 人工走查。#183（U1）是 9372 行的结构重构，没有 eslint（react-hooks 规则零覆盖）、没有任何运行时验证，而 AFK agent 无法执行人工走查——测试能力的真空不是被裁决出来的，是被一条复述出来的禁令锁死的。
- **过宽**：它从来管不住运行时依赖——`ui/` 在册 **15 个运行时依赖**，mermaid/echarts/mathjs/mafs/katex 五个重量级照加不误。实际被管住的只有测试/工具链依赖：**假的一致性**。
- **真实约束被错置**：本仓依赖的真实成本在 AGENTS.md 里写着——worktree 双份安装（根 + `ui/` 各一次）、npx junction 脆弱性。这些约束的是 **node_modules 安装面**，不是「依赖」这个抽象概念；devDep 与 runtime 依赖的代价结构完全不同，不该共用一条禁令。

关键裁决——依赖约束分三层，各层各管各的：

- **第一层：门的执法工具，永久零依赖。** ADR-0047 全文有效：所有门 node:test 原生、随 `npm test` 全量执行、带自检、阈值实测。任何"门需要装个 linter/cruiser 才能写"的提案，默认否决。
- **第二层：测试与工具链依赖（devDependencies），逐票许可。** 票面须写明：引什么、为什么更便宜的替代不够、装在哪个子包、体积数字。允许 DOM 模拟与查询类库（jsdom／happy-dom／@testing-library/*）；**不建第二个 runner、不建第二套测试配置面**——runner 保持 node:test（测试库对 runner 无感，引库不引 runner）。永不进任何运行时产物。
- **第三层：运行时依赖（dependencies），论证制。** 票面须给 min+gzip 量级的体积审计数字与维护成本评估；重量级默认否决，须附懒加载方案或替代论证。存量五重的审计与懒加载裁决归 #187。
- **构建步骤的边界随之澄清**：构建期**代码生成**仍被否决（ADR-0045／ADR-0049 维持）；vite 既有能力的配置微调（如 React.lazy 分包）不构成「新增构建步骤」。未来票面不得再写 blanket 的「零新增依赖、零构建步骤变更」——引用本 ADR 的三层口径逐层写。

替代方案（否决）：

- **维持 blanket 零新增依赖**——把两个限定域裁决永久化成教条。它的直接后果已经发生：#154 的测试豁免被无边界复述到 #183，一张 9372 行的结构重构票只能靠人工走查验收，与 `可交给Agent` 的标签自相矛盾。且它对 15 个运行时依赖睁眼瞎，是假的一致性。
- **全面放开（依赖自由）**——忽视本仓真实约束：双份安装、junction 脆弱、bundle 无人管。运行时依赖仍需闸门，只是闸门从"禁令"改成"论证"。
- **runner 换 vitest**——第二个 runner 等于第二套配置面 + lockfile 分叉；本仓 node:test 原生 TS 直跑已验证（Node ≥22）、门家族全挂其上。@testing-library 对 runner 无感，第二层引库即可，不必引 runner。

边界：

- **不改 ADR-0042／ADR-0047 的任何门规则**，**不改 ADR-0045／ADR-0049 的 codegen 否决**。ADR-0045 §98「不新增任何依赖」的原义保留于其票域（注册表施工），本 ADR 只收回它的越界复述。
- #154 的「不为此引入前端测试框架」由本 ADR **精确化**：精确后的读法是"不引浏览器环境模拟框架"作 blanket；L3 类组件测试按第二层许可制执行（#187 的 U2 票）。#183 验收标准里的「零新增依赖、零构建步骤变更」改引本 ADR（该票本身三层都不触发：结构搬移不加依赖）。
- 第二层许可的真实代价（worktree 双份安装随 `ui/` devDep 增长而加重）须写进各票的理由栏，作为许可考量的一部分。
