# ADR-0102：审计由非阻建议升为强制行动清单

日期：2026-09-17 ｜ 状态：已裁决（实施归票面）｜ 相关：ADR-0101（教练回单站回路）、ADR-0088（草稿通过 = 门通过）

## 裁了什么

**教练回合的审计输出分两层**：**门错误**（拦发布，照旧）与**行动清单**（非阻，但**必须回应**）。行动清单由审计的非阻检出派生，每条带可执行指向。

- **推进判据**：下一批补丁必须**逐条落实**清单项；某条不成立时，必须在回复文本里**显式驳回并给理由**；既不处理也不驳回 = **本批视为未推进**——作为可观测的失败形态计入日志与回执，不新增机械门。
- **生成与修复分档**：生成轮走默认思考档，**修复轮升档**，取代执行官站恒深档。
- 审计与发布门仍同源（草稿通过 = 门通过），发布门复验不变。

## 为什么

- **建议不追等于没有建议**：非阻检出此前是「该修的照修」——模型可以整批无视而不付任何代价。这正是「质量漂移」能在门全绿的情况下发生的原因：门只查结构合法性与汇合，够不到「算子选择与理由是否成立」。
- **强制回应把建议变成推进判据**：它不改门序列、不拦发布，只要求模型**在文本里交代**——因此不与「机械门不裁教学质量」的既有边界冲突，也不把人工裁决权交给机械门。
- **邻仓已在产线验证**：把审计产出做成「须逐条落实或显式驳回，否则视为未推进」的行动清单，是长程多批构建能跑满大轮次预算而不空转的主因之一；本仓缺的正是这一层。
- **恒深档是纯浪费**：合并后生成段与修复段工作性质不同——生成段维持默认档、修复段升档，比整站恒深更省，且把深档花在错误收敛上。

## 否决了什么

- **把非阻检出直接升为硬门（拦发布）**：检出里含倾向类判断（质量量规的提议面），硬门等于把裁决权交给机械门，与「AI 评分是提议、人审是终审」冲突。
- **保持非阻、靠人审兜**：人审面在离线报告里，回路内无人可兜；「该修的照修」实测等于「可以不修」。
- **只在提示词里写「请处理建议」**：无观测判据的祈使句；没有「未推进」这个可观测形态，漂移不可见。
- **生成段也升档**：把深档花在尚未定位错误的阶段，是合并后最贵的一段。

## 不做什么

- 不新增门序列、不改受理门与发布门；不把清单项做成一票一项的机械校验。
- 不改质量量规本体与离线评审（那是人审面）。
- 不引入邻仓的「发布前独立 LLM 终审软门」——独立成票。
