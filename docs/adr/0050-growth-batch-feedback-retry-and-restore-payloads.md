# 生成队列可靠性：回灌重裁、显式重试与重启负载恢复

生长批的失效链是单点的：教练一版裁决被受理门拒收（实机死法：「引用不存在的区 + 概念未铸名」，ADR-0041 已记录）→ 任务 failed → 自动触发点全被失败阻尼 → 课程**静默停止生长**，唯一信号是生成页深处一条红色标签和一条 12 秒即逝的通知，而错误文案说「修正后重提」——无人重提。同时重启恢复把图域任务的负载（种子表单、反编译/计划/里程碑参数、生长批注入）留在盘上不读回：排队的种子任务重启后进执行器才炸「负载缺失或 phase 未知」——静默变形。本 ADR 定三处修复的语义：**回灌止血**（引擎）、**显式重试**（宿主阻尼豁免 + UI 按钮）、**负载恢复**（恢复侧校验）。

理由：三处共享同一个根因——「一次失败 = 终局」的假设只在**全自动无监督**回路里成立，而生成队列今天有明确的人工监督面（生成页 + 任务通知），失败之后的正确动作是让人廉价地重新拉起，而不是等 24h 保留期过期。回灌重裁不是「多试几次」：教练的畸形产出是**上下文可见性问题**（图面/登记表已在提示词里，但门禁清单没有），把门错误原文回灌进重裁段，与正文管线的门禁修复轮（`applySectionWithRepair`）、大纲护栏反馈轮、里程碑轻量结构门是同一族既定模式——本 ADR 只是把这族模式补齐到生长批。

关键裁决：

- **回灌重裁缝放引擎 `coachGrowthBatch` 内，只包 propose 侧的受理门。** 受理门拒收（结构/概念对表/锚保护/巩固门/生长闸门/路线门）→ 门错误原文 + 被拒裁决 YAML 原文回灌教练重裁一次（全量包 + 图面，deep 档）→ 重裁产出再进受理门，过则照常受理。**重裁段结论即终审**：分歧声明只作可观测留痕，不再升级仲裁段——重裁本身已是加深的一轮，「恰一轮」封顶防重试风暴。重裁段内任何失败（模型调用/解析/仍被拒）都以合并错误抛出（【首轮】+【重裁】两轮死因，宿主任务消息与通知可读）。放引擎不放宿主：上下文包、图面、`parseGrowthVerdict` 都在方法内，宿主侧重跑要凭空重建整条组装链；且引擎侧修复对未来 agent 通道的教练回合消费方同效。**恰一轮**：金样本调用数基线（1/2/3）在成功路径上不动，拒收路径 +1；无指数退避、无重试风暴。schema 门（`parseGrowthVerdict`）不回灌——模板钉死产物形状、畸形率低，且它在任何段内先行，包进去会把三段式升级链整个卷进重跑。
- **重裁段进 `segments` 可观测**（tier=`repair`、effort=deep），宿主任务消息的段标签给「回灌重裁」。
- **显式重试 = force 豁免失败阻尼。** `enqueueGrowthBatch` 的 force（面板「生长一步」、失败通知与生成页的「重试」按钮，同走 POST /coach/growth）在上一批 **failed** 时豁免阻尼、终态记录覆盖重新入队；自动触点（无 force）阻尼逐字不回归——防「失败→排空→检查点→入队」烧 token 环的初衷不变。**已取消不豁免**：取消是明确的中止意图，重试只属于失败批。在途防重入照旧。
- **失败通知与生成页给「重试」按钮**（纯客户端，ADR-0038 无推送通道的边界不动）：生长批失败通知（App 级 toast）与生成页 failed 行各一枚，点击 = 重新下发面板生长命令。种子/罗盘/反编译/计划/里程碑的重试不做按钮——各自主页面已有重新下发的入口（表单/按钮），队列任务只是它们的异步形态。
- **重启恢复补读负载 + 恢复处校验。** `restoreGenJobs` 补读 `seedPayload`/`decompilePayload`/`planPayload`/`milestonePayload`/`growthInject`/`growthOutcome`（写入侧保证形状，恢复侧只做非空对象闸；损坏负载进执行器由引擎契约 fail loud）。排队图域任务恢复后缺必需负载（旧档案/未完整落盘）→ **恢复处**明确标 failed（「负载缺失…重新下发（可重试）」，盖 finishedAt）——不再留 queued 假象拖到执行器炸「负载缺失或 phase 未知」。契约收口为纯函数 `graphJobPayloadGap`（`generation-jobs.ts`，入队侧保证与恢复侧校验同源）；罗盘与生长零负载（course 键即全部入参）。

边界：

- **阻尼语义除「force 豁免 failed」一处外零改动**；自动触发点（节点完成/会话开始/队列空闲）的失败重拉仍被拒。
- 受理门本身零改动：门清单、错误文案、零落盘纪律（propose 拒不建 pending）全部原样。
- apply 失败（竞态/审计 ERROR）不回灌——沿既有「机器裁决不留 pending、自清后原样抛错」。
- 通知仍是纯客户端轮询 diff（10s 任务注册表）；「重试」按钮只是给 diff 产物加一个动作，不引推送。

替代方案（否决）：

- **宿主侧捕获后带 inject 重跑整个回合**——inject 是计划修订的语义（注入块进包），门错误塞进去是语义挪用；且整回合重跑多付一次轻量段调用，观测上也无法与计划修订注入区分。
- **失败自动重试 N 次**——失败阻尼存在的理由就是防无人监督的烧 token 环（本 ADR 要保护的正是它）；自动重试与「回灌重裁一次」的区别在后者携带死因、是修复轮而非盲目重跑，且一轮封顶。
- **恢复侧对缺负载任务静默丢弃**——注册表是面板的事实来源，静默丢弃让「队列里少了任务」无人可见；明确标 failed 可重试把处置权留给人。
