# 存储塌缩：一课程一文件 + schema v4 宣告式断裂（零迁移）

父裁决 ADR-0087 已定「图存储塌成单层：一区一文件 → 一课程一文件，扁平 `nodes[]`」；本 ADR 记录落地时的三个非显然取舍：**断裂方式**、**零迁移**、以及**随分区一起失去生存依据的审计规则**。

## 裁决

1. **单一正典文件 `data/图.yaml`**，形状 `{ nodes: [...] }`。`region` / `color` / `blocks` 键不存在（解析层 fail loud）。`GraphStore` 原语收缩为 `graphPath` / `load` / `graphDoc` / `writeGraphDoc` 四件；`loadRegionDoc` → `loadGraphDoc`。`Graph` 构造从 `regions` 改 `nodes`，节点对象列表随构造保留（`graph.nodes`——`declaredEncOf` 要 enc 的原始形态含 note，图视图的 `encOf` 会丢）。
2. **schema 主版本 3→4，宣告式断裂，零迁移脚本**（`CURRENT_SCHEMA_VERSION = 4`）。旧库（v3 及更早）启动硬门拒载，文案直接给出处置动作：**旧课由用户自删**，不提供迁移、不进存档区、不做双读。拒载文案不再指向 `scripts/migrate-v2.mjs`（那是 v2→v3 的一次性脚本，本版无对应物）。
3. **随分区退役的读数**（分组依据物理消失，无法保留口径）：
   - 审计 **R4 深度异常**（块内均值基线）与 **R5 跨区引用** 退役；规则编号不回收、不复用。
   - **R1/R14/R15/R16 审计文案**与正文上下文包去掉 `[区 · 块]` 坐标前缀，节点名与深度读数保留；规则阈值一律不动。
   - `floatNodes`（空降节点，健康分前置完备项）的「region 序靠后」改为「**图内声明序靠后（前 1/4 之外）**」——同一启发式在单文件上的自然推广，阈值不变。

## 备选与不选的理由

- **带迁移脚本**（解析旧分区文件合并成单文件）：旧库只有个位数实验课程，写+维护一个一次性脚本的成本高于删库重建；且迁移动作会把「旧形态还活着」的预期延续下去，违背宣告式断裂（ADR-0034 先例）的零兼容纪律。
- **保留多文件、仅去分区键**：文件数是分区语义的残影（区名即文件名），多文件正是「一区一文件」的存储式分组本体；塌缩要塌就塌到底。
- **R4 改全图均值基线**：块内局部基线是 R4 的全部信息量，换成全图均值后告警与 R1/R13 高度重叠且噪音更大——不如退役。

## 行为与门影响

- 建课脚手架落 `data/图.yaml`（`{ nodes: [] }`），`00_未分区.yaml` 退场；`addEndpoint` 落图、`removeEndpoint` 摘图、`applyEdit`/`applyEnrich` 重写、快照、enrich 指纹（`data/图.yaml` 单指纹）全部换单文件形态。
- 体检（data-check）：`graph_missing` 判据改为「`data/图.yaml` 缺席」；区名去重检查退役（单文件内节点重名照报）。
- 调度/今日事件与 `graphNode` 视图去 `region` 字段；就绪清单从按区分组改平铺。
- 棘轮基线（G1–G9）随结构变更同提交下调；无提示词模板改动（`src/engine/prompts/` 零触碰，T3/#282 已清完提示词面的区·块坐标）。
