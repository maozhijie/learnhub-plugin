# agent 交互收口统一缝：单发补全与只读工具回路双模式

引擎与 LLM 的全部交互收口到一个统一缝模块（`engine/agent.ts`），接口按业务事实分双模式——`complete()`（一次对话直接返回结果）与 `agentLoop()`（有界多轮迭代 + 只读工具调用）。全部 LLM 调用点迁入缝：策略重的六站（种子起草、教练生长、罗盘、目标反编译、计划草案、里程碑草案）先行，机械站（出卡、判卷、自注反馈）随后择机。回路实现走**自建有界工具回路**（llm.stream 原生 function calling + 只读引擎视图白名单 + 轮数上限），不创建宿主会话；缝上保留宿主会话适配位（`ctx.agents.create` + 按 agent 工具限制），教练未来需要全 agent 面（查 vault 笔记、查网）时切换，调用点零改动。

三条论据。**宿主早期破坏性更新频繁，调用策略需要与宿主形态解耦的家**：现状唯一缝只有传输层（llmSeam 适配空闲超时/截断重试/档位翻译），提示词组装、解析、受理门、修复轮散落 13+ 调用点——同一种「回灌修复」种子与反编译各写一份、生长批漏配，教练一次产出畸形即 failed，失败后自动触发点全被阻尼，课程静默停止生长（实机证据：数学课生长批死于「引用不存在的区 + 概念未铸名」，错误文案说「修正后重提」而无人重提）。缝把策略收口一处，dsh 更新只改适配文件。**教练质量：盲盒上下文包换按需自查**：教练只能吃固定包，引用了不存在的区也无处核实；工具回路让它查图自证名字、对表登记表概念后再裁决，受理门拒收率从源头下降。**双模式是业务事实不是过度设计**：出卡/判卷要一次直返，教练/罗盘要多轮迭代，一种机制硬套所有站必然两头不讨好。

关键裁决：
- **教练工具面 = 只读引擎视图白名单**（图视图、节点卡、概念登记表、行为摘要、题库概况、罗盘、终点锚）；教练不持任何写工具，写路径仍走提案→受理门→apply 正道。
- **原则：工具访问提升证据质量，受理门维持信任边界**——回路产物照过全部既有门（schema/结构/概念对表/锚保护/巩固/生长闸门），门不因回路存在而放松。
- **回路预算**：K≤6 次工具轮 + 1 次门错修复轮（受理门错误回灌重裁，取代散装回灌逻辑）；回路只在生成队列任务内运行；工具实现禁止递归入队/触发教练（防自激）。
- **不取宿主会话路线**（`ctx.agents.create` 可行但不作首途）：金样本回放测试纪律靠注入假 LlmComplete 脚本化应答，自建回路同样确定性可测，宿主会话则要造假会话机器；生长批五点高频触发，宿主会话每批一个可见会话刷 agent UI，且完整会话机器开销（持久化/投影/标题生成自身还烧一次 LLM）与一次补全循环不成比例。适配位留在缝里作后路。
- **生长批「回灌修复一轮」作为即时止血先行落地**（不等缝建成），它就是缝里门错修复轮的雏形，不作废。
- **升级顺序**：教练生长先升回路（实机死因即「不能查图自证」）；罗盘重画第二候选；种子/反编译维持单发+既有回灌（并入缝的门错修复轮形态）。
- **机械调用不升回路**——一次直返+既有修复够用，回路的轮数/延迟/成本税只花在值得多轮裁决的地方。
- **与 ADR-0038 的关系不变**：变的是引擎内部怎么调模型，不是谁来按按钮；面板下发与 agent 工具两条入口的调用策略在缝里汇流同源。
- CONTEXT.md「教练回合」词条同步改写：固定上下文包→基础上下文包+裁前只读自查。

替代方案（否决）：
- **宿主会话路线**（插件创建并监控 dsh 会话、按会话限工具）——作为缝的后路保留而非首途，理由见关键裁决第四条。
- **维持散装调用点+各站自带修复**——碎片现状即反证：回灌逻辑三站两样、生长批漏配，死后无自愈、课程静默停摆。
- **文本协议工具调用**（XML/标记块自发明协议）——宿主 llm.stream 的 GenerateOptions 原生 `tools` 字段直通 provider function calling，无需脆弱解析。

**归属补记（ADR-0044）**：本 ADR 定了缝的**形状**，但未定它**住哪一层、谁拥有 dsh 耦合**。该归属已由 ADR-0044 裁完，本 ADR 的形状裁决不变：端口住应用层（`engine/llm.ts` 的 `LlmComplete` + 照同形新增的 `LlmStream`）、`engine/agent.ts` 是应用层的端口消费者（`complete()` 与 `agentLoop()` 都住这里，含只读引擎视图白名单与 K 轮预算）、dsh 耦合 100% 收在 `host/llm.ts` 这一个适配器文件、投递层只做构造与注入；R3「engine 禁 import `@deepseek-ai/*`」因此成为应用层与适配器的分界线。
