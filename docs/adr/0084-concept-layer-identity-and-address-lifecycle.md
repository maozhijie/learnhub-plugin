# 概念层职责重划：登记表保留为身份系统、地址生命周期与治理纪律

概念登记表是 Learnhub 的**地址空间**：节点经 `teaches`/`assumes`/`misconceptions`、题目经 `invokes`，用**概念名（地址）**引用概念条目；沉淀记录也以概念地址书写。它是这套系统里**唯一不随节点改名/删除而流失的坐标轴**——`del_node`/`rename` 是图的一等操作，而概念条目「永不删除、只并入」。但它的写入面机械化（AI 有手无眼）、读出面残缺（收敛只能靠人偶然看见）、治理面无回路（唯一许给人判断的合并动作是唯一没有门的动作）——**概念层能正常生长，却不能自净**，信噪比随时间单向劣化且劣化不可见（详见父票 #260 的问题陈述）。

本 ADR 把这一轮概念层职责重划的**不可逆裁决**落成纸面；域词条（`CONTEXT.md`「概念」「概念登记表」「概念足迹」）按同一口径修订，两者的差值以 ADR 为准。实现面见 #262/#264/#265，共享面（教练工具面白名单与工具规格）归 #249。

## 裁决

**① 登记表保留为身份系统，不退役。** 理由：它管**身份**（一个名字至多属一条目，全部名字课程内联合唯一），图管**结构**（`pre`/`enc` 边与区/块）——两者是不同的问题域。身份问题无法外包给图：节点 `rename`/`del` 是一等操作，而概念地址必须跨这些操作存活（沉淀层档案坐标系，ADR-0034）。退役登记表 = 把「这个名字是哪个身份」的账丢给一个本来就不承诺名字稳定的地方。
*否决*：退役（身份无所依）；层级化 region/block 式多级（业务外）；语义模糊匹配（与「写侧恒精确」冲突，见「声明恒精确」条）。

**② 地址永不删除、只并入；退役 = 标记废弃，不是删除。** 名字并集（合并）与废弃标记**都不丢地址**：用旧名字写的历史记录仍精确解析到同一身份。删除即**断读**——历史流水与沉淀正典里那些地址会变成悬空，而它们是**追加正史、不可重写**。「信噪比退役」的需求由**标记**满足：废弃条目从**生成注入面**（概念清单 / 易混对 / 档位）与**候选面**退出（不再被注入、不再被提名）；「考古」需求由**保留全部别名解析**满足。废弃**可逆**（清标记即完全恢复：写侧只落 `true`，`false` 等同缺席，无残留字段）。
*否决*：硬删除（断读）；改名式软删除（改语义，且历史地址仍会断）。

**③ 单向混淆对合法，但为待复核态。** 写入侧**不自动补双向**（不无依据地造数据）；读侧**显式呈现单向状态**。单向**不是缺陷、也不是完成态**——它是**待复核态**，人审据此补全或确认（与「别名自动收编 / 定义自动更新永远人审」同一纪律）。

**④ 档位（知道/会用/能教）不进门禁、不进调度**（既裁；`src/engine/types.ts::CONCEPT_TIERS`）。可引用纪律句：**「概念档位只作生成注入与教练登记表档位视野的感知面，不进门禁、不进调度。」** 档位与 Mastery（0–1 掌握度，读侧派生、不落盘）是两个域，不互算。

*部分取代*：本句「不进门禁」半部已被 **[ADR-0105](./0105-concept-fields-as-gate-input.md)** 取代（档位随 `assumes` 进入门禁校验、按序比较）；「不进调度」保持有效。

**⑤ `assumes` 维持软语义，不参与传递闭包。** `assumes` 是**感知面**（节点假设学习者已会的前置概念），并入传递闭包会把感知**硬化**成隐式门禁。硬依赖只有 `pre`（无权重，管门禁/ready）；`enc` 是成分技能边（0–1），必须落在该节点 `pre` 传递闭包内。`assumes` 是概念引用、不是调度输入。

*部分取代*：本句「软语义、不进门禁」半部已被 **[ADR-0105](./0105-concept-fields-as-gate-input.md)** 取代（`assumes` 升格为门禁输入）；「不参与传递闭包、不进调度」保持有效。

**声明恒精确（贯穿①–⑤）**：写侧概念引用逐字命中在册名字（受理门拒收编造名）；名字变体不自动入册（别名合并走人审）。读侧的**子串发现**（概念足迹 query）只供找候选，空结果语义 = 「换宽词或读全表，不是不存在」。

## 自净判据（三条可检验）

概念层**能自净**当且仅当三条全满足——缺一条则逐步劣化：

1. **孤儿可见面**：有读侧投影能列出「没有节点教、没有题目 `invokes`」的概念（概念足迹，ADR-0077 / #249）。
2. **对称性纪律**：混淆对的单向/双向状态在读侧有显式呈现（本 ADR ③；读面 #262，候选派生 #265）。
3. **量级纪律**：概念侧有与节点侧**同规格**的量级告警（别名条数、混淆对条数的 WARN/ERROR 带，#264）。

## 行为与门影响

- **不碰路由 / 工具面**：本票不新增命令/工具声明，零行为快照迁移（`host-routes-baseline.json` / `host-tools-*.json` / `host-face-baseline.json` 不动）。
- **文件规模棘轮（G5）**：`concepts.ts` / `question-bank.ts` / `growth-subsystem.ts` / `coach-tools.ts` / `content.ts` / `content-subsystem.ts` / `sediment.ts` 行数随实现变化，同一提交按实测重写 `scripts/arch-baseline.json`（`--update`）。
- **零 canonical 写入、零新账本**：全部新机制是**读侧派生 + 登记表读改写**；持久化层只收「登记表条目（身份）」与「提案（动作）」两类。
- **提示词模板文本零改动**：废弃过滤全部发生在**注入组装层**——出题**概念清单**与**易混对**（`question-bank` 的 `.filter(!retired)` + `confusablePairsOf` 内部过滤）、**内容包 §12 误解坑位 + §13 前置概念档位**（`contextPack` 的 `retiredConcepts`，由 `contentPack` 经 `queryEntriesFor` 宽容读取——登记表 Broken 不拦生成，ADR-0071）、**教练登记表档位视野**（`growth-subsystem` 前沿 teaches/assumes 折叠）。不动 `src/engine/prompts/` 的模板文本、不新开提示词常量。按 #260 的用户裁定，本票**不占 `prompt-bump` 单点**；章程 §8 明记「同版本号下的注入面变化两门都不执法，靠人审兜」——回退点即上述各处 `deprecated` 过滤。**未过门登记**：语料回放与评审对照不适用（模板版本号集合无变化，`prompt-bump -- check` 恒绿）。

## 边界

- **登记表退役** → 否决（见 ①）。
- **别名自动收编 / 定义自动更新** → 永远人审；本 ADR 只补**人审面**，不补自动面。
- **登记表层级化（region/block 式多级）与语义模糊匹配** → 业务外。
- **节点 / 题目 / 调度语义** → 不改：不改任何门的判定，不改教学语义，不改 FSRS/XP。
- **UI** → 另票（图谱视图清理与概念层可见面）。
- **跨课程概念共享/合并** → 保持每课程独立命名空间的现状，另票再议。

## 替代方案（否决）

- **退役登记表，让图承载身份**——图不承诺名字稳定（`rename`/`del` 是一等操作），沉淀档案坐标系会随之流失。
- **废弃 = 删除条目**——断历史地址的读（追加正史不可重写），且与「条目永不删除、只并入」自相矛盾。
- **写入侧自动补双向混淆对**——无依据地造数据；改用「读侧显式呈现单向 + 候选派生走提案（#265）」。
- **档位并入门禁/调度**——把感知面硬化成门（与既裁冲突）；档位是「知道/会用/能教」的教学深度感知，不是掌握度（Mastery 是 0–1 读侧派生）。*注*：「并入门禁」半已被 [ADR-0105](./0105-concept-fields-as-gate-input.md) 翻转（档位进门禁）；「并入调度」仍否决。
- **`assumes` 引入传递闭包**——把软语义硬化成隐式依赖；硬依赖只归 `pre`。
