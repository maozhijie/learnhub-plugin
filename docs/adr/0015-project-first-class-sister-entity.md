# Project 一等实体：Course 的姊妹对象，非项目节点

决议（#74，2026-09-09，需求池 §5 决策 1）：「项目」进入领域词汇表为一等实体，是 **Course 的姊妹实体**而非 `type=project` 节点（正式化需求池 §1.2 总纲裁决，覆盖研究笔记 F1 原记法）。裁决细目：

1. **词条**：Project（项目）、Milestone（里程碑）、Fading Tier（渐退档，骨架→补全→独立）入 CONTEXT.md，随本决议落库。
2. **生命周期**：active/paused/delivered/archived 四态。「终态可选」= 没有规则强迫任何项目离开 active（无截止项目合法地永驻 active、无催办义务），而非存在第五个「无终态」状态；不设不可达转移——任意状态可重开回 active，delivered/archived 只是「完成 / 收纳」两个非活跃语义标签（重开比重建诚实，承 ADR-0004 精神）。
3. **enc 边界**：enc 边归节点域，Project 不持有 enc 边；项目执行证据沿**被行使的既有 enc 边**回流进节点的练习证据通道（单向复制，非共享存储）；「哪条边被行使」的判定机制归行为推断 enc 边票。
4. **项目自己的执行事件流**：项目持有一条执行事件流（事件=真实执行+表现评级），喂渐退档移动与 2×2 诊断；它与节点练习证据通道是两条流。「执行事件」的正式词条随 FSRS 复用边界裁决票产出，本决议只锁归属。
5. **对账边界**：Settle 只在里程碑粒度新增（节点粒度照旧）；项目无 est、无节点式定价；交付是状态变更不是对账动作；无截止项目可以永不对账（账本永不关闭）。
6. **关联边界**：项目可与节点/课程存在关联（服务证据回流、里程碑检索点抽题、知识子图反编译），但关联永不构成 pre 门禁或完成门禁；关联可显式声明也可行为涌现，形态不词条化，留后续票收敛。
7. **零消费者改动**：节点消费者（sessions/srs/xp）对 Project 不可见；Project 不进题目门禁、无 mastery、无 FSRS 卡。
8. **渐退档移动**：档位移动判据=档内表现，引擎提议、学习者可改（与 Today Pin「提议非指令」同一精神）；mastery 对项目只做入档推荐（challenge point），永不做升档门禁（总纲裁决 5）。

为什么是姊妹实体而不是节点——四个错位：容量契约（节点 est 上限 30–60 分钟，项目以周/月计）；生命周期（节点五态没有「终态可选」，项目需要 paused 与无截止合法）；调度语义（FSRS 卡与题目完成门禁在项目域无定义）；本体（节点是知识单元，项目是实践实体）。备选 `type=project` 节点被否：它把周/月级实体塞进 est 容量契约、把无终态生命周期塞进节点五态，并迫使 sessions/srs/xp 全线加分支。

工程影响（供执行票消费，非本决议约束）：上行回流机械上 = 对被行使 enc 边两端节点调用既有 `applyPracticeEvidence`（practice_ema 占 mastery 派生 30%），零新存储形态；里程碑计划「走 Proposal 快照语义」今天是**语义复用**（提案→审批→快照工作流惯例）——现状 proposal store 强耦合图谱域（kind 仅 gen/edit、快照内容=整图文档序列），泛化改造归 P-2 执行票；里程碑对账 = journal 新流水 kind（对齐 `xp_settle` 先例）。
