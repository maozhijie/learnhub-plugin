# ADR-0075: 提示词文本的单源与惰性模板——`prompts/` 落点、`{{var}}` 严格渲染、模板面清单

日期：2026-09-14 ｜ 票：#237 ｜ 依赖：#220（登记纪律）、#218（契约后置与登记表落点）｜ 章程：`architecture.md` §8、§9

生成质量的杠杆集中在提示词（ADR-0072：「改模板 = 改生产行为」），但**文本的形态与落点**一直无裁决。**形态**：只有 15 条生成模板与 4 个 `*_SYSTEM` 是命名常量，其余约 60 处指令散文散在拼装函数里——**提示词是长篇散文，却与代码共用一套语法**，散文里出现反引号或 `${` 就把代码改坏，AI 尤其读不出「插的是语法还是字面量」；实测代价是每次改完都要人工返工。**落点**：没有「全部提示词在哪」的单一答案，人要知道这次改了哪几条只能靠提交信息。**人编面**：`loadPrompt` 的 vault 快照在内置版本更高时**直接覆盖**用户文件（只留 `.bak`），承载不了持久修正（§4 据此否决覆盖层）。

## 裁决

### 1. 提示词文本是惰性字符串，变量走 `{{var}}` + 严格渲染

`src/engine/prompt-render.ts`：文本不含任何插值语法，变量面收窄成 `{{name}}` 占位符表，取值在调用点由 `render(tpl, vars)` 完成；零依赖叶子（同 `io.ts`／`prompt-assembly.ts` 形态）。

**为什么不是 TS 模板字面量**：散文与代码共用语法正是上面那条代价的根因，惰性串让提示词对代码**零语法风险**——这是主要动机，不是顺带的整洁；附带好处是变量面变成一处可对账的清单。

**严格是刻意的**（两类都不静默）：**缺变量 → 抛**，否则模型读到 `{{targetNode}}` 原文；**渲染后仍残留 `{{标识符}}` → 抛**，占位符的失败模式就是静默把原文喂给模型，而模型不报错、只会照着生成，只能靠渲染期抛错暴露（触发面是「注入的值自身带着占位符」）。

**占位符只认标识符形态**（`{{targetNode}}`）是刻意收窄的口径：`{{…}}` 同时是**挖空重述的卡面标记**（`learner-cards.ts` 的 cloze 语法），而学习者自写卡面内容会作为**值**流进提示词；若把「任何 `{{…}}`」都判成残留，学习者写一个英文挖空（`{{mitosis}}`）就会当场抛错——那是数据，不是没填的占位符（剩余误报面见边界段）。多余变量不抛（传超集无害，「传错名」由缺变量兜住）；收窄口径由 `tests/prompt-render.test.ts` 两个反向用例钉住。

**`{{renderers}}` 不走这个渲染器**：15 条生成模板里的 `{{renderers}}` 由 `Content.loadPrompt` 在运行时替换（vault 快照路径，含「旧模板缺占位符时末尾追加注入段」的兜底），生成站的**材料**注入走 `withContractLast` 段序拼装、不做字符串替换。因此 `templates.ts` 的文本**不得**送进 `render()`——那会把 `{{renderers}}` 判成缺失变量（约束写在模块头注）。

### 2. 落点：`src/engine/prompts/` 按域分文件；行数棘轮按 `types.ts` 先例豁免

按域分文件、照现有模块边界走（`templates`／`grading`／`feedback`／`quiz`／`content`／`projects`／`host`）。**不做 barrel 索引**：「零依赖叶子」纪律反对无人调的中间人（`prompt-assembly.ts` 头注：「露了就是无人调的中间人」），消费方直接引具体文件。

**15 条生成模板一起搬进 `prompts/templates.ts`，`Content.PROMPT_KINDS` 改为 re-export 该常量**——**键集与访问面一字不动**：契约注册表 `OUTPUT_CONTRACTS`、登记表 `PROMPT_CHANGELOG` 的键集对账与 171 条文本断言（`tests/prompt-contract.test.ts`）都继续读 `Content.PROMPT_KINDS`，故搬迁是一次**零语义变化的搬家**。

**行数棘轮豁免**：`src/engine/prompts/` 进 `scripts/scan-budget.mjs::SIZE_WHITELIST`，理由与 `src/engine/types.ts` 同款（**文本大表，行数不是病灶信号**）；不豁免则每次手编提示词增删一行都要在同一提交里下调基线，而人编提示词是高频动作。这是**放宽**一处棘轮，按章程 §5 登记理由：被豁免的是「提示词文本」这一类，其行数由版本标记与登记门对账，不由行数棘轮对账。

**宿主侧散文进同一模块，host 深导入**（导师系统提示、节任务块、回路提示词段、AB 变体）。依据是 R1 的**实际**受控面：`HOST` 常量就是 `src/index.ts`，`src/host/**` 不在其中，且已有深导入纯类型面的先例。代价是它落在「host 不深导入引擎子模块（D14）」那句注释的**字面之外**——不扭曲源码去迎合注释，而是**给约定补上例外的边界**：注释就地改写为「host 深导入只准落在**纯声明面**（纯类型、纯字符串常量）」。走门面会改 host 调引擎面的对账基线，不值。

### 3. 模板面：单路径 → 清单，搬迁不产生新版本号

`scripts/prompt-bump.mts` 的 `TEMPLATE_FILE`（单路径字符串）改为 `TEMPLATE_FILES`（清单），且清单**包含历史路径** `src/engine/content.ts`。理由是门的判据本身：提交级门判的是**版本号集合差**（ADR-0072 §裁决 2：「标记挪位／新增一份同版本模板都不算 bump」）；若清单只列新路径，搬迁那一提交的父提交版本集合会读成**空集**，15 条老标记全被误判成「首次出现」，门就会逼人给一次纯搬迁补 15 条**假增量**登记。留下历史路径后，搬迁前后并集相同、Δ 为空。配套两处机械改动：**并集而非逐文件**（`versionsAt(ref)` 取面内各路径版本号并集）；**`refHasPath` 容错**（`git cat-file -e` 先探存在性——父提交没有新路径是**正常状态**，旧实现会抛 git 错、把门崩在那次提交上）。

**这条同样堵住一个恒过风险**：若只改清单不验证，门会在搬迁后**看不见新路径**（`git log -- <路径>` 过滤掉了新文件的 diff），成为恒过的门。故自检里必须有**搬迁后在新路径里 bump 而不补登记 → 红**这一态（章程 §5：「恒过的门比没有门更坏」）。

### 4. 人工编辑面：不建覆盖层，纪律落 `AGENTS.md`

**不新建人工覆盖层**（曾评估 `preset/prompts/<kind>.md` 之类）：`loadPrompt` 的 vault 快照已是「可编辑面」，但承担不了持久修正（内置版本更高即覆盖），新建一层只会引入「哪一份在生效」的第二义；本票的瓶颈是**定位**，不是**分层**。所以「人编面」就是**源码常量本身**，靠两件事支撑：文本已变成惰性串（编辑散文不再有语法风险）+ **收尾登记纪律**。

**纪律**（章程条款落 `AGENTS.md`，与 §8 同族）：**凡改动了提示词的会话，收尾必须点名报告**——改了哪条、`文件:行`、新旧差异要点、对应的 `PROMPT_CHANGELOG` 条目。性质：它**不是门能拦住的形态**（收尾消息不在仓库里、机械不可判，硬造判据就是假装，同 §8 末「取不到就不假装」）；它兜住的正是 §8 自认的空洞——**同版本号下的 prompt 变化**两级门都不执法，只能靠人审，而人审的前提是有人告诉你**改在哪**。

## 边界与登记（如实）

- **零行为变更**：搬迁前后提示词**逐字节相同**、渲染结果相同，故**不 bump 任何模板版本、不加登记条目**（这正是 §3 要保证的形态），快照零漂移。**换行符不构成风险（实测）**：模板字面量内 `<CR><LF>` 按语言规范**归一为 `<LF>`**，运行期文本与检出换行族无关。
- **收窄口径的已知边界**：剩余误报面是「注入值自带 `{{英文标识符}}`」，实现在此处确认**有一条新可达路径**——评审对照的提示词把**记录下来的生成提示词**当值注入，而模型／学习者文本也可能带英文标识符花括号（如 Anki 模板语法 `{{frontside}}`），这类值过去原样透传、现在会抛。判据是「它本身就是真歧义」，故**保留严格口径**；将来若在人审里看到误抛，**正确的修法是注入前显式转义该值，不是放宽渲染器**。
- **模板面清单里的历史路径长期留在面里**（贡献空集、无害）；删掉它就重新引入 §3 的误判，故不删。
- **`REPAIR_MECHANISMS` 三条证人串随散文迁出而漂移**：本票把它们从提示词文本换成**调用点锚点**（机制的实现是回路不是散文）；今后改那三个常量名要同步那三条登记。
- **收尾登记纪律无门**（§4，机械不可判）；章程 §8 的既有边界不变，只多一条「收尾报告要点名改在哪」的人审抓手。
