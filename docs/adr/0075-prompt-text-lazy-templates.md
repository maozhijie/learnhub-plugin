# ADR-0075: 提示词文本的单源与惰性模板——`prompts/` 落点、`{{var}}` 严格渲染、模板面清单

日期：2026-09-14 ｜ 票：#237 ｜ 依赖：#220（登记纪律）、#218（契约后置与登记表落点）｜ 章程：`docs/agents/architecture.md` §8、§9

## 背景与问题

本仓的生成质量杠杆集中在提示词上（ADR-0072 的原话：「改模板 = 改生产行为」）。但**文本的形态与落点**一直没有裁决：

- **形态**：只有 15 条生成模板与 4 个 `*_SYSTEM` 是命名常量，其余约 60 处指令散文散在拼装函数里——有的是 `['…', '…'].join('\n')`，有的是裸模板字面量。而**提示词是长篇散文，却与代码共用一套语法**：散文里出现反引号或 `${` 就把代码改坏了。这条对 AI 编辑尤其致命——它读不出「这里插的是语法还是字面量」。实测的代价就是：AI 改提示词的效果差，而「大量功能不改提示词不行」，于是每次改完都要人工返工一次。
- **落点**：没有「全部提示词在哪」的单一答案。人要知道这次改了哪几条、去哪补编辑，只能靠提交信息（或者根本没有）。
- **人工返工面**：`Content.loadPrompt` 早就给生成模板开了 vault 侧可编辑快照（`state/提示词/<kind>.md`），但**内置版本号更高时直接覆盖用户文件**（只留 `.bak`）——所以那里承载不了「我手工改一次」的持久修正。

要裁决的形态问题有四个：文本用什么**形态**（惰性串还是模板字面量）、变量怎么**取值**（`{{}}` 还是 `${}`，错配怎么处理）、**落在哪**（是否搬迁 15 条模板、宿主侧散文的归处、是否要一个人工覆盖层）、以及搬迁**撞上提交级登记门**时怎么办。

## 裁决

### 1. 提示词文本是惰性字符串，变量走 `{{var}}` + 严格渲染

`src/engine/prompt-render.ts`。文本不含任何插值语法，变量面收窄成 `{{name}}` 占位符表，取值在调用点由 `render(tpl, vars)` 完成。零依赖叶子（R5 同 `io.ts`、`prompt-assembly.ts` 形态）。

**为什么不是 TS 模板字面量**：散文与代码共用语法是上面那条实测代价的根因。惰性串让提示词对代码**零语法风险**——这是本裁决的主要动机，不是顺带的整洁。附带好处是变量面变成一处可对账的清单，`${}` 散在长散文里时没人能一眼看全要传什么。

**严格是刻意的**（两类都不静默）：

- **缺变量 → 抛**。否则模型读到的是 `{{targetNode}}` 原文。
- **渲染后仍残留 `{{标识符}}` → 抛**。占位符的失败模式就是「静默把原文喂给模型」，而模型不会报错、只会照着生成——这类缺陷只能靠渲染期抛错暴露。触发面是「注入的值自身带着占位符」。

**占位符只认标识符形态**（`{{targetNode}}`），这是刻意收窄的口径：`{{…}}` 同时是**挖空重述的卡面标记**（`learner-cards.ts` 的 cloze 语法），而学习者自写的卡面内容会作为**值**流进提示词（自注讲解、再讲一遍）。若把「任何 `{{…}}`」都判成残留，学习者写一个英文挖空（`{{mitosis}}`）就会让提示词当场抛错——那是数据，不是没填的占位符。收窄后的剩余误报面只有「值里恰好带 `{{英文标识符}}`」这一种，它本身就是真歧义（模型读到也分不清），抛错是诚实反应。这条边界由 `tests/prompt-render.test.ts` 的两个反向用例钉住（挖空形态必须通过、标识符形态必须抛）。

多余变量不抛：模板没用到就是没用到，传超集无害；「传错名」由缺变量那一类兜住。

**`{{renderers}}` 不走这个渲染器**：15 条生成模板里的 `{{renderers}}` 由 `Content.loadPrompt` 在运行时替换（vault 快照路径，含「旧模板缺占位符时末尾追加注入段」的运行时兜底）。生成站的**材料**注入走 `withContractLast` 的段序拼装、不做字符串替换。因此 `templates.ts` 的文本**不得**送进 `render()`——那会把 `{{renderers}}` 判成缺失变量。这条约束写在 `templates.ts` 的模块头注里。

### 2. 落点：`src/engine/prompts/` 按域分文件，行数棘轮按 `types.ts` 先例豁免

按域分文件（`templates.ts` 生成模板、`grading.ts` 判卷、`feedback.ts` 学习者反馈、`quiz.ts` 出题族、`content.ts` 内容管线、`projects.ts` 项目族、`host.ts` 宿主侧），照现有模块边界走。不做 barrel 索引：本仓的「零依赖叶子」纪律明确反对无人调的中间人（`prompt-assembly.ts` 头注原话：「露了就是无人调的中间人」），消费方直接引具体文件。

**15 条生成模板一起搬进 `prompts/templates.ts`**，`Content.PROMPT_KINDS` 改为 re-export 该常量。这样**键集与访问面一字不动**：契约注册表 `OUTPUT_CONTRACTS`、登记表 `PROMPT_CHANGELOG` 的键集对账（`tests/output-contract.test.ts` 卡精确相等）与 `tests/prompt-contract.test.ts` 的 171 条文本断言都继续读 `Content.PROMPT_KINDS`，搬迁因此是一次**零语义变化**的搬家（搬迁前后逐字节相同，`{{renderers}}` 与 45 处转义反引号原样保留）。

**行数棘轮豁免**：给 `src/engine/prompts/` 进 `scripts/scan-budget.mjs::SIZE_WHITELIST`，理由与 `src/engine/types.ts` 同款（**文本大表，行数不是病灶信号**）。不豁免的话，每次手编提示词增删一行都要在同一提交里下调 `arch-baseline.json`——那会让「人改一次提示词」这件高频动作每次都背上一次基线维护。白名单条目的 `reason` 会随文件落位，门另断言每条白名单至少命中一个文件（白名单本身也可能是幽灵）。这是**放宽**一处棘轮，按章程 §5 在此登记理由：被豁免的是「提示词文本」这一类，其行数由版本标记与登记门对账，不由行数棘轮对账。

**宿主侧散文进同一模块，host 深导入**（`handlers.ts:52` 导师系统提示、`host/jobs.ts` 节任务块、`host/llm.ts` 回路提示词段、`host/spike.ts` 的 AB 变体）。裁决依据是 R1 的**实际**受控面：`tests/import-rules.test.ts` 的 `HOST` 常量就是 `src/index.ts`，R1 只迭代这一个文件的边；`src/host/**` 不在其中，且已有先例（`host/handlers.ts:15` 深导入 `../engine/types.ts` 这个纯类型面）。一个纯字符串常量的叶子比纯类型面更无行为，故按同一形态处理。代价是它落在门面注释那句「host 不深导入引擎子模块（D14）」的**字面之外**——按 §3 的纪律，这里不扭曲源码去迎合注释，而是**给约定补上例外的边界**：该注释在 `src/engine/index.ts` 就地改写为「host 深导入只准落在**纯声明面**（纯类型、纯字符串常量）」。走门面（把提示词做成引擎方法）会改 `tests/fixtures/host-face-baseline.json` 的 host 调引擎面对账，收益只是注释更好看，不值。

### 3. 模板面：单路径 → 清单，搬迁不产生新版本号

`scripts/prompt-bump.mts::TEMPLATE_FILE`（单路径字符串）改为 `TEMPLATE_FILES`（清单），且清单**包含历史路径** `src/engine/content.ts`。

理由是门的判据本身：提交级门的判据是**版本号集合差**（ADR-0072 §裁决 2：「标记挪位/新增一份同版本模板都不算 bump」）。若清单只列新路径，搬迁那一提交的父提交版本集合会读成**空集**，15 条老标记全部被误判成「首次出现」，门就会逼人给一次纯搬迁补 15 条**假增量**登记——那是把诚实登记表污染成噪声。清单里留下历史路径后，搬迁前后并集相同，Δ 为空，一次搬迁在门眼里是真正的零变化。这正是 ADR-0072 原话的兑现，不是新判据。

配套两处机械改动：

- **并集而非逐文件**：新增 `versionsAt(ref)` 取面内所有路径的版本号并集。
- **`refHasPath` 容错**：`git cat-file -e` 先探存在性——父提交没有新路径是**正常状态**（文件首次落地），不是 git 故障。旧实现直接 `git show <sha>^:<path>`，遇到不存在会抛 git 错、把门崩在那一次提交上。

**这条同样堵住一个恒过风险**：若只改清单不验证，门会在搬迁后**看不见新路径**（`git log -- <路径>` 过滤掉了新文件的 diff），成为「恒过的门」。故自检里必须有**搬迁后在新路径里 bump 而不补登记 → 红**这一态（章程 §5：「收集器类门另须断言它能看见目标形态」「恒过的门比没有门更坏」）。

### 4. 人工编辑面：不建覆盖层，纪律落 `AGENTS.md`

**不新建人工覆盖层**（曾评估 `preset/prompts/<kind>.md` 之类）。理由：`loadPrompt` 的 vault 快照已是「可编辑面」，但它承担不了持久修正（内置版本更高即覆盖），而新建一层会引入「哪一份在生效」的第二义；本票的目标是**让人快速找到 AI 改了什么并就地补编辑**，这件事的瓶颈是**定位**，不是**分层**。

所以本票的「人编面」就是**源码常量本身**，靠两件事支撑：文本已变成惰性串（编辑散文不再有语法风险）+ **收尾登记纪律**（下条）。

**纪律**（章程条款落 `AGENTS.md`，与 §8 的登记/过门同族）：**凡改动了提示词的会话，任务收尾必须点名报告**——改了哪条提示词、`文件:行`、新旧差异要点、以及对应的 `PROMPT_CHANGELOG` 登记条目。这条纪律的性质要说清：它**不是门能拦住的形态**——收尾消息不在仓库里，机械不可判，硬造判据就是假装（与章程 §8 末尾「取不到就不假装」同款）。它兜住的正是 §8 自认的那个空洞（**同版本号下的 prompt 变化**两门都不执法）：那一类只能靠人审，而人审的前提是有人告诉你**改在哪**。

## 登记与代价

- **新增**：`src/engine/prompts/{templates,grading,feedback,quiz,content,projects,host}.ts`（纯文本面）、`src/engine/prompt-render.ts`（渲染器，住 `prompts/` **之外**——它是要被棘轮量的代码，与 `prompt-assembly.ts` 同族）、`tests/prompt-render.test.ts`（11 例）、本 ADR、`AGENTS.md` 提示词纪律段。
- **改动**：`scripts/prompt-bump.mts`（`TEMPLATE_FILE` → `TEMPLATE_FILES` + `versionsAt` + `refHasPath`）、`tests/prompt-changelog.test.ts`（+1 例搬迁自检，共 13 例）、`scripts/scan-budget.mjs`（白名单加一条）、`src/engine/content.ts`（模板迁出 + re-export，2075 → 1477 行）、**16 个消费文件**（`grading`/`quality-review`/`explain`/`self-note`/`receipts`/`question-audit`/`question-dedup`/`question-bank`/`content-subsystem`/`note-source`/`generation-jobs`/`seed`/`project-decompile`/`coach-round`/`growth-subsystem` + 宿主四个），`src/engine/output-contracts.ts`（`REPAIR_MECHANISMS` 三条证人串改代码级锚点）、`src/engine/index.ts`（D14 注释补例外边界）、`arch-baseline.json`（新受控文件登记 + `content.ts` 行数下调 + 各消费文件行数随迁）、`AGENTS.md`（收尾登记纪律）、`tests/README.md`（门册登记本票的门改动）。
- **约定沿用**：保留全部既有导出名与签名（导出常量在原名文件 re-export，拼装函数只换函数体为 `render(CONST, {...})`）——171 条按键读 `Content.PROMPT_KINDS` 的文本断言、契约注册表、`SYSTEM_TEXTS` 的符号导入都不改读法。
- **零行为变更**：搬迁前后提示词**逐字节相同**，渲染结果相同，故**不 bump 任何模板版本、不加登记条目**（这正是 §3 要保证的形态）。`host-tools-*`、`host-routes-*` 快照零漂移。
- **已知边界（如实登记）**：① `{{}}` 收窄口径的剩余误报面是「注入值自带 `{{英文标识符}}`」（见 §1 末段，抛错即设计）。**这条在实现中确认有一条新可达路径**：评审对照的 `reviewReconcilePrompt` 把**记录下来的生成提示词**当值注入，而模型/学习者文本也可能带英文标识符花括号（如 Anki 模板语法 `{{frontside}}`）——这类值过去原样透传、现在会抛。判据是「它本身就是真歧义」，故保留严格口径；但如果将来在人审里看到误抛，正确的修法是把该值在注入前显式转义，而不是放宽渲染器。② 收尾登记纪律无门（§4，机械不可判）；③ 章程 §8 的既有边界不变——**同版本号下的 prompt 变化**提交级/状态级两门都不执法，只多了一条「收尾报告要点名改在哪」的人审抓手；④ 模板面清单里的历史路径 `src/engine/content.ts` 会长期留在面里（贡献空集、无害），删掉它就会重新引入 §3 的误判，故不删；⑤ `REPAIR_MECHANISMS` 里三条证人串随散文迁出而漂移，本票把它们换成**调用点锚点**（见「登记与代价」）——今后改那三个常量名要同步那三条登记（常量内已就地注释提示）；⑥ **换行符不构成风险（实测确认，不是想当然）**：本仓 `core.autocrlf=true`，Windows 检出的工作副本是 CRLF，很容易担心「把多行模板从 CRLF 文件搬到另一个换行族的文件会改掉提示词」。实测否定：模板字面量内的 `<CR><LF>` 按语言规范**归一为 `<LF>`**（用 CRLF 源文件写 `` `x\r\ny` `` 取出 `"x\ny"`），而 `'…\n…'` 转义写法本就与文件换行无关——所以提示词的运行期文本**与检出换行族无关**，本次搬迁在任意平台逐字节等价。
- **实现中新增的机械对账**（本票的字节保真证据，不在 `npm test` 里）：用 TypeScript 解析器把每个新常量文件与迁移前各喂给文件的「静态文本片段」（带插值模板取 head + 各 span 字面量、按 `{{var}}` 二次切分）逐字对账——126 个片段里 124 个直接命中，余 2 个（`reviewBlindPrompt` / `reviewReconcilePrompt`）是旧代码「`[...].join('\n')` 与 `a + b` 混用」造成的重连口径差，逐字核源确认等价。另有各域的运行时桩（旧模块 vs 新模块同输入比较输出）报零差异。

## 验收链

- **渲染器**：`tests/prompt-render.test.ts` 11 例——正样本（替换/数字/重复/无占位符/多余变量）与反样本（缺变量、值非文本、值自带标识符占位符）各成用例，另加两条反向用例钉住收窄口径（挖空形态必须通过、`{{ light: 1 }}` 与 JSON 单花括号必须通过、Anki 模板语法必须抛）。
- **搬迁零语义**：`tests/prompt-contract.test.ts`（171 条按键读 `Content.PROMPT_KINDS` 的文本断言）与 `tests/output-contract.test.ts`（键集精确相等 + 契约段锚点）在搬迁后全绿，即证明「键集与文本都没变」。
- **门改动两态**（验收原文）：`tests/prompt-changelog.test.ts` 的临时仓库新增用例——纯搬迁提交必须**绿**（面只列新路径时必红，即本条的实测反样本）、搬迁后在**新路径**里 bump 不补登记必须**红**（防恒过）；真 git 历史在含搬迁提交的分支上必须绿。
- **章程条款**：`docs/agents/architecture.md` §8（登记门的面口径）与 `AGENTS.md`（收尾登记纪律）。
