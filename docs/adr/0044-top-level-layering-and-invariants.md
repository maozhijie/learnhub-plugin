# 顶层分层：四层责任、顶层不变量与三件不要做

引擎今天同时是域、应用与适配器——FSRS／掌握度／XP／判卷／图结构／沉淀折叠是纯规则，门面与九个子系统是编排，vault FS／Anki 传输／LLM 缝型／时钟与随机是外部世界；三者混居 `src/engine/`，而文件分区（E/U/P/D/C/V 区与 gallery 式分节）是**按票号切的、不是按闭环切的**——这是门面曾长到约 240 个方法、依赖需靠 R1–R7 硬管的根因。项目的真实形状是「一个本地优先的学习闭环 + 两个投递面 + 一条 LLM 生产管线」：单进程、**多处权威 + 约定协调**的数据面、**一个命令系统的三份手写实现**（见 ADR-0045）。本 ADR 把这条形状立成四层责任 + 一条顶层不变量 + 三件不要做，作为 #165 及后续所有结构票的顶层依据。**本 ADR 只画线，不搬代码。**

理由：四层不是新目录树，是**责任模型**，而它已大部分被 R1–R7 近似执法了——host（投递）→ 门面（应用）→ engine 领域模块（域），engine 零宿主依赖、零 `@deepseek-ai/*` 导入。真正缺的只有一层：**适配器仍住在域里**——`src/engine/` 33 个文件 import `node:fs`（284 处调用）、`new Date(` 35 处散在 14 个文件、`Math.random` 4 处、Anki 的 `fetch` 默认参（`AnkiConnectClient(endpoint, fetchImpl = fetch)`）。这条缺口的代价已有**可测量的形状**：`src/engine/views.ts` 里 5 处成文的类型镜像是被 fs 耦合逼出来的——镜像成因注释就写在 `views.ts:127`／`:149`／`:181`、`views/bank.ts:30`、`views/learner.ts:91`（「这些模块依赖 `node:fs`，UI 侧无法 import」）。也就是说适配器层缺失不是审美问题，**它就是类型镜像漂移的根因**。同时，「架构约定只活在注释与 ADR 里」的代价也已实测：#152 之前，写在 `engine/index.ts` 头注释里的 D14 照样长出三处宿主深导入与三条 import 环；R3 曾因收集器只收相对说明符而恒过（见 ADR-0047）。

关键裁决：

- **四层责任表**：

| 层 | 内容 | 约束 |
|---|---|---|
| 域 | FSRS、掌握度、XP、判卷、图结构、沉淀折叠——纯规则与**纯日历运算**（输入时间戳） | 零 I/O、零平台：不 import `node:fs`、不 import `@deepseek-ai/*`、不读「当前时刻」与随机数（经参数或端口传入） |
| 应用 | 门面 `engine/index.ts` + 九个子系统 + 写入单元编排 | 只依赖域 + 端口接口；不 import 宿主；跨子系统只经门面（ADR-0043 的 R6 形态） |
| 适配器 | vault 存储、Anki 传输、LLM 双模式缝、时钟与随机 | 实现端口；**不反向依赖应用** |
| 投递 | 命令注册表 + 宿主（工具／路由／队列／静态伺服）+ SPA | 唯一知道「外部世界」的一层；**唯一的装配点** |

- **层次与目录的映射（不搬文件）**：域与应用同住 `src/engine/`；适配器的外移目的是 `src/host/`（**不新开 `src/adapters/`**）——这样 **R2「engine 禁 import 宿主」自动成为应用→适配器边界**，而 `src/index.ts` 成为唯一装配点。R1–R7 不重写、不废止，升格为四层的一等执法。既有的 `engine/llm.ts`（22 行、纯类型、零导入的 `LlmComplete`）与 `host/llm.ts`（实现）已经是这个形状的雏形。
- **顶层不变量：只有教练层能改图，且必经提案门。** 其余各层只写自己的正典。实测今天在**模块粒度已经成立**：唯一写 `data/*.yaml` 的原语是 `graph.ts:266` 的 `GraphStore.writeRegionDoc`，唯一调用者是 `proposals.ts`（`:688` `applyEdit`、`:888`／`:891` `applySeed`；另一路径 `:1044` `applyEnrich` 直写原子）。登记两处松动、**不就地改**：① `writeRegionDoc` 是 public 且非原子，结构上拦不住新调用者；② `graphApply('enrich')` 从 `growth-subsystem.ts:907`、`projects.ts:1277` 绕过 `graphApply` 包装直调 `proposals.*`。判据取「谁能调用图写原语」：**门白名单＝`proposals.ts`**——今天即绿，不需要棘轮（门清单见 ADR-0047）。
- **缝住哪一层、谁拥有 dsh 耦合**（补 ADR-0041 的归属，**不重裁其形状**）：ADR-0041 已定缝的形状（`complete()` 单发 + `agentLoop()` 有界工具回路、回路预算 K≤6 + 1 门错修复轮、教练工具面＝只读引擎视图白名单），缺的是归属。裁决：**端口住应用层、实现住适配器、装配住投递层**——`engine/llm.ts` 已有 `LlmComplete`，**照同一形状新增 `LlmStream` 端口**；`engine/agent.ts` 是应用层的端口消费者（实现 `complete()` 与 `agentLoop()`，含只读引擎视图白名单与 K 轮预算）；**dsh 耦合 100% 收在 `host/llm.ts` 这一个适配器文件**（`@deepseek-ai/dsh-llm`／`cordis` 的引用点不增加）；`src/index.ts` 只做构造与注入。R3「engine 禁 import `@deepseek-ai/*`」原样成立，且**从此就是域／应用与适配器的分界线**。
- **为什么 `agentLoop()` 不搬适配器**：白名单是「只读**引擎视图**」这一引擎概念，回路又只在生成队列任务内运行（队列是应用与宿主共有的机制）——搬走会让 ADR-0041 上述两条字面裁决同时失效，并把 #163 的教练回路推成跨包重构。多一个与既有端口同形的类型，成本远低于此。
- **`stripFences` 的 9 处接线**是适配器行为（补全结果的文本后处理）散在投递层，随缝一并归位；登记为已知缺口，不在本 ADR 施工。
- **「同事务」属应用层**：写入单元的编排（顺序 + 幂等 + journal）是应用关注点；落盘的原子原语属适配器关注点（见 ADR-0046）。
- **三件不要做**：
  - **不引通用工作流／事件溯源框架**：32 处「同事务」顺序约定是**领域知识**（哪一处先写、为何先写，只有该域说得清），不是框架缺口；现有 append-only 流水 + 幂等重放已够用。引框架要先把领域顺序重表达成配置，收益为负。
  - **不把 FSRS／图算法抽成独立包**：它们与领域词汇（节点、前置、enc、掌握度、学习日）深度耦合，抽出去要先造一层词汇映射，只增边界成本、不增复用——唯一消费者是引擎自己。
  - **不服务化／多进程**：单用户、本地优先是产品优势，不该有服务边界；唯一可能撑爆单进程的是 LLM 长任务，而这已被既有的全局串行生成队列与任务注册表解决（ADR-0038）。

边界：

- **本 ADR 只画责任线，不搬代码。** FS／Anki／时钟／随机的物理外移另开票；唯一例外是 agent 缝——它是骨架 C 的**第一个实例**，由 #162 落地（ADR-0041 已定形状，本 ADR 只定归属）。
- **不新增可达性**：四层不改变任何命令的对外可达面（见 ADR-0045）。
- **不动公共面**：门面签名与 host/UI/测试调用点零改动（#152 已确立纪律）。
- **不新目录树**：域的物理位置仍是 `src/engine/`；`views/` 的归档形态沿用 ADR-0043，不改。
- `src/engine/data-check.ts`（824 行／18 处 fs 调用／0 写）是纯读侧模块——「读模型／查询层」是否单列一层，本 ADR **不作裁决**，随适配器票一并裁；本 ADR 只登记它既不属于域（有 I/O）也不属于投递（无外部世界）。
- 时钟外移的实测清单随适配器票：`Date.now()` 5 处、`new Date(` 35 处散在 14 个文件；`dates.ts` 是**日历语义**的正当归属（纯运算），但它同时提供 `nowIso()` 这类**读时钟**函数——读「当前时刻」属适配器关注点，`today`／`cutoff` 已在几乎全部 API 上贯穿为参数（`learningDay()`），外移只需收口默认回退。
- ADR-0042 的 R1–R7、ADR-0043 的子系统与枢纽领主判定线**均不改**；四层是在其上补命名与一层缺口，不是替代。
- 顶层重划若改变文件归属，**所有门阈值重推**（见 ADR-0047 的棘轮时序）。

替代方案（否决）：

- **按目录树硬分层**（`src/domain/` + `src/app/` + `src/adapters/` + `src/delivery/` 整树搬迁）——纯搬移不产生设计收益，却让全部接缝路径同时晃动，与 ADR-0043「零既有模块搬移、接缝路径不晃」直接相抵；而导入方向本来就已由 R1–R7 执法。四层的增量价值在**命名责任与定位缺口**，不在目录。
- **`agentLoop()` 整体搬适配层**（引擎只留 `complete()` 端口）——引擎更纯，但只读工具白名单与回路预算变成宿主概念，与 ADR-0041 的两条字面裁决同时相抵，且 #163 的回路逻辑要在包间重构；收益（引擎少一个端口）不抵成本。
- **缝自持 dsh 依赖**（`engine/agent.ts` 直接 import `@deepseek-ai/dsh-llm`）——直接破 R3／ADR-0042，且把宿主破坏性更新的冲击面从 1 个适配器文件放大到整个应用层。
- **服务化／多进程**——见「三件不要做」第三条。
- **把 R1–R7 重写成「四层版」的七条规则**——规则集本身没有错，只是少了一层；重写会让 ADR-0042 的实测依据（三条环的解法、store 拆 io 的理由）失去锚点，收益为零。
