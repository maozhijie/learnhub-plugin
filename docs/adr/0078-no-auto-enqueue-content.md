# 正文生成一律显式下发：撤掉 apply 与生长批的自动入队链

现状有两条「结构动作顺带排正文」的自动链：① 种子/建课提案 apply 之后，起点节点里「正文未生成」者被逐个排进全局生成队列（#160 `triggerSeedContent`）；② 生长批受理之后，本批新建且正文未生成的就绪节点（`ready_unbuilt`）被自动排进队列，任务消息附「正文生成已入队 N 节」。两条链的共同形态是：**学习者的一个结构动作（过提案、批生长）顺带花掉一次模型额度**，且生成发生在人情愿之前——提案一过内容就在酿，生长批一落就接着生成。

理由：ADR-0076 已经为「加终点」定过同一条口径（加终点 = 纯声明，落锚不拉回合，第一次放行由学习者显式下发「生长一步」），理由是**方向是学习者攒出来的，中途开始生成会打断攒方向的过程**。正文自动入队是同一种病：结构与内容的节奏不同——结构便宜、可反复改，内容贵、一生成就是数分钟的管线 + 真实额度；把内容挂在结构动作的尾巴上，等于让「改结构」这件事附带「要不要开始烧额度」的隐性承诺。而且自动入队让生成队列的队首不可预期：学习者点「生成」时，前面可能已经排了一批自己没要过的任务。

关键裁决：

- **apply 只落结构。** `afterGraphApply` 退化为「清扫悬空任务」一件事（编辑批含 `del_node`/`rename` 时的注册表联动，ADR-0039 不回归）；`triggerSeedContent` 整体删除。种子提案、`learnhub_graph_apply`、反编译联合入口的种子半区（#156）三条入口行为一致：过门即落盘，零入队。
- **生长批只落结构。** `generateGrowthJob` 受理成功后不再为缺口节点入队正文；`coachGrowthBatch` 的 `applied` 形状去掉 `ready_unbuilt`（连同它的 `loadView` + 前沿计算一并撤除）——该字段的唯一消费方就是被撤掉的入队循环。
- **显式通道一字不动。** 面板「生成」/`POST /generate`、`learnhub_question_generate`、整课重置（`POST /course/reset`）、反馈重生成（`POST /feedback` → `生成队列.md`）都照旧——它们是学习者点名要的，正是「显式下发」的形态。
- **冒烟补齐显式下发。** `src/host/smoke.ts` 原本靠 `afterGraphApply` 的自动入队把任务放进注册表（漏了就是「任务不在注册表」）；现在补一次 `enqueueGeneration`，语义等价于面板「生成」按钮——冒烟照旧跑真实生产路径，只是那一脚由冒烟自己踩。

边界：

- **T1/T2 阶段变更仍自动登记 `生成队列.md`**（`content.onStageChange`）。它与上面两条不是一回事：那是给人看的未完成清单，没有任何机器执行挂在它上面（`queueItemsAll` 只到面板生成页），人勾掉或点生成才发生消费。要不要连它一起撤属独立裁决。
- **队列空闲仍自动拉生长批**（`pumpGeneration` 排空 → `coachTrigger('queue_idle')`，#144/#145）。它入队的是**结构**生长批，不是正文；本 ADR 只撤正文链，生长批的自动拉批与重拉阻尼（含其停摆判据）一字不动。副作用是原先「生长批 → 正文」的连锁自动生成随之消失——这正是本票要的结果。
- **不新增开关。** 不做 `autoGenerate: false` 之类的配置位：口径是「正文只由显式动作产生」，留一个默认开的自动位等于把同一个坑再挖一遍。要恢复自动链是下一次行为裁决（本 ADR 可修订）。
- **队列语义零改动**：FIFO、单并发、可取消、重启暂停（`queuePaused`）、终态保留期与清扫都不动。本 ADR 只改「谁往里放任务」。

替代方案（否决）：

- **加配置开关（默认关/默认开）**——默认开等于没改；默认关等于用配置表达一个已经判死的形态，还多一份要维护、要被恢复路径读回的状态。
- **只撤种子链、留生长批链**——生长批链更隐蔽（学习者看不到自己在批生长时顺手排了正文），且它才是「队列空闲自动拉批」的下游放大器；只留它等于把最该撤的那条留下。
- **改成「自动入队但默认暂停」（复用 `queuePaused`）**——暂停旗标是**重启恢复**语义（leak 到盘上的排队任务不静默开跑），拿它当开关会搅浑两件事的判据；且任务仍在队列里占位、仍要在生成页被逐个处理。
- **保留 `ready_unbuilt` 字段只停消费**——计算它的代价是一次 `loadView` + 前沿集过滤（每生长批一次），而它的唯一消费方就是被撤掉的循环；留一个算完即弃的字段是给下一个读代码的人埋问号。
