# ADR-0069: 工具调用通道 spike 装置（双臂 × 两站 × 多变体）

日期：2026-09-13 ｜ 票：#216 ｜ 总纲：#212 ｜ 依赖：#213（语料/计量）、#219（temperature 端口）、#230（多样性仪表）

## 背景与问题

dsh-llm 接口无 `response_format`、无 `tool_choice`（#212 §一）——结构化通道只能走**自愿调用**：提示词要求模型调 `submit` 工具、参数即 JSON；模型不调、回文本时按现行 YAML 解析自然收束（生产先例：教练回合 `agentLoop` K≤6）。

要不要把这条通道铺到生成站，不能用「看起来更结构化」拍板：格式约束有**格式税**的实证威胁——多样性坍缩（arXiv:2607.18476：一句「Reply with JSON only」使众数答案占比 41%→64%）、格式散布（arXiv:2310.11324：合法格式变体的性能散布可达数十个准确率点）。#216 因此预注册了双臂协议与不对称预注册线（**税若存在，出现在多样性轴而非正确率轴**），本 ADR 只裁决**装置**的形态；数据与最终裁决回帖在票面。

## 裁决

### 1. 装置住宿主（`src/host/spike.ts`），提示词零复制

真 provider 只在宿主 ctx 上。装置按「（站 × 臂 × 变体 × 次数）」循环，每次：

```
生产提示词（引擎在场拼装） + 臂/变体后缀 → 模型（对照臂=补全缝 / 工具臂=回路缝+submit 工具）
   → 应答交回**既有受理门**（大纲 contentOutline / 出题 questionGenerate）→ 记录
```

关键：**提示词不是人工复制的**，而是让引擎按生产路径拼装（大纲 = `loadPrompt('课程大纲')` + 裁剪包；出题 = `questionGenerate` 内部拼装），装置只把「臂/变体后缀」追加在末尾并发出去。因此「同提示词」是同一条代码路径的结论，不是比对结论。

### 2. JSON ⊂ YAML：实验臂零引擎改动接入

工具臂把 `submit` 工具的参数（JSON 串）**原样**交回引擎；`YAML.parseModel` 直接吃 JSON，受理门、逐题卫生门、查重、invokes 对表与对照臂完全同一套。未命中（模型不调工具）即回落文本——协议预注册的「失败无害回落」语义，同样走现行解析。

### 3. 每格独立 vault 副本（污染隔离）

模板 vault 一次构建（单课程 / 单节点 / 一段有节的正文 / 三枚在册概念），每格**每次跑全新副本**：出题站的查重基线与 #230 的 `bank` 范围读数会被历史批污染（票面增补已点名「先归档再跑下一臂」），逐次副本是最省事的等价做法，且臂间、变体间、次间互不影响。

### 4. 判据不外借

- **格式轴**：交付成功率 = 生产受理结果（大纲 `contentOutline` 不抛 / 出题 `added > 0`）；命中率 = 工具臂确有一次 `tool_call`；schema 合规 = 解析成功 + 契约 shape。
- **内容/多样性轴**：读 #230 仪表的 `batch` 读数（两臂各跑各的批），`distinct` 题面数按 `normalizeStem` 去重自算（票面 2026-09-13 更正：仪表不含该计数）。
- **成本轴**：`promptChars`（零噪音，两臂同生产提示词）+ `toolSchemaChars`（工具 schema 占额，字符数）+ provider usage token（**注记**：同站同前缀存在前缀缓存，越靠后的调用越便宜，故 token 差只作量级参考）。

### 5. 变体与样本量（FormatSpread 抗性）

每臂 **2 个语义等价的措辞变体**（对照臂：生产原文 / 末尾重申契约；工具臂：指令式 / 口令式），每格 9 次 → **每臂 18 次**（预注册 N=15–20 区间内）。读数按变体分列、臂级聚合，比例一律带 Wilson 95% CI——小样本点估计不做显著性宣称（写进报告备注，避免把 18 次读成定论）。

### 6. 协议外参数一律显式登记

- 采样温度统一设 `1`（两臂同值，控制变量；#219 端口是执行手段——这是它的首个消费方）。
- 出题站第二意见门关闭（`quizAuditRate: 0`）；逐题修复轮（#148）与门错重试仍在（它们是受理语义的一部分，不在两臂之间制造差异）。
- reasoner 与 chat 分开报：装置的报告只覆盖**一次运行的模型**（模型由宿主部署配置决定），换模型 = 另起宿主重跑一次、单独留档。

### 7. 语料与产物

- `POST /learnhub/api/spike`（命令注册表 `spike`，无引擎型白名单）+ 驱动 `npm run spike`（`--runs/--stations/--corpus/--out`，退出码 2 = 格式达标线未过）。
- 语料：一调用一文件（frontmatter 站/臂/变体/次/命中/交付/schema/token + 提示词计量 + 每一轮原始应答），目录由 `--corpus` 指定（缺省临时目录）。G9 裁决同 #213：单文件遥测写、无跨文件一致性 → 不入 `runWriteUnit` 站点表。
- 报告 JSON 同时内嵌逐次行（`rows`），语料可回看不必依赖目录。
- **数据产物（入库路径）**：
  - 主轮（deepseek-v4-flash，装置修正后）：`docs/research/2026-09-spike-tool-channel.json` +
    `docs/research/spike-216-corpus/`（72 份语料，一调用一文件：frontmatter 站/臂/变体/次/命中/交付/schema/token/**死因**
    + **提示词原文** + 每轮原始应答）+ `docs/research/2026-09-spike-tool-channel-recomputed.json`（语料复算读数）；
  - 前置轮（同模型，语料未含提示词原文，`skipped` 未提取）：`-run2.json` / `-run2-recomputed.json` 留档作复现对照；
  - 模型轴（增补「reasoner 与 chat 分开报」；provider 无显式 reasoner 型号，取同 provider 更大模型 deepseek-v4-pro）：
    `-pro.json` + `spike-216-corpus-pro/`。
- **格式轴的实测发现（装置产出，非装置裁决）**：YAML 对照臂在出题站出现过 3/18 交付失败，死因同一类
  ——模型把多行文本塞进单引号字符串导致 `Missing closing 'quote`（真语法错，非解析器缺陷）；工具臂参数走
  JSON，该类失败结构性不可发生。「格式契约稳定」（#212 第一支柱）由此有了可测读数，登记进票面裁决。

### 8. 首轮实测的两处装置缺陷（已修，登记在后）

1. **工具 schema 描述诱导非法取值**：大纲 `submit` 的 `type` 描述里写了菜单外的「应用」，模型照抄 → 一次交付门失败（`sections.4.type「应用」不在节类型菜单`）。修正为逐字列菜单（概念/例题/演示/小结/练习/交互/思维）。**这条说明装置自身的文本也是实验处理的一部分**——描述里出现什么，模型就可能写什么。
2. **驱动被 fetch 的 300s 头超时掐断**：`fetch`（undici）默认 `headersTimeout` 300s，「宿主同步跑完整轮再回」的调用在 5 分钟处断链（首轮 72 格次语料跑齐、报告丢）。两个装置（smoke/spike）的驱动改用 `node:http`（无隐式头超时）+ 语料目录绝对化（相对路径会落在宿主 cwd）。
3. 由此产出的**语料复算**工具（`scripts/spike-recompute.mts`）：格式/成本轴取 frontmatter（运行时读数），内容/多样性轴由语料确定性复算（回复面），并给臂级 Wilson CI 与两臂差 Welch CI——「报告丢了、数据还在」不是口头保证，是可执行路径。

首轮（含缺陷）与第二轮（修正后，入库语料）**在同一多样性轴上给出方向相反的边界信号**（首轮 selfBLEU 工具 − 对照 = +0.041，CI −0.014–0.096；次轮 −0.017，CI −0.064–0.029）——这正是 FormatSpread 警告的形态：单轮结论会被散布淹没。入库证据以第二轮为准。
