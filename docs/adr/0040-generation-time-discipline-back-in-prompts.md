# 生成时纪律回归提示词层：理念条款与质量自查随生长式提示词携带

一次成型→生长式 cutover（#138→#153）把旧管线提示词里的理念条款（认知粒度 30 分钟自问、动作句命名、螺旋式合法、依赖充分性、边级自查、上交前自查）连同 Scale Floor、健康分交付门、检察官子代理一起退役，当时的口径是「批质量由受理门 + audit + 复诊把守」。实测暴露这次退役丢的不是一样东西而是两样：机械门该把守的（schema、无环、概念在册）确实收编了，但**只存在于生成时**的质量——节点粒度、命名形态、pre 充分性——没有任何面在管：受理门查不了语义，audit 只能事后报警。症状已现形：学习者自述零基础，种子起点仍是复合概念（坡道的第一级台阶就是「Python 基础语法」式复合泛称）。本裁决：生成时纪律写回提示词层——教练回合 v3 新增生长纪律段（粒度/动作句/依赖充分性/真实依赖优先于难度曲线/边级自查/上交前自查），种子提案 v2 新增起点资格判据（单一行为单元 + 复合概念操作化判定 + 宁简勿繁），反编译 v9 种子簇同判据一句，`learnhub_graph_propose` 工具描述同步收紧。条款文本以 allo（姊妹项目）现行版本为底翻回生长语义——它是同一理念体系的幸存实测版（learnhub→allo 移植有 allo ADR-0002 档案），旧 SKILL.md 全文见 git `7c041bd^:skills/learnhub-graph-generate/SKILL.md` 作对照校勘。

关键裁决：
- **两层分工**：受理门能机械查的继续标硬约束（schema、在册、复诊必填），门禁查不了的写成程序化自查（逐边 verdict、30 分钟自问、复合概念操作化判定）——不冒充硬约束（allo 教训：门禁不兜底的「硬」是空威胁），也不写许可式告诫（allo 教训：「可视化为主」式许可表述被模型无视，才升的硬约束）。
- **退役的不复活**：Scale Floor/规模底线（ADR-0033 明判：盲区事件化优于制度化）、健康分阈值交付门、检察官子代理（#153 裁决）不随本次回来；条款按生长语义改造（依赖充分性落在 ops 的 pre 语义上，难度跳跃转译为「下一回合插入在当场补过渡」），不照搬旧管线语汇。
- **起点资格无条件严判**：起点任何情况下是单一行为单元——零复合概念、零基础学习者从常识直接可起步；学习者自述的基础水平只写进 reason 点「略过哪些地形」，不放松资格。不对称论证写进提示词：起点过简代价趋近零（很快被生长消费），过繁代价是整条坡道断裂。与既有条款的分工：vault 熟悉边界管「边界放在哪」，资格判据管「什么配当起点」，互不冲突。
- **audit findings 喂教练回合是后置议题**：coachContextPack 六区块现不带 audit findings，面板流的教练看不到审计面——「建议逐条落实/显式驳回」条款先挂账，等 findings 进上下文包再有资格写进提示词。

替代方案（否决）：
- 共享「生长纪律」渲染块经 `{{placeholder}}` 注入多模板——新增机制，且三个提示词的理念侧重不同（裁决语义 vs 定位语义），强行共享稀释语义；内联延续现状。
- 复活检察官或 allo 式 LLM 软终审——#153 已裁决批质量由受理门 + audit + 复诊把守；软终审若要做另立议题，不混进提示词升级。
- 以旧 SKILL.md 原文为底删改——带着 Scale Floor/健康分门等已判退役语汇，逐条剜不如以 allo 实测版为底、旧文对照校勘。
