# ADR-0070: 离线批量评审器与图质量面审计抽样（语料 × 量规 × 人读报告）

日期：2026-09-13 ｜ 票：#222（评审器）、#224（图质量面审计） ｜ 总纲：#212 ｜ 依赖：#213（生成语料/计量）、#221（质量量规注册表）、#219（temperature 端口）、#223（两段式防锚定的生成时先例）

## 背景与问题

质量回路要能测量，才有迭代的方向。此前全仓的「质量」只有**格式轴**的机械门（解析器/契约注册表/质检门）与**结果轴**的被动信号（复诊、N-of-1、申诉勘误）；内容质量轴零测量——#212 §四.4 列出的稀释点、反模板化只有出题站有机械配套、模板版本间没有任何可比读数。已经就位的两件东西使这件事现在可做：生成语料（#213）把真实模型调用的提示词与原始产出全部落盘，质量量规（#221）把五类产物的判据连同证据要求写成了机器可读的注册表——**判定标准先于判定器**，判定器才有可消费的判据。

要裁决的形态问题有四个：抽样怎么定（成本/代表性）、判读要不要防锚定、报告给谁看/以什么形态落盘、以及「模型给自己生成的东西打分」这件事的**判读效力边界**在哪。

## 裁决

### 1. 一条链：抽样 → 两段式评审 → 聚合 → 人读报告；进语料、固定温度

装置分三层，各有其位：

- **引擎（纯函数，零 fs 零时钟）**：`quality-review.ts` = 测量面（抽样 / 提示词 / 应答解析 / 证据定位核对 / 聚合读数），`quality-review-report.ts` = 交付面（报告类型 + 人读渲染），`quality-audit.ts` = 图质量面的审计面清单与系统性发现候选。判据一律来自 #221 量规表，评审器**不重写判据**（改判据改量规表，评审器跟着变——不可能出现两套判据）。
- **宿主（`host/quality-review.ts`）**：读盘（语料抽样池，经 `host/corpus.ts` 的读侧解析——语料格式的单一出处）、调模型（真 provider 只在宿主 ctx）、写盘（报告）。
- **手动触发**：`scripts/quality-review.mjs` → `POST /learnhub/api/quality-review` → 宿主运行器。**不进任何生产管线**——评审是离线测量，不阻塞也不参与生成。

三条随行的纪律：**评审调用本身进语料**（站标签 `质量评审`，站词表 +1）——判定器的原始应答同样留档（人工检视判读是否走样、换模型/换供应商时的判读漂移标本；判卷族同理：判定器**不设自己的量规**，故不进评审抽样池——这不是漏登，是分层法庭的结构事实：没有人审的量规不立）；**采样温度固定 0**（#219 端口，默认值不动）——判定要可复算，跨版本/跨轮次的差异应是内容差异，温度固定下的残余波动即漂移信号；**报告不进 canonical**（写 `state/质量评审/<ts>-<站>.md`，单文件原子写、无跨文件事务，故不入 `runWriteUnit` 站点表——与 #213 语料同属观测写）。沉淀层「内容质量结论」事件**后接**（event schema 另行落地）。

### 2. 抽样：失败/容忍件定额优先 + 成功件等距，无随机数

按站独立：bad 桶（`outcome ∈ {failed, tolerated}`）定额取最新的 N 件（环形池保留的就是最近的样本，比较与召回都该从最近的说起），ok 桶等距取 M 件（`equidistantIndices`，与 #223 的抽样同族口径：等距、不引随机数）。两桶独立、不满额不互补——报告按实际件数走，不制造「凑够配额」的假象。**空输出件（调用级失败）不作评分**：它的审计价值是失败本身（失败码 + 语料），报告单列且零模型调用（成本纪律）。缺省配额 `{bad: 3, ok: 2}`/站、重复 2 次——起步低，看全貌由操作者显式调参（`--bad/--ok/--repeats`）。

### 3. 两段式防锚定：先盲评、再对账，两份读数都留

照搬申诉复核（`grading.ts` DISPUTE_REVIEW：Phase 1 独立解题、明确忽略存储键）的形态，**适用处照搬**：

- **一期（盲评）**：只给量规与**产物原文**——生成提示词、站/档/outcome/失败码一律不给。锚定源（指令说了什么、它是失败件）先在，评审就会去「解释产物为什么长这样」，而不是「产物本身够不够好」。产物原文块因此**不印语料 ref**：ref 形如 `<站>/<ok|bad>-<时间戳>…`，站名与桶前缀（= outcome）都在里面（code-review 抓出：ADR 承诺的匿名与实现的不一致）。
- **二期（对账）**：给出渲染后的生成提示词（材料 + 输出契约）与元数据，逐维度确认或修正（`revised` 标记 + 依据说明），并给一句 `contract_note`。契约允许是**底线**、量规判据是**标准**——故提示词明写「不要因为『指令允许』就放过真正的缺项」。

**一期 → 二期的修正率本身是读数**（报告逐件给出「几个维度被修正」），不是要抹平的噪声：它测量「契约解释改变了判读」的幅度。

### 4. 报告：人读先行、逐维度、无总分；每条分数指回语料与原文证据

**件口径与轮次口径分开**（code-review 抓出的读数缺陷）：分布 / 低分件 / 系统性候选一律按**件**计（`canonicalReviews`：每件取首轮，重复评审只因稳定性读数存在）——旧实现按评审记录计数，默认两轮下「一件低分」就被算成 2/2 = 100%、直接越过系统性候选线。跨轮分歧全部归稳定性读数（温度固定下它测的是模型侧漂移，不是样本间差异）。评审失败件（`failure` 在场）**恒无终判**：一期判读仍留档（附录标「未采信」），但不进任何分布与低分件。

报告开头是判读分层声明（词条「内容质量」），随后按序：各站逐维度分数分布（1–4 档 + 不可判 + 低分 + 评审面异常）→ **低分件清单**（每条带语料 ref + 证据引文 + 判分理由）→ 未评分件与**评审失败件**（**评审失败 ≠ 产物差**，单列，不当低分）→ 模板版本对照视图（版本从渲染后提示词的 `<!-- learnhub:prompt/vN -->` 提取；版本间比同一维度的低分率，不做跨维度合成、不排序优劣）→ 稳定性读数（同输入重复评审的逐维度一致率与平均档差）→ 附录逐件明细。

两条硬纪律：

- **无总分**：量规无总分档（#221 元数据），报告不合成、不加权、不排序产物优劣。逐维度分布与低分件是全部读数。
- **引文必须可定位**：回复里的每条证据引用都做**确定性核对**（去空白后必须能在产物原文里找到；整句找不到时认 ≥12 字的归一化前缀，以容模型照抄长句时的尾部改写）。找不到记 `unlocated` 并在报告显式列出——评审员的引文不实是**评审质量本身**的读数，不得静默通过。

### 5. 判读效力边界（分层法庭）：AI 评分 = 提议，人审 = 终审

本装置的全部输出都是**提议**：报告供人审对表逐条核对，采纳与否的裁决在人；结果法院（复诊/N-of-1/申诉勘误）各守其领域——结果信号不回写评分、评分不冒充结果（`RUBRIC_COURTS` 随报告带出）。这条不是免责声明而是形态约束：报告与提示词都不做「通过/不通过」的裁定，工具面不接任何自动动作（无面板控件、无 agent 工具、不进生成管线）。

## 图质量面审计（#224）：同一装置，换审计面与样本

审计不是第二套装置——**同一评审器**，量规换成「教练回合」「种子·终点」（#221 在册），样本换成图质量面的语料站（教练生长 / 种子起草），加两件审计特有的东西：

- **审计面清单**（`AUDIT_AXES`，机器可读）：两类审计各声明站、量规、要看的维度与看点；报告开头照它声明「这一轮审了什么、没审什么」（未抽到样本的轴照实写「本轮无该轴语料样本」——防「跑过一轮」被读成「全面覆盖」）。一张跨表对账门把审计面清单钉在语料站词表与量规注册表上：站改名/维度 id 漂移即红，审计不会静默跑空。
- **系统性发现候选**（`systemicCandidates`）：逐（站 × 维度）算低分率，越过预注册线（≥2 件已判档且低分率 ≥50%）即入候选，带低分件引用与判据出处——「某算子被系统性误用」「终点承诺句系统性窄化」这类结论的**候选形态**。候选仍是提议（人审蒸馏成新票挂总纲票 #212 或改量规/改提示词）；样本量小时低分率极不稳定，故 `low/scored` 与件数随候选带出。

教练回合量规的「算子语义 / 裁决与路线」与种子·终点量规的「起点/终点资格」在语料里可判的前提是：语料文件的**提示词段含图面与上下文包**（教练生长站的 loop 调用把图面渲染进提示词），故二期对账能看到「裁决 vs 图面」；一期盲评看的是裁决本身的自洽性（批规模、算子方向、接线义务、理由是否给到边级）。这就是两段式在图质量面上的分工。

## 后果与代价

- **成本**：每件 = 2 次调用（两期）× 重复次数，走真实配额；缺省配额与重复次数刻意压到最小可观测档（起步 5 件/站 × 2 轮 × 2 期 = 20 次/站）。要更多样本由操作者显式加。
- **评审失败不重试**（`rounds: 0`，登记在输出契约注册表）：坏应答（一期或二期任一阶段）记「评审失败」单列，成本不翻倍，且失败不得被读成低分——一期判读在附录里以「未采信」留档。
- **报告无人自动消费**：本 ADR 不建任何自动阈值动作。#220（提示词 changelog 纪律）是它的第一个计划内消费者（跨版本对照过门），那笔账记在 #220。
- **审计发现回流是人的动作**：低分件 + 证据贴票、系统性候选蒸馏新票，都在人审（本 ADR 只保证这两样在报告里是现成的）。
- **新站接入三处登记**（#214 覆盖完备性的直接后果）：语料站词表 + 输出契约注册表条目（format `json`、契约住 system、`systemAnchors: ['qualityReview']` → `QUALITY_REVIEW_SYSTEM`）+ 测试侧别名表。漏一处测试即红。
- **规模**：G5 基线同提交迁移（4 个新受控文件 + 6 处增长 + 1 处下降——`host/smoke.ts` 的 frontmatter 解析收归 `host/corpus.ts`，语料格式读侧自此单一出处）。
- **本地/并发**：`state/质量评审/` 与语料同属 state 观测面，可随语料一并清理；同秒同范围重跑 = 同名原子覆盖（报告是不可变读数，不追加）。
