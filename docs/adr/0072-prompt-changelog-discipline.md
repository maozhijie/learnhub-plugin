# ADR-0072: 提示词变更纪律——登记四件套、提交级登记门与「过门」双检

日期：2026-09-13 ｜ 票：#220 ｜ 总纲：#212 ｜ 依赖：#213（生成语料）、#222（离线批量评审器）、#218（契约后置与登记表落点）｜ 章程：`docs/agents/architecture.md` §8

## 背景与问题

#212 的缘起是一句大实话：**提示词与生成流程是本项目的主要支柱，但多次迭代后不稳定**。近三个月连环暴露的生成失败（enc_candidates 串入大纲、溢出死局、G1 门误报）全部是契约矛盾/边界不清——修法已经体系化（裁剪包 → 容忍解析 → 回灌修复轮 → 稳定码），但**「改提示词」这件事本身没有纪律**：模板文本一改，模型看到的东西就变了，产出随之变化，而这次变更「预期输出发生什么变化」只活在提交信息里（或者根本不写）。于是「多次迭代后不稳定」的制度缺口就是：**改了没法对账，退化了没人知道**。

#220 要的是把这件事制度化：每次模板版本 bump 必须带**预期输出增量**，并过双重回归——语料回放（格式契约稳定轴）+ 评审对照（内容质量轴）。两条测量链当时都还没落地（#213 语料捕获、#222 离线评审器），所以票面写明「两票未落地前，本票先落地登记格式与章程条款」——现在两票都已落地（ADR-0060 / ADR-0070），本 ADR 落地完整纪律。

要裁决的形态问题有三个：登记**记在哪、记什么**；「bump 必须带登记」用什么**判据**执法（状态级还是提交级）；以及「过门」的两条读数**在什么条件下算通过、什么条件下该拒绝**。

## 裁决

### 1. 登记四件套：`version` / `date` / `changeType` / **`expectedDelta`**

落点 = 契约注册表（`src/engine/output-contracts.ts::PROMPT_CHANGELOG`，键 = `PROMPT_KINDS` 键）——#218 已按 #220 的字段格式手工落位（ADR-0065 §「登记与代价」），本票接管并把它写进章程。`expectedDelta`（**预期输出增量**）是这次改动**预期模型输出发生什么变化**：它是语料回放与评审对照的对账对象（「变了没有、变得对不对」），也是回退时的定位锚。

一条形态规则：**同一版本号下允许第二条登记**——模板文本没动、但最终 prompt 变了（拼装侧重排、上下文包变更、注入面增删）同样要登记，记在同一版本号下并写明变更面，**不冒充版本 bump**。先例是 ADR-0065 §6 的「§5 禁止概念复活」（模板文本一字未动，但最终 prompt 多出最多 200 个节点名）：把它写成 v12 会伪造版本线，写成 v11 第二条才诚实。

### 2. 提交级登记门：走 git 历史，版本级判据，纪律起点动态发现

`scripts/prompt-bump.mts check`（`npm run prompt-bump -- check`）。三条判据设计，各有其因：

- **为什么是提交级**：状态级门（`output-contract.test.ts::runChangelogGate`：每个模板键的最高登记版本 == 模板头版本标记）只能证明**当下状态**自洽——「bump 和补登记」分两次提交，状态级门在两次提交之间的那个 HEAD 上是绿的，纪律的时序要求（bump 当次就带登记）它看不见。两门互补：状态级管**完备性**（键覆盖、版本对齐），提交级管**时序**。
- **为什么是版本级而不是键级**：提交级的判据是「本提交**新出现**的模板版本号，本提交是否新增了同版本号的登记条目」——版本号对账。键级（哪个键被 bump 了）需要解析 `PROMPT_KINDS` 的模板字面量做键→版本映射，脆且代码多；而「登记记到了别的键名下」这个形态由**状态级门**在 HEAD 兜住（bumped 键的最高登记版本会低于模板版本 → 红）。两门合起来足够，登记这一层不做键级判据（这是**如实登记的判据边界**，不是遗漏）。
- **为什么是集合差而不是 diff 行**：「标记行被挪位/模板被复制一份（同版本号）」在 diff 里也是「新增了一行标记」，但都不是 bump。判据取**模板文件在该提交与父提交的版本号集合差**——只有真正的新版本号才要求登记。代价是候选提交要各跑一次 `git show`：故两段式扫描（一次 `git log -p -U0` 找候选，只对候选做集合差），候选稀少，开销可忽略。
- **纪律起点动态发现**：不写死 sha——起点 = `PROMPT_CHANGELOG` 首次出现的提交（`git log -S`）。此前没有登记面（编不出一份诚实的回溯表，同 `PROMPT_CHANGELOG` 头注「本表自 #218 起计」）；此后任何 bump 都要带登记，起点随历史自动前移。

自检按章程 §5：真历史必须绿；**临时 git 仓库**里造「bump 不补登记」提交必须红、同一仓库里合规提交单独看必须绿（验收原文「对 bump 无 changelog 变红、对合规变更绿」的两态实测）；纯函数另按合成 diff 三类样本自检；扫描面必须给出「扫到几个提交」的读数（防恒过——扫到 0 个是读数不是通过）。

### 3. 过门双检：语料回放（解析面）+ 评审对照（内容面）

`scripts/prompt-bump.mts replay|compare`。两者都**不进 `npm test` 必跑集**（要真语料目录、要真模型报告），是**变更当下跑的手工门**；会进必跑集的是它们**自身的自检**。

**① 语料回放**（格式契约稳定轴）：站 → 本站**离线解析面**注册表，把语料里存的原始输出重新过一遍，判据只认「**基线通过（ok/tolerated）→ 回放失败**」＝解析回归。三条语义要点：

- **语料存的是剥围栏前的原始输出**（捕获点在适配器出口），而站在解析前有剥围栏后处理（seam 的 `stripFences` / 罗盘的 `stripWrappingFence`）——回放照做，否则会造出成片的假回归。
- **跨产物一致性按自指口径旁路**：反编译/计划站的 `project` 名一致性、`expectSeed` 在场性检查需要**输入面**知识（本次目标是哪个项目、有没有显式课程），回放取不到输入，故取产物自身的 `project` 值自指、`expectSeed` 关。回放判的是**解析面**，不是受理面的对外一致性。
- **覆盖是显式清单**：不在回放面的站（会话式辅导、判定器站、要引擎/课程上下文的 markdown 站：节生成三变体、里程碑草案）在 `REPLAY_OUT_OF_SCOPE` 里逐个给理由——与契约注册表的 `OUT_OF_SCOPE_STATIONS` 同款纪律（**漏登新站 = 红**，不是静默不覆盖）。零样本按**失败**处理（空语料回放会恒过）。

**回放面的忠实性有实测链**：对 `docs/research/spike-216-corpus/`（#216 spike 的**真实**模型输出，178 行/件的多轮语料）的 control 臂逐件回放，**逐件复现当时生产的 `delivered`/`schema_ok`**——课程大纲 18 件全通过（0 假阳性）、题目生成 15 件通过 + 3 件失败（三件的失败原因逐字复现当时记录的「模型输出不是合法 YAML」）。这条链同时证明了「回放面与站解析链一致」和「回放能看见失败」，并已进 `tests/prompt-changelog.test.ts`（该语料被删/改动时该门会红，属预期）。

**② 评审对照**（内容质量轴）：两份 `quality-review --out` 报告（改前 / 改后各跑一次）在**同源样本**上逐（站 × 维度）均值不降。三条硬前提，不满足即**拒绝比对**（不是通过）：同源样本（评审面 ref 集合一致）、维度集合一致（改模板不该改量规维度）、两侧都有可判档读数（零样本恒过闸）。效力边界照 ADR-0070：这是**机械读数**（「评分没降」），内容质量是否变好归人审——分层法庭不动。

**取不到就不假装**：真语料目录或真模型报告取不到时，如实登记「未过门」与理由（含回退点）——先例是 ADR-0065 §6（§5 复活的上下文包修复未做真模型对照，如实登记「若观察到幻觉/跑题上升，回退点就是这一行」）。

## 登记与代价

- **新增**：`scripts/prompt-bump.mts`（三子命令 + 纯函数面）、`tests/prompt-changelog.test.ts`（11 例）、`package.json` 加 `prompt-bump` 脚本、章程 §8、门册 S73 与新门登记表。
- **不动**：G3/G4/G5 基线零变化（装置住 `scripts/`，在 G5 受控面之外）、零快照迁移、零行为变更、零 canonical 写入。`npm test` 新增 11 例（含一次真 git 历史扫描 ~0.7s）。
- **已知边界（如实登记）**：① 提交级门是**版本级**对账（键级由状态级门在 HEAD 兜，见 §2）；② 回放面与站解析链的**同步靠镜像**（每站一行注释指到链的出处），漂移由 `tests/prompt-changelog.test.ts` 的真语料忠实性链与各站行为测试共同兜；③ 评审对照需要真模型，`npm test` 里只有它的自检。

## 验收链

- **登记门两态**（验收原文）：真历史绿（`check` 退出 0 + 扫描面读数）／临时仓库「bump 不补登记」红（退出 1 + 违规行指名版本号）／同仓库合规提交绿。
- **语料回放**：合成语料无假阳性 + 回归检出 + 基线本就 failed 不计回归 + 零样本按失败；真语料忠实性 36 件（#216 spike control 臂）逐件对齐。
- **评审对照**：不降/下降/非同源/维度集合变化/零样本五态。
- **章程条款**：`docs/agents/architecture.md` §8（登记四件套 + 两门 + 过门两条 + 取不到不假装）。
