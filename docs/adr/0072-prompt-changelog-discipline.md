# ADR-0072: 提示词变更纪律——登记四件套、提交级登记门与「过门」双检

日期：2026-09-13 ｜ 票：#220 ｜ 总纲：#212 ｜ 依赖：#213（生成语料）、#222（离线评审器）、#218（登记表落点）｜ 章程：`docs/agents/architecture.md` §8

#212 的缘起是一句大实话：**提示词与生成流程是本项目的主要支柱，但多次迭代后不稳定**——近三个月连环暴露的生成失败（enc_candidates 串入大纲、溢出死局、G1 门误报）全是契约矛盾/边界不清，修法已体系化（裁剪包、容忍解析、回灌修复轮、稳定码），但**「改提示词」本身没有纪律**：模板一改，模型看到的东西就变了、产出随之变化，而「预期输出发生什么变化」只活在提交信息里（或根本不写）——制度缺口就是**改了没法对账、退化了没人知道**。本 ADR 把它制度化：每次模板 bump 必须带**预期输出增量**，并过双重回归（语料回放 = 格式契约稳定轴 + 评审对照 = 内容质量轴）；两条测量链 #213 / #222（ADR-0060 / ADR-0070）现已落地。

## 裁决

### 1. 登记四件套：`version` / `date` / `changeType` / **`expectedDelta`**

落点 = 契约注册表 `PROMPT_CHANGELOG`（`src/engine/output-contracts.ts`，键 = `PROMPT_KINDS` 键）：#218 已按 #220 的字段格式手工落位（ADR-0065 §「登记与代价」），本票接管并写进章程。`expectedDelta`（**预期输出增量**）= 这次改动**预期模型输出发生什么变化**——它是回放与评审对照的对账对象（「变了没有、变得对不对」），也是回退时的定位锚。

形态规则：**同一版本号下允许第二条登记**——模板没动但最终 prompt 变了（拼装侧重排、上下文包变更、注入面增删）同样要登记，写明变更面，**不冒充版本 bump**。先例 ADR-0065 §6 的「§5 禁止概念复活」（模板一字未动，最终 prompt 多出最多 200 个节点名）：写成 v12 会伪造版本线，写成 v11 第二条才诚实。

### 2. 提交级登记门：走 git 历史，版本号差为判据，纪律起点动态发现

`scripts/prompt-bump.mts check`（`npm run prompt-bump -- check`）——模板版本 bump 的提交必须**同提交**补登记条目。判据各有其因：

- **为什么是提交级**：状态级门（`runChangelogGate`：每个模板键的最高登记版本 == 模板头版本标记）只能证明**当下状态**自洽——「bump 与补登记」分两次提交，状态级门在两次之间的那个 HEAD 上是绿的，时序要求（bump 当次就带登记）它看不见。两门互补：状态级管**完备性**（键覆盖、版本对齐），提交级管**时序**。
- **为什么不是 diff 行**：「标记行被挪位／模板被复制（同版本号）」在 diff 里也是「新增一行标记」，都不是 bump；判据取**版本号差**，只有真正的新版本号才要求登记。代价是候选提交各跑一次 `git show`，故两段式扫描（`git log -p -U0` 找候选、只对候选求差）。
- **判据粒度 = 逐键版本差**（#250 修正，2026-09-15）：原取模板面版本号**集合差**，而每个键的版本号各自独立计数（同一面里 v3 与 v14 并存），「v8」天然跨键撞车——真实 bump 会被误判成零变化（实测：`教练回合` v7→v8 时 `check` 报绿）。改为解析模板键开行、把标记归属到它的键，`newVersions` = 版本变了的那些键的版本号；不可归属到键的标记（历史形态）退回集合差。实测（2026-09-15）：修正后 `7a9a1368..HEAD` 报 bump 提交 3 个（修正前 2 个），历史提交 `0c930d42`（#240 / ADR-0076）的 `newVersions` 由 `[3,5]` 变 `[3,5,7,11]`——两处都被撞车吃掉。搬迁不变式（同键同版本换文件 = 零变化）照旧：逐键口径比集合口径**更强**。
- **纪律起点动态发现**：不写死 sha——起点 = `PROMPT_CHANGELOG` 首次出现的提交（`git log -S`）；此前没有登记面（同表头注），此后任何 bump 都要带登记，起点随历史自动前移。

自检按章程 §5：真历史必须绿；**临时 git 仓库**里造「bump 不补登记」提交必须红、同仓库合规提交单独看必须绿（验收原文两态）；纯函数另按合成 diff 三类样本自检；扫描面必须给出「扫到几个提交」的读数（**扫到 0 个是读数不是通过**）。#250 补一例：造「两键共用 v8、其中一个 bump 到 v8」的样本，断言集合口径 `unionNew` 为空而逐键口径 `perKeyNew = [8]`。

### 3. 过门双检：语料回放（解析面）+ 评审对照（内容面）

`scripts/prompt-bump.mts replay|compare`。两者都**不进 `npm test` 必跑集**（要真语料目录、要真模型报告），是**变更当下跑的手工门**；进必跑集的只是它们**自身的自检**。

**① 语料回放**：把语料里的原始输出重过一遍本站**离线解析面**注册表，判据只认「**基线通过（ok/tolerated）→ 回放失败**」＝解析回归。三条语义要点：语料存**剥围栏前的原始输出**（捕获点在适配器出口），站解析前有剥围栏后处理——回放照做，否则成片假回归；跨产物一致性按**自指口径旁路**（`project` 名一致性与 `expectSeed` 在场性要**输入面**知识、回放取不到，故取产物自身 `project` 自指、`expectSeed` 关）；覆盖是**显式清单**，不在回放面的站在 `REPLAY_OUT_OF_SCOPE` 里逐个给理由（漏登新站 = 红，同 `OUT_OF_SCOPE_STATIONS` 纪律），零样本按**失败**（空语料回放会恒过）。忠实性实测链：对 `docs/research/spike-216-corpus/`（#216 spike 真实输出）control 臂逐件回放，逐件复现当时的 `delivered`/`schema_ok`（大纲 18 件 0 假阳性；题目 15 通过 + 3 失败原因逐字复现）——同证回放面与站解析链一致、且能看见失败。

**② 评审对照**：两份 `quality-review --out` 报告（改前/改后各跑一次）在**同源样本**上逐（站 × 维度）均值不降。三条硬前提不满足即**拒绝比对**（不是通过）：同源样本（评审面 ref 集合一致）、维度集合一致、两侧都有可判档读数（零样本恒过闸）。效力边界照 ADR-0070：只出**机械读数**（「评分没降」），内容质量是否变好归人审。

**取不到就不假装**：真语料目录或真模型报告取不到时，如实登记「未过门」与理由（含回退点）——先例 ADR-0065 §6。

## 已知边界

- ① 提交级门是**登记层**判据：只对账版本号（#250 起逐键），不独立验证登记记在了哪个键名下——那由状态级门在 HEAD 兜（见 §2）。
- ② 回放面与站解析链的同步靠**镜像**（每站一行注释指到出处），漂移由真语料忠实性链与各站行为测试共同兜。
- ③ 评审对照需要真模型，`npm test` 里只有它的自检。
- ④ **同版本号下的 prompt 变化**（改模板文本不 bump、改拼装缝、注入面增删）**两门都不执法**——提交级门看版本号差、状态级门看版本号对齐，都只看版本号。章程 §8 已把这一句从「门会拦住」改写成「纪律 + 人审兜住，别当成门能拦住的形态」——**门的效力边界写清，比让读者以为它管得更宽要好**。要机械化需要键级「模板文本变了」判据（解析 `PROMPT_KINDS` 字面量），代价与脆性都高，不做。
