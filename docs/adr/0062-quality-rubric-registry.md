# ADR-0062: 质量量规注册表——五产物类型、判定标准先于判定器

日期：2026-09-13 ｜ 票：#221 ｜ 总纲：#212 ｜ 姊妹件：ADR-0061（输出契约注册表）

## 背景与问题

内容质量轴（#212 §五）的判定此前只散在提示词契约与 ADR 散文里：格式契约稳定有稳定码族与解析门执法，内容质量却没有任何机器可读的判定标准——离线评审器（#222）与人审对表没有可消费的共识物。CONTEXT.md「质量量规」词条已承诺：量规先于评审器存在，判定标准是共识物，评审器只是执行它。

## 裁决

### 1. 量规 = 引擎侧纯数据模块（`src/engine/quality-rubrics.ts`）

五份量规：大纲 / 节正文（含风格变体）/ 题目 / 教练回合 / 种子·终点。每条判据三要素：判定标准（「好」长什么样，可被人审对表）+ 证据要求（评审必须引用什么原文、定位到哪）+ 出处（`模板:<PROMPT_KINDS 键>` / `ADR-XXXX` / `词条:<词条名>` / `引擎:<文件>`）。来源 = 仓库自己的教育学操作化——词条承诺（worked example 阶梯、检索点、PS-I、思维轨迹、误解坑位、前置档位、费曼/苏格拉底、4C/ID、渐退档、非承诺措辞）+ 各站提示词契约 + ADR-0040/0056 资格判据，不引入外部评分量表。

### 2. 元数据 = 分层法庭，无总分

全部量规共用同一法庭声明（`RUBRIC_COURTS` 单一出处）：AI 按量规评分 = 提议（附证据引用、永不直接 canonical）、人审 = 终审、学习者结果法院（复诊/N-of-1/申诉勘误）各守其领域。**无「总分」维度**——维度间不作加权合成（词条「内容质量」_Avoid_ 明令「质量分」），锚门拒绝任何总分维度。量规只管内容质量轴；格式契约稳定轴由 ADR-0061 的输出契约注册表与解析门执法，两轴不互相冒充。

### 3. 锚门与自检

`tests/quality-rubrics.test.ts`：source 解析不到文档（模板键改名/ADR 改号/词条删除/引擎文件挪走）即红；anchor 原句在出处文档找不到即红（模板改句必须同步量规）；法庭元数据必须引用单一出处；总分维度拒绝。自检三样本：伪造锚点、伪造出处、加总分维度/换法庭——各自必须变红。

### 4. #221 增补条款落地

- **预注册预测**（#225 报告 §9）：「不趋同」维度将最先爆出低分（多样性全仓零测量 + 格式约束锐化压力，arXiv:2607.18476），注记随题目量规入库——兑现度是调查结论的自检，多样性证据底座由 #230 供给。
- **「与相邻节衔接」显式判据**进节正文量规：#227 判定节间衔接断裂是流程性缺陷——量规若只看单节文风，会把系统性问题误读为个别文风问题。

### 5. 消费面

`allCriteria()` 输出量规/维度/判据三级定位的扁平视图，评审器（#222）逐判据生成评审提示词与人审对表行；#223 的键自洽判据与第二意见门同判据（对账是确定性检查，不消费评审器——量规行内显式注记这一分工）。

## 后果

- 判定标准成为入库物：人审有对表、评审器有输入、模型或提示词改动撞锚门即红。
- 量规文本本身走人审（#221 验收条款）：本表是 agent 起草稿，经维护者过目才算共识物。
- 代价：模板/词条/ADR 改动可能撞锚门——这正是目的（教育学承诺的漂移显性化）。
