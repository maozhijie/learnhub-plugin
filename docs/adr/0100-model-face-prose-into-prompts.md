# ADR-0100：模型面散文铺满 `prompts/` —— 教练三站先行

- 状态：接受
- 日期：2026-09-17
- 关联：#311、ADR-0075（提示词惰性字符串与 `render`）、ADR-0090（首级判据迁家）

## 裁决

`src/engine/prompts/` 的收纳口径从「只收模板」拓宽为「**凡会离开代码仓、进到模型眼前的散文都收**」：
不再限于「对模型说做什么、怎么做」的指令——工具 `description`、参数说明、上下文包骨架行、视图
骨架行、回执与拒收回灌文案，只要**删掉它模型行为会变**，一律迁入 `prompts/`。文本为惰性字符串 +
`{{var}}` 占位符，取值由 `prompt-render.ts::render()` 在调用点完成（缺变量与残留占位符当场抛）。

本票落地**波①（教练三站）**；波②、波③另票（见下）。

## 为什么

- 用户诉求是「提示词集中手调」：此前模型读到的散文有一半散在代码里（工具 `description`、上下文包
  骨架、cheatsheet、回执口径），改一句措辞要跨文件找。
- #303 首级判据块正因为「住在 `prompts/` 外的一次拷贝」而失锚（见 #310）——同一段模型面文字存在
  两份拷贝就会漂移。
- 先例与纪律已齐备（ADR-0075：惰性字符串 + `render` 严格校验），本票只是把口径铺满。

## 范围（波①：教练三站）

教练三站（思路官／执行官／只读工具站）的模型面散文整体迁入 `prompts/` 同族文件——按站/域分文件
（上下文包骨架、只读工具与视图骨架、思路官材料块、执行官写件面、草稿形状面）。消费点一律走
`render(CONST, {...})`；零占位符的静态块也过 `render(CONST, {})`（先例 `COACH_FIRST_RUNG_CRITERIA`），
以守「文本只准经 `render`」。**取材与定序逻辑留在原站点**——`prompts/` 只收文字，不搬拼装。

## 否决 / 不做

- **本票不做波②（渲染能力清单、宿主节块标题）**：`shared/content-renderers.ts::rendererCapabilityBlock()`
  的正文虽属模型面，但 `shared/` 不能反向 import `engine/`（分层门 R1–R7）。正确拆法是「清单数据留
  `shared/`、骨架文本落 `prompts/`、拼装函数移到 `engine/` 侧」，牵动 G-门与依赖面，单独立票。
  `host/jobs.ts::sectionMaterials` 的节块标题同理（`## 前节结尾` 已在 `prompts/host.ts`，其余散着）。
- **本票不做波③（门错误文案）**：`proposals.ts`/`graph.ts`/`concepts.ts` 的门错误同时被
  `tests/helpers/copy-lock.ts` 大量断言。逐条评估「**语义判据归门、措辞归 `prompts`**」，能搬的
  再搬、被锁的先登记再动——不盲迁。
- **不改拼装与取材逻辑**：本票是纯搬移，不动拼接与定序；唯一例外是一处诊断面的数组守卫（见「影响」）。

## 影响

- 教练三站任意一条模型面散文，现在只需动 `prompts/` 一个文件（验收判据 #1）。
- 文本逐字搬移，最终 prompt 不变（验收判据 #4；`prompt-bump check` 受控面零版本变化 + 既有 coach 测试全绿）。
- **一处新增守卫**：腐坏草稿（`concepts` 存成字典而非列表）下，`render` 的严格性会让「草稿状态」块当场抛错——而 HEAD 是静默渲染 `undefined`。补数组守卫（非数组读 0）使诊断面不崩、毒形状照旧被后续门折叠成可读错误；读数由 `undefined` 变 `0` 只在腐坏输入下出现。
- **`render` 严格性的暴露面扩大**：`render` 对「注入值自带 `{{英文标识符}}`」抛错（ADR-0075 刻意口径）——搬移后模型/作者自撰文本（计划理由、轮志摘要、门回灌 `msg`、误解 `model` 文字）也经 `render` 注入，含 `{{ident}}` 时由 HEAD 的「原样渲染」变为抛错。按 ADR-0075 接受（此类值本就真歧义）；正常场景最终 prompt 逐字不变。
- `host.ts` 的范围口径注释同步拓宽（`prompts/host.ts` 头注记）。
- 后续波次（②渲染能力清单与宿主节块、③门错误）另票。
