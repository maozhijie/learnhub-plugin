# 名称建课、手动多终点与生长停摆判据

现状建课只有一条通道：种子提案（`kind=seed`）。面板表单要填 `课程名 + 目标描述 + 目标类型（+ 覆盖锚定时的工作表） + 参考笔记`，入队跑一次「种子起草」模型站，产 1–3 起点 + **1 个**终点 + 朝终点的粗占位边，人审 apply 才在一个写单元里落注册表 / 区文件 / 终点锚 / 罗盘 / 节点骨架。终点唯一性是硬约束：单锚文件、`endpointGuardErrors` 拒绝改终点、生长批必须接线到那一个终点（ADR-0055/0056）。实机症状（「数学」重建多轮、2026-09-14 清空重建）：目标描述成了**建课门票**而不是「我想学成什么」；节点数是不可预测的，却要在建课那一刻定下一个终点并承诺；想加第二个方向没有入口——换终点只能整课 reseed，锚没有直改通道。

理由：终点该干的事只有两件——把生长**朝哪去**说清楚、让生长**知道何时可以停**。它不该同时是「承诺物」兼「完成判据的锚点」，那两件职责是完成态存在时才需要的；而完成态不是学习者要的东西（「要么还有得学、要么所有终点都已达成，才允许不再产生节点」）。终点一旦只作方向，多终点就是常态而不是例外：课程的方向本来就是一张网，同一条台阶同时朝几个方向推进一步是**正常的结构**，不该被表达成缺陷。终点由谁产生也随之改变：起草模型该给人省力，但不该成为人表达方向的唯一通道——人随时加一个终点，比任何起草都便宜、也准确——所以人手加的终点不过任何 AI 资格门，人是权威。方向与台阶的分工不变：人给方向（终点、以及起草结构时给的起点），教练沿方向长台阶，结构事实仍由受理门守（终点接线、禁长过目标）。

关键裁决：

- **建课 = 名称即空图。** 面板只收一个课程名。落盘内容（同一写单元）：注册表条目 + 课程根目录 + `data/00_未分区.yaml`（**零节点区**，空图的载体）+ 空 `概念登记表.yaml` + `state/终点锚.json`（`{version: 2, anchors: []}`）+ `罗盘.md` 骨架。空图沿用现有读取路径：`GraphStore.load` 一行不改（它只对「数据目录不存在」「目录为空」fail loud，零节点区文件是正常可读的图）。删掉旧建课路径：面板的建课表单字段、`mode=new`/`mode=reseed` 的 `initCourse`、影响预览的建课分支、`SeedDraftRequest.goal` 必填。建课**不自动初始化**：零节点图不入任何自动触发点，第一次生长由学习者显式下发（节点数不可预测，结构先由人定）。
- **终点由学习者手动增删，可任意多个。** 两个动作、立即写盘、不等生成队列：**添加**（建零 pre 节点 + 落一条锚，可选一句目标描述供教练读）与**删除**（锚与节点一并移除，已铺的台阶留在图上成为末端，UI 确认一次）。**不提供改名**（会破坏既有生成路径的语义）也**不提供「把图上已有节点设为终点」**（撞纯标记红线：已有正文/题库/调度/est 的节点不能被标成终点）。终点本体不变：零正文零题库零调度零推荐，一切的「终点性」仍从锚读侧派生（ADR-0055 单源派生不动）。
- **锚 schema v2 与断裂 v3。** `state/终点锚.json` 改为 `{version: 2, anchors: [EndpointAnchor]}`：每条独立 `{endpoint, goal_note?, goal_type, declared, sealed?, worksheet?}`，收尾宣告与工作表逐终点独立，`goal_type` 默认能力锚定且人加时不露出表单。走宣告式断裂（ADR-0034）：一次性脚本把现有课程树整体移入 `存档/pre-v2/<日期>/`、`learnhub.json` 戳 `version: 3` 并在 `breaks` 追加记录、概念登记表按惯例豁免存活，**零兼容读**。
- **教练启动条件与接线触发。**（本节触发口径已被文末「修订（#240 实机走查）」取代：加终点只声明方向、放行归「生长一步」；本条以下文字为原始裁决留档。）教练回合要求 ≥1 终点（零终点时 UI 明说「先加一个终点」；空锚是合法空态，不再是「未播种」）。添加终点是显式结构动作：落盘后**立即入队一次教练回合并走 `force`**（绕过「就绪深度已满足即短路返回 idle」），由教练裁决把新终点接上相关的既有节点、必要时插台阶。**不为「未接线终点」另设受理门义务**——改依赖关系本来就是教练的生长能力（提案校验只要求 op 指向的节点在图上，与「是不是本批新增」无关），新加终点只是又一次手动生长动作。
- **生长停摆 = 就绪存量达标 或 所有终点已达成。** 逐终点状态三档：未接线 → 已铺通（锚上 `sealed`）→ 已达成（已铺通且该终点最后台阶全部 ≥ 掌握阈值）。**课程完成态删除**：`foldCompletion` 保留但降为停摆输入与逐终点读数，UI 的 `🎉 已完成` 横幅删掉；逐终点读数报「已铺通 / 已达成 / 闭包已学 N / 共 M」。就绪存量口径**不变**（照旧全图计数），故不波及就绪卡、冷启动首周折算与周复盘对账。
- **多终点裁决与接线门。** 生长批的 note 增加 `target_endpoints: []`（本批朝哪些终点长），现有「主线批必接线」门从单数终点改为**对每个声明的终点**跑同一套覆盖检查。**同一个新节点可以同时充当多个终点的最后台阶**（交汇节点），这是合法形态不是缺陷；`add_node` 以终点为 pre 仍直接拒（禁长过目标，方向不变）。教练的上下文包带逐终点状态，据以裁决朝哪个终点长——优先选能同时推进多个未达成终点的台阶（提示词纪律，不做机器规则）。
- **罗盘按终点分节。** 「剩余路线」一节一个终点，节头写成 `- **终点名**：`——终点名也是图上节点名，节头天然「有锚」，#231 的对账机械一行不改（不用 `###` 标题，否则会被 `validateRouteBody` 放过、被对账记成漂移条目）。同一交汇节点允许出现在多节。罗盘初画与沙盘 ETA 逐终点化；周复盘的路线对账结论照旧只作读数。
- **结构读数正名。** 图屏与审计报告的「主线深度」正名为**图深度**（口径不变：全图最长路径，多终点下没有单一主线可指），另给逐终点三读数（已铺通/已达成/闭包已学）。
- **交汇节点是读侧派生。** 节点落在 ≥2 个终点的前置闭包内即交汇：零写侧字段、不落盘（与 Mastery 同款纪律）。消费方三处：教练裁决纪律、图与终点列表读数、审计与生成注入按多归属读它。
- **种子降职为「给已注册课程起草结构」。** `kind=seed` 保留，但只能作用于已存在的课程（不再建课、不再 `initCourse`）；面板不再露出种子入口（agent 通道与目标反编译仍用），目标反编译改为**要求课程先已注册**（反编译不再自带建课能力）。起点资格判据（ADR-0040）与终点资格判据（ADR-0056 承诺句）降为起草通道的提示词纪律，不约束人手加的节点。

边界：

- **不追溯**：存量课程的图、锚与生成产物不动；断裂把课程树整体归档，引擎读侧永不读归档区（ADR-0034 照旧）。
- **空目录仍 fail loud**：空图的合法载体是零节点区文件，不是缺目录；Missing 与 Broken 的区分不动。
- **就绪存量口径与 FIFO 不插队照旧**：零节点闸只关「自动触发点」，显式下发（面板「生长一步」）照常即时入队、追加队尾。（「加终点也即时入队」已被文末「修订（#240 实机走查）」取代：加终点是纯声明、不入队。）
- **终点资格判据不再有机器门**：人手加终点不判承诺句/台阶句；该判据只在起草通道的提示词里活着。
- **手加终点与删除都是即时写盘**：不走提案、不走人审（人是权威），但重名/断边/环等结构门照旧在写单元前生效。
- **未接线终点不阻塞学习**：终点零消费，接不接线只影响逐终点读数与罗盘，不影响就绪、推荐与调度。

替代方案（否决）：

- **保留种子建课、只把面板字段砍到名称**——建课仍要跑一次模型、仍要一次人审，且「1 个终点 + 1–3 起点」的一次成型承诺还在；砍字段不解决「方向必须一次说完」这个病根。
- **放行空目录当空图**——「图是空的」与「图不存在」的区分被搅浑（那是 Missing/Broken 纪律的基石），且空目录 git 不跟踪；零节点区文件用一个文件买到同样的语义。
- **新增加权归属边（节点→终点，像 enc 那样）表达「不同程度推动」**——多一层图语义就要配新的门、新的审计、新的生成注入，而它的消费方（细粒度归属读数）现在不存在；交汇由前置闭包自然表达，真要细粒度时再加，那是加法不是改法。
- **每终点一个锚文件**——目录布局多一层，读侧要扫目录聚合，断裂脚本与 Data Check 都要分叉；单文件内数组一行读全。
- **引擎在添加终点时自动连线**——伪造 pre 边等于替教练裁决「哪些节点是最终台阶」（沿用 ADR-0055 的否决理由）；接线走教练回合，触发走显式入队。
- **保留课程完成态（读侧宣告）**——学习者明确不要这个结果：一个课程可以永远停在「暂时不用再长」，宣告「完成」会把停摆误读成终结。
- **就绪存量只数「朝未达成终点」的节点**——口径改动波及就绪卡、冷启动折算、周复盘路线对账与沙盘 ETA，而它带来的精度（区分「这条线在饿」）现在没有消费方；逐终点读数已经够用。
- **终点可改名 / 可把已有节点设为终点**——改名破坏既有生成路径（文件名、题库、罗盘引用）的语义；「设为终点」与纯标记的红线冲突（被学的节点不能同时是终点）。

## 修订（#240 实机走查，2026-09-14）：加终点只声明方向，放行归「生长一步」

**取代上节 §「教练启动条件与接线触发」与边界「显式下发（面板、加终点）照常即时入队」两处条款。**

实机症状：空课加 4 个终点，加第一个时引擎就自动拉了一轮接线回合（原条款），学习者想「先把 n 个方向都声明完再放行」时被中途插了一轮；而那一轮又因 `force` 只在**入队侧**生效、没随任务进执行侧，被停摆短路吃成 `idle`（「教练判断暂不需长新内容（就绪 0/5）」），面板上看到的是「点了生长一步什么也没发生」。

裁决两条：

- **加终点 = 纯声明。** 落锚与零 pre 节点，立即写盘，**不触发生成、不拉回合**（`/endpoint/add` 不再有教练回合受理态，`coach_round` 响应字段退役）。理由：方向是学习者攒出来的，逐终点各拉一轮既会中途开始生成，也让教练看不见还没声明完的方向——而「同一台阶同时服务多个方向」（交汇优先）恰恰要一次看到全部方向才挑得出来。放行学 **#238 Story 4「第一次放行教练由我显式下发」** 的字面口径。
- **`force` 随任务进执行侧。** 显式重新裁决的豁免必须跟着那一轮任务走（`growthForce` 随注册表持久化与恢复），否则「生长一步」在停摆图上恒空转——豁免只落在入队阻尼上等于按钮失效。自动触发点不带它：停摆判据与重拉阻尼照旧。

**未改**：停摆判据本身（「端点只有终点节点」仍判 `exhausted`）。它正是「先声明、后放行」得以成立的闸——若不判停摆，自动触发点（会话开始/队列空闲）会在学习者还没放行时就拉起回合。代价是这一状态下的停摆文案读起来像「无事可做」而非「等你放行」，属已知措辞债（读数与文案的区分留待后续票）。
