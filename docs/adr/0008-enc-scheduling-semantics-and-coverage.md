# enc 承担调度语义：成分技能边从「仅内容/审计」升级为调度也消费

决议（#32，2026-09-08，Arc A3 前置）：enc（带权成分技能边）从「仅服务内容生成与图审计」升级为**调度也消费**的边。语义契约：enc = 本节点练习真实调用、位于本节点 pre 传递闭包内的前置技能，权重表达调用强度；它供 Arc A3 的两类调度行为作路由依据——(1) enc 带权失败 → 把补救定向路由到对应成分技能祖先节点的题目重练；(2) 前置衰减再激活的优先级参考。消费机制（落在 `sessions.ts::gateBlockers/readySet` 如何改、阈值与触发）不在本决议内，由 #37（A3 形态票）设计。

补覆盖：**不设**全库一次性回填硬门槛。图生成/内容管线对全部**新生成**图与节点自即日起承担产出 enc 的义务；主渠道是把练习反哺的机器块（`enc_candidates` / 练习级 `uses`）提升为 enc 边——现状 `encBackfeedHints` 只对「候选不在闭包内」建议 `set_pre`，从不把闭包内的候选落成 enc，这是全库 enc=0 的结构缺口。存量图回填随 A3 课程启用**渐进**，先覆盖试点课程。

可靠性契约：**单一 enc 型**，内容与调度共用同一种边，不另设调度专用验证子型。背书靠两层——(1) 内容契约：§7 强制练习真实调用已声明 enc，反哺通道即练习实际调用的声明；(2) 审计强化：补覆盖缺口 / enc 与反哺候选一致性 / 权重合理性检查（结构审计 E6/E7 只验断边与闭包归属，验不了语义真假，需新增内容级检查）。CONTEXT.md Enc 词条同步改写（去掉「调度目前不消费」）。实施见对应工单；本决议成立依赖该实施把 enc 覆盖与质量门槛立起来。
