# 命令面统一：声明式命令注册表（表项形状与分流纪律）

投递面是一个命令系统的**三份手写实现**：agent 工具 111 个、HTTP 路由 120 条路径、UI 客户端 111 个端点函数。单条命令的通体形状是「取参 → engine → 序列化」，业务逻辑占比不足 1%，三份实现却各自维护参数解析、校验、序列化与命名。本 ADR 把三者收敛为**一份声明式命令注册表**（字段见下），工具面与路由面各只剩一个薄适配器，UI 的类型与调用从同一份 schema 派生。**本 ADR 只定表项形状与纪律，实现施工另开票。**

理由三条，都是实测的：

1. **命名不能当地基**：111 个工具里只有 23 个与某条路由同名（20.7%）。真正的配对键是**引擎入口**（两面各调约 110 个引擎方法、共享 84 个）——所以主键是命令 `id`，工具名与路由路径降级为**属性**。
2. **执行模型是（命令, 通道）对的属性，不是命令的属性**：`compass_paint` 工具侧同步直调、面板侧走生成队列；`coachGrowthBatch` 只有队列、无工具。单命令单字段的模型表达不了这个分叉。
3. **参数校验有两个出处，而工具侧已在写声明式 schema**：路由侧 `need()` 123 个调用点 + 21 处内联缺参报错 + 51 处手写 `typeof` 守卫；工具侧已按 SDK 的 per-property DSL 写了 148 处 `required`，却被 `Record<string, unknown>` 加两次 `as never` 把编译期推断主动丢掉。

## 表项形状

```ts
interface ChannelSpec {
  channel: 'agent' | 'panel'
  mode: 'sync' | 'queued'
  tool?: string                                             // agent 通道的工具名
  route?: { method: 'GET' | 'POST' | 'PUT'; path: string }  // panel 通道的路由
  phase?: GenJobPhase                                       // 仅 mode:'queued'：入口阶段
  bind?: Array<string | null>                               // 顺序＝引擎实参位置，元素＝ args 键名，null＝传 undefined
}

interface CommandSpec {
  id: string                 // 稳定主键（kebab）；工具名与路由路径由它派生或显式声明
  summary?: string           // 人话描述（工具面 description 与面板文案的单源）；agent 通道必填
  args: ParameterSchemaSpec  // 参数 schema：沿用宿主已在写的 SDK DSL
  engine?: string            // 引擎入口（门面方法名）——声明了就必须存在；留空须进白名单（逐条理由）
  output?: TypeRef           // 输出形状：引擎视图类型的类型引用（编译期幻影字段，零运行时）
  domain: CommandDomain      // 域分组（表内字段，也是声明文件的切分依据）
  channels: ChannelSpec[]
}
```

- **`channels` 是唯一表达「允许通道 + 执行模型」的形状，两个字段不拆**：「允许通道」＝列出的通道集合，「执行模型」＝每条通道自己的 mode。这让「同一动作两条通道两种行为」在类型里无法被掩盖，且今天零行为变化。
- **主键是 `id`**，不是命名、也不是引擎入口（一个引擎入口、两个通道、两个名字是常态）。
- **`args` 沿用 SDK 的 per-property DSL**，不引 zod／ajv（ADR-0042 已把「为静态规则引工具链」列为否决项）。两个 `as never` 随命令迁移逐条退役——SDK 会给回参数类型，而今天 111 个处理函数把参数类型手写第二遍、两份声明互不校验。
- **`output` 是类型引用，编译期零运行时**；不做运行时输出校验（那需要 schema 库）。对外形状本就统一：路由侧原样透传、`sendJson` 序列化一次（禁止手动 `JSON.stringify` 造成双重编码）；错误形状全仓 `{ error: string }`。
- **参数校验收成一处**：`need()` 的「缺失即 400」与 `tool-contracts.ts` 的显式契约原则（可选参数只允许「省略」或「合法」；非法输入**永不**静默改写为另一个请求）由注册表驱动的适配器统一施加，消除上列内联守卫；错误消息形状与状态码逐字不变。

## 裁定（#169 施工前，2026-09-11）

1. **`engine` 可选，三类命令留空并逐条登记理由**：**队列型**（14 条，handler 只入队、真正调用在 `jobs.ts` runner 的多方法管线——改为在**通道**上声明 `phase`，门断言 `phase ∈ GEN_JOB_PHASES` 且 runner 有该分支）；**按参分派型**（7 条，入口是实参的函数，如 `/node/pin`，保留手写 handler）；**无引擎型**（9 条：伺服、队列态、常量、LLM 会话）。
2. **加 `bind`（位置式实参绑定），其余保留手写 handler**：实参实测——纯位置透传 153、带换算 17、嵌套负载 32、带回调 2。`bind` 住**通道**（与 `mode`／`phase` 同理，是（命令, 通道）对的属性）；换算走 `args` 的 `required`／类型派生守卫；**载荷类不塞进 DSL**（在 JSON 里写小程序，与「不引通用工作流框架」同款否决）；手写 handler 住**适配器**按 `id` 对齐。
3. **`summary` 取工具面 description 逐字，仅面板通道的命令可缺**：面板侧今天没有任何命令文案（都在 UI 里手写），为 49 条仅面板命令现写人话文案是产品文案、不该由实现票代笔。仅面板命令的缺文案登记为待办票。
4. **配对按引擎入口**：命名口径只覆盖 23/111，而引擎入口口径自动消解三类命名例外（截断／单复数／域名词）；实测「多工具 × 多路由」的歧义组 0 组。
5. **声明按域分文件、单点装配、门在装配表上跑**：体量实测约 2000 行／90KB，远超「宿主单文件 ≤900 行」。**域分组是表内字段、可以落到文件**——约束的是唯一性与配对要有**全局视角**，不是物理文件数。
6. **零依赖口径放宽为「零运行时依赖」**：注册表只允许 `import type`（构建期擦除，UI 跨包 `import type` 的前提不变），禁止任何运行时 import。
7. **一票到底、不拆子票**：骨架、门、两个通道切生成路径、UI 同源派生在一次交付里完成；每步 `npm test` 全绿、分步提交、可独立回滚。

## 九道门

**① `engine` 存在性 ② 队列阶段 ③ 唯一性（`id`／`tool` 名／`(method, path)`）④ handler 覆盖（适配器 id 集合 == 注册表非生成路径命令，无孤儿无死代码）⑤ 指南投影 ⑥ 零运行时依赖 ⑦ 零行为漂移（工具面 name/description/parameters 快照 + 路由探针快照）⑧ 声明与面一致 ⑨ 可达性**（每个命令至少一个可达面，通道种类遂由 `agent`／`panel` 扩为 `agent`／`panel`／`ops`——#257 / ADR-0083）。

门体在 `tests/commands.test.ts`、各带自检；阈值的实测链与快照迁移登记在 `tests/README.md`（门册）。

## 后续裁决与修订

**#185（2026-09-12）阶段命名统一 + 可选参数 fail loud**：`GEN_JOB_PHASES` 全表统一英文小写（`种子→seed`／`生长→growth`／`富化→enrich`／`罗盘→compass`／`反编译→decompile`／`计划→plan`／`里程碑→milestone`；`outline`／`sections`／`quiz` 不动）——依据是 phase 原值不直接示人（生成页与通知都是「值 → 中文标签」映射），持久化值与声明统一为 ASCII 标识符；迁移走**读侧别名、不拒载**（别名表只住宿主恢复缝，现值原样、旧中文值映射、**未知值原样透传**，写侧一律产现值）；**可选参数收紧为 fail loud**——十个 `opt*` 守卫从「类型不符就不带出该键」改为「键缺席 → 省略语义不变；**键在场但类型不符 → 抛 `ParamError`**」（显式 `null` 也算在场且类型不符；空白文本／显式 `false` 等值级 convenience 保留）。受影响命令（47 条）与快照迁移明细见门册与 #185 票面。

**#155／#156（2026-09-12）面板诚实性、报错卫生、`enrich` 词表位剔除、双提案联合 apply**：图域五条入队路由响应加 `queued` 旗标（入队成功 `true`、同键在途拒绝 `false`），让「假成功」可被 UI 分辨；`GEN_JOB_PHASES` **剔除 `enrich`**（推翻 #185 的「保留词表位」——覆盖层回填是同步受理产 pending 提案的通道、从无队列形态）；静态伺服报错卫生（`/file`、`/vendor` 的扩展名判定改从文件名段取，报错不回显请求路径，面板页 500 不拼接 `err.message`）；`/proposals/apply` 检测反编译对自动走联合入口（kind ∈ {seed, project_plan} 且带 pair 联动 → 直调 `project.projectDecompileApply`，该入口由此从工具独有变两面共享）。

## 替代方案（否决）

- **以命名规则当地基**（工具名 ↔ 路由路径作主键）——只覆盖 23/111，另三类例外要么被硬编码成规则表、要么漏掉。命名是**属性**，不是身份。
- **「允许通道」与「执行模型」拆成两个 per-command 字段**——表达不了（命令, 通道）级分叉：要么把 `compass_paint` 压成单值（改行为），要么再加第三份「分流例外」清单（把分叉降级成待清零的债，而不是类型里的一等事实）。
- **生成 `ui/src/api.ts`**——加 build 步骤；而调用点形状其实不必变，生成物只多一层构建依赖与一份需要同步的产物。
- **泛型 `invoke(id, args)` 直接取代 111 个手写函数**——收益最大但 139 处调用点要改，与「公共面零改动」相抵；属规格已明确另开票的终极形态。
- **运行时输出校验**（引 schema 库检查响应形状）——与 ADR-0042 否决 zod／ajv 同源：输出形状是编译期事实，运行期再验一次买不到信任，只买到依赖。
- **先让路由与工具一一对齐再建表**（补齐 49 + 26 条对侧缺失入口）——那是新增可达性的 scope change，不是统一化。

## 边界

- **不新增可达性**：26 条 tool-only、49 条 route-only 的引擎方法保持原样。「一份声明、两个适配器」是机械统一，不是「面板能做的都给 agent 开个工具」。
- **与 ADR-0038 的关系**：0038 的「面板能做的，指南不再宣传」从文档句子变成 `channels` 上的可执行事实——`AGENT_GUIDE` 的工具名降为注册表的**受检投影**（门断言每条 `tool` 名 ∈ 注册表且通道分类一致）；指南文案仍手写（教学性文字，不是派生物）。0038 的传输裁决不受影响：面板下发照旧复用全局串行生成队列。
- **UI 同源**：111 个 `api.ts` 端点函数名与签名保持不变、139 处调用点零改动；响应类型从 `output` 派生，顺带收口 19 个引擎形状镜像与 49 个内联匿名响应类型、消掉 camelCase→snake_case 的第三处手写映射。**不做代码生成**（加 build 步骤是 ADR-0042 同类的工具链成本）。
- **迁移是增量、一次一条命令**（ADR-0043 的逐刀纪律）：每条迁完、`npm test` 全绿、才删旧分支，注册表与旧实现可长期并存。**「门面转发层消失或自动生成」**（消费方直连子系统）是终极形态，已由 ADR-0049 定案（终态 C 形态，施工票 #182），本 ADR 不裁。
- **不新增任何依赖**（不引 zod／ajv／代码生成器／运行时输出校验）；`src/tool-contracts.ts` 是运行时**守卫函数**模块、不是契约表，也不枚举任何工具——它贡献校验语义，注册表不复用它的形状。
- `ui/` 的类型错与它自己的 tsconfig／vite 构建不在本 ADR 范围（现状看 `npm run typecheck` 与 `scripts/arch-baseline.json`）。

**施工与迁移明细**见 #165／#169／#185／#155／#156 票面与门册 `tests/README.md`；`git log` 是完整流水。
