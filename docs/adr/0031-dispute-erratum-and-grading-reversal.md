# 瑕疵题勘误与判罚冲正：申诉有出口，账本可净额修正，但 FSRS 与原始流水不动

「题目错了而不是我错了」此前在学习流程里无处安放：判错全额记账（0 XP、FSRS Again、练习证据 EMA 下滑、完成门禁正确率、会话连对），唯一近似的出口是「提意见重出一题」，但它不触碰任何已落盘判罚；判卷逃生门只覆盖判卷器故障，规则判卷（比对答案键）永远不会触发。本裁决给这个状态一条完整链路，并同时收敛四条边界：

1. **判错反馈必须能对上作答**：判错结果态公布答案键并点名差异（「漏选了 A」「从第 2 项起顺序不对」）。实践中大量「题目错了」其实是「判错反馈没展示键，学习者从解析反推出一个自相矛盾的键」（实测案例：多选漏选 A 被当成坏题）——这是展示缺陷，不是判卷缺陷，先修展示。
2. **申诉走 AI 两阶段复核**：复核模型先只看题面独立解题、再与存储键/解析对账，三态裁定（键错/题面坏/题没问题）。纯用户说了算会架空「答错」这个诚实信号；纯机器裁决在个人学习工具里越权——最终解释权留给用户，复核说题没问题仍可二次确认强制豁免。
3. **记账三分法，豁免永不得分**：键错 → 改键并用新键重判被申诉的作答，原作答符合新键则改判为对（补 XP/对错/EMA）；题面坏 → 本次作答作废（逃生门口径）+ 归档重出；强制豁免 → 同作废口径。核心立场：豁免是「这题不算」，永远不产生得分；改判只能来自键修改后的重判——「判我对」这个动作不存在。
4. **冲正是追加的抵消凭证，不是改写**：`state/勘误.jsonl` 追加裁定记录，practice.jsonl 永不改写；XP 与作答统计等聚合账读侧按净值算。FSRS 调度不冲正、review-log 不抹除——给 FSRS 发明「负评分」需要重定义整个推进语义，而调度误差会自愈（作废题归档退出调度；改键题按新键继续调度，多推的一次 Again 只影响间隔不影响对错史）。frontmatter 里的 EMA/计数是增量聚合，逆向调整为单步逆推——争议条是节点最新证据时精确，否则是派生读侧可接受的近似（EMA 不是 canonical，ADR-0007）。历史作答不追溯重判：错过的下次复习按新键判，自然矫正。

预防侧同步收敛：出题提示词升 v9 加「交卷前逐题独立重解、键/解析/题面三方对账」硬约束（自检在同一上下文里效果有限但零成本）；多选「至少 2 个正确项」从 prompt 约束落为写入侧门禁（生成入库与修订路径拒收，读取侧保持宽松——存量题库的历史违例不该让整个题库读成 Broken，显式盘点修复）。生成后的二次独立校验调用（成本翻倍）暂不做：申诉链路已是兜底，等真实坏题率数据再议。
