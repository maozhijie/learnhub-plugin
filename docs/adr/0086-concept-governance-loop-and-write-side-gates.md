# 概念层治理回路与写侧门：合并提案化、候选派生、近似名预检、量级纪律、注入上限

概念层在 #262（地址生命周期）之后仍有两处结构性缺口：**唯一许给人判断的动作（合并）是唯一没有门的动作**——agent 直写、无确认，而合并不可逆（只并入、不拆分）；混淆对只有手写声明一条路，没有从数据挖候选的机制，只能腐。同时写侧纪律不均匀：生长批只拿到「在册 N 条」一个计数，近似名重复是系统性产出；错误卡生成期读到的概念名无在册门；概念侧无量级纪律；混淆对注入无上限。本 ADR 把 #264/#265 的裁决落成纸面（父票 #260；域词条 CONTEXT.md「概念」「概念登记表」已同口径修订）。

## 裁决

**① 合并走「提案 + 人确认」两段式，直写面退役。** 合并与图变更提案同规格：`proposeConceptMerge` 受理（在册对表 + 归一 + 自并/未在册拒收）→ pending → **人的动作**（面板 /proposals/apply，kind=concept_merge）→ apply 双门复验后落盘。未确认不落盘。不可逆语义在提案面**双形态声明**：产物恒带 `irreversible: true` + 不可逆全文 `irreversible_note`（`CONCEPT_MERGE_IRREVERSIBLE` 单源；apply 复核声明文本被篡改即拒——不可逆语义不接受改写）；受理回执与 summary 带短句「只并入、不拆分」。确认门**只从面板可达**：agent 无 apply 工具（graph_apply 只收 edit/enrich）。原直写面 `ConceptRegistry.merge` 删除——留着它就是留着绕门的第二条路。
*否决*：agent 直写 + 事后 journal（门在人看之前，等于没有门）；apply 前二次弹窗确认（面板 apply 本身就是确认动作，加一层是税）。

**② 混淆对候选从题目共现派生，走提案，人审一次一条，绝不自动入册。** 派生证据两类：同一节点题目各自 invokes 的概念对（同一学习动作里被同时调用的概念）；节点误解先验的概念与其题目 invokes 的概念对（错答侧 × 正答侧）。全部经精确解析归一，**未在册不提名、任一端废弃不提名**（ADR-0084 ② 的候选面退出）；登记表已声明的对（无序，`conceptPairKey` 单一身份键）不再提名；pending 提案的对不重复堆（按**产物结构**比对 a/b，不靠 summary 文本；重跑幂等）。单次扫描产出上限 20（人审队列是人的吞吐），每条提案携带逐条共现证据行——证据随产物落盘（提案记录的 artifact 即可查），summary 带首条证据使人审列表即可读；提案详情视图归 UI 票（父票 #260 已裁 UI 另票）。接受（apply）后**只写提案声明的那个方向**：单向合法但是待复核态（ADR-0084 ③），写入侧不自动补双向。
*否决*：候选自动入册（与「别名自动收编永远人审」同一纪律冲突）；写入侧按候选自动补双向（无依据造数据）；派生范围扩到跨节点题目共现（证据弱、噪声大，先不做）。

**③ 近似名预检是软提示，不改精确撞名的硬拒。** 铸名受理门对本批新名（canonical ∪ 别名）与在册名字全集（含**废弃条目**的地址——它们仍占名位）做字符 trigram Jaccard 检测（与题目侧查重 #119 同算法族，独立阈值 0.6——概念名短，0.6 已属写法近似），超阈值随受理回执 `warns` 回报候选清单，提交方自行决定改名或在 reason 里说明。精确相等仍由 `mintConflicts` 硬拒——两个门的业务不重叠。
*否决*：近似名硬拒（拦截合法铸名，软语义；说明义务在提交方）；语义模糊匹配（业务外，ADR-0084 已裁）。

**④ 概念侧量级纪律与节点侧同规格：WARN/ERROR 两带，只报不拦。** 别名条数带 4/8，混淆对条数带 8/16（WARN 带 = 注入上限，越过即「注入面已在截断」）。报到三处：铸名受理回执（本批落盘后的量级读数）、data-check（`concept_registry_magnitude`，hint 级——**不是** broken：别名是历史地址，全部照常解析，断读才是违约；量级是「该收敛了」的信号）、合并提案回执（并入是别名增长的主通道，回执带并入后的量级读数）。
*否决*：超量拒写（拦下别名即断历史地址的读，与 ADR-0084 ② 冲突）；ERROR 带升级 broken（数据没坏，门不能谎报）。

**⑤ 混淆对注入设上限 8 条，超限按稳定序截断并在注入文本内披露。** 稳定序 = `confusablePairsOf` 产出序（登记表文件序的纯函数，同输入恒同输出，不排序不重排）；披露行写明「共几对、注入前几对、上限多少、为什么」——静默截断会让模型以为清单就是全部。披露文字是**组装面文本**，不是提示词常量 ⇒ 不触发 prompt-bump（#260 用户裁定的同一口径；`TEMPLATE_FILES` 扫描的版本号集合无变化）。

**⑥ 错误卡生成期概念引用补门，与节点三面、题目 invokes 同口径。** 误解先验进提示词材料前过登记表在册集：不在册的名字**拦在材料之外**并随生成结果如实报告（`unregistered_concepts`）——静默喂给模型等于把悬空地址洗成「先验」。登记表 Broken 时本门降级为不生效、生成照常（ADR-0071 宽容读取，生成不被数据异常拦腰打断）。

## 与 ADR-0084 的接续

ADR-0084 三条自净判据在本轮全部落地：孤儿可见面（#249 足迹）→ **对称性纪律**（读侧单向标注 #262 + 候选派生走提案本轮）→ **量级纪律**（本轮 ④）。治理闭环的最后一块是「待决动作的一处可见」：合并提案与候选提案都进既有提案清单（kind 过滤 `concept_merge` / `confusable_pair`），面板提案列表即人审收件箱，零新账本。

## 行为与门影响

- **PROPOSAL_KINDS 扩容**：`concept_merge` / `confusable_pair` 入 vocabulary 单点（types.ts）；提案统一 apply 入口 `proposalApply` 分发两新 kind（面板 `/proposals/apply` 消费，agent 工具面不暴露这两个 apply）。
- **受控面迁移（同提交完成）**：工具 111→112（+`learnhub_concept_confusable_candidates`；`learnhub_concept_merge` 语义改为提案受理，新增可选 `reason`）；`host-tools-snapshot.json`（3 处描述 + 1 参数 + 1 新工具）、`host-tools-behavior.json`（+2 探针）、`host-face-baseline.json`（toolOnly 26）、命令注册表 155→156、G5 棘轮 7 文件。
- **提示词模板文本零改动**：近似名提示、量级告警、截断披露全部是引擎侧组装文字或工具描述；`prompt-bump check` 恒绿，不占 prompt-bump 单点。
- **已知缝（如实登记）**：教练回合路径的受理 `warns`（近似名候选等）随 `proposeEdit` 产生但回合结果不携带——与既有「窄节点 WARN」同缝，非本轮扩大；工具面 `learnhub_graph_propose` 的受理回执完整携带（#264 验收判据在该缝上成立）。

## 替代方案（否决）

- **合并保持 agent 直写、加审计告警**——不可逆动作的事后告警不是门。
- **候选派生走 LLM 生成**——共现是机械事实，模型编的证据不可审；派生必须纯函数、可复现。
- **注入截断只截不披露**——模型把截断清单当全集，比不截更危险。
- **量级纪律做成硬门**——见 ④ 否决，别名断读是违约，超量不是。
