# ADR-0061: 输出契约注册表 phase 1——契约数据单一出处 + 文本锚门

日期：2026-09-13 ｜ 票：#214 ｜ 总纲：#212（生成管线稳定性与内容质量工作流）

## 背景与问题

每站「输出什么形态、允什么成分、败了几轮、挂什么码」散在解析器代码、提示词文本、提交信息与 ADR 散文里。近三个月全部生成事故都是**契约矛盾/边界不清**（enc_candidates 串入大纲、溢出死局、§8 与「只输出一个 YAML」同包自相矛盾），零例是 YAML 语法错、零例是解析器 bug（#212 §二）——修复模式已体系化，但契约本身没有单一出处，模板改一句、解析器改一门、谁也不会被提醒对账。CONTEXT.md「输出契约」词条承诺了注册表，本 ADR 落地 phase 1。

## 裁决

### 1. 注册表 = 引擎侧纯数据模块（`src/engine/output-contracts.ts`）

每站一条 `OutputContract`：形态（`yaml | markdown-blocks | json | route-text`，**`'json'` 枚举位保留** = 未来迁移口子）、契约句原文锚（`clause`）、允许/禁止成分、修复策略（轮数/反馈形状/升档——**如实登记现状**：罗盘 0 轮、回执 0 轮（ADR-0004）、出题无整批轮）、失败码族、解析容忍、**格式敏感度**（机械评审/规划/推理创意）与结构化资格、phase 1 格式级 shape。同站多交付面用 `surface`（课程节生成的正文/交互件）。会话式辅导站（讲解反馈/自注反馈/老师辅导/讲给我听）**明示不在册**（`OUT_OF_SCOPE_STATIONS` 带理由）——覆盖面是显式清单，不是漏登。

### 2. 站名对齐走测试三方核对，不走引擎引宿主

站名 = 语料站名词表（host/corpus.ts `STATIONS`，#213）的同名值。R2（引擎禁引宿主）不许注册表 import STATIONS——对齐由文本锚门测试三方核对（注册表 ↔ `PROMPT_KINDS` ↔ `STATIONS`）：契约站名必须在词表、模板键与 `PROMPT_KINDS` 全集一一对应、不在册站名不得是幽灵。

### 3. 格式敏感度治理结构化迁移资格

敏感度三轴（机械评审/规划/推理创意）记录各站对形态变化的敏感面；**phase 1 对齐现状的不变式：`structuredEligible === (format === 'json')`**——只有已在 JSON 通道上的站（判卷/申诉判卷/回执评审，分类任务正向证据充分）有资格维持结构化通道；YAML 站群默认不迁（#214 增补：多样性坍缩对 JSON/XML 指令显著、YAML/CSV 不显著，arXiv:2607.18476）。迁移裁决归工具调用 spike（#216）双臂协议，不因「JSON 好解析」单边改判。

### 4. 文本锚门（`tests/output-contract.test.ts`）

模板文本与注册表交叉核对，漂移即红：契约句（「只输出一个 YAML 文档（不要代码围栏、不要任何解释）」族原句）逐锚全文命中；**yaml 站模板不得出现 `enc_candidates`**（§8 契约矛盾事故类的直接锚）；判卷族系统提示词与回执评审 system 契约、交互件规范块同门对账。门带自检（ADR-0047 铁律①）：改坏契约句、往 YAML 模板塞机器块、改注册表不改模板、删模板键、幽灵站名、破坏资格不变式——六个变坏样本各自必须变红。

### 5. 校验器 phase 1 = 格式级前置（不改行为）

`validateByContract(entry, parsed)` 只锁「解析产物像不像本站产物的形状」（yaml/json 顶层键与类型、节正文 ## 开头无 frontmatter、里程碑四块齐全、路线正文无标题无围栏）；深结构门（逐题形态、候选对照、名字对账、条目数）仍归各站既有解析器，phase 1 不接线进管线、不改任何行为——它是 #217（修复轮策略统一）与评审器（#222）的消费面。

## 6. phase 2 设计（本票出设计，另立票实施）

装配器按各段契约依赖声明自动推导裁剪：`OutputContract` 增 `packDeps` 列（该站消费上下文包的哪些段：如大纲站 `[§1–§7, §9–§13]`、节生成站全量含 §8）；`contextPack` 改为按在站 `packDeps` 投影，`omitDeliverables` 从调用点手工指定变为「包装配器读在站契约自动推导」。验收形态：契约矛盾（包内指令与在站输出契约冲突）结构性不可能复发——大纲包永不可能带 §8，因为装配器只认注册表不认调用点。机器块家族（enc_candidates/learnhub-interactive/learnhub-predict）作为「节正文契约专属成分」登记在契约的 allowed/forbidden 里，装配器据此裁剪。

## 后果

- 契约有单一数据出处；模板改句、解析器改门，锚门红着等对账。
- 「迭代漂移」的根被堵在 review 面：漂移在 `npm test` 即红，不等生成事故。
- 修复策略现状（出题无整批轮等）被显式登记为数据，#217 的评估有了基线。
- 代价：每站契约多一处要同步维护的声明——这正是目的（同步成本显性化）。
