# ADR-0071: Vault 先验检索换核——BM25 式打分、登记表查询扩展与检索审计

日期：2026-09-13 ｜ 票：#229 ｜ 总纲：#212 ｜ 证据：#225 报告（docs/research/2026-09-generation-methodology.md，四个真缝隙之一「检索词面召回与静默缺席」）｜ 前身：V-2 / #106、#78 调研（宿主无嵌入 API）

## 背景与问题

Vault 先验（`src/engine/vault-prior.ts`）是「生成尊重学习者已有的理解与记法」这条产品承诺的唯一实现路径。它不是通用搜索，是**每次生成前的三件小事**：派生检索词、扫个人笔记、注入 top-3 摘录。旧实现这三件都停在原型水平：

- **打分是 `String.includes` 计数**（标题 +3、正文 +1）：无 IDF（「基础」这类无处不在的词与只出现一次的概念词同权）、无词频饱和（同一篇里出现十次就十分）、无长度归一（长笔记靠堆字攒分）。词面检索的范式下限是 BM25，`includes` 连它都不是——而这是「召回到没召回到」的唯一决定因素。
- **检索词只来自课程规范词表**（节点名 + 直接前置名）：学习者的私人记法恰在词表之外（Furnas 词表问题）——他明明在笔记里写过，系统却读不到，于是「不从零教已会内容」在这些人身上失效。
- **零命中静默返回空串**：个性化缺席没有任何信号。学习者读到的差异只是「生成得有点空」，无从知道这次生成没读他的笔记，更无从区分「确实没记过」与「检索没命中」。`maxFiles` 截断同理（按目录字典序取前 2000 篇），且是**系统性偏斜**：胜出的永远是同一批目录名靠前的文件。

三件都在 `searchVaultPrior` 这一个换核边界内——**注入面不动**：注入段形态（`priorSection`）、注入位置（上下文包尾部）、只读纪律（ADR-0010）都不变。

## 裁决

### 1. 打分换核：BM25 式（IDF × 词频饱和 × 长度归一 + 标题字段加权）

- **IDF**：Robertson–Spärck-Jones 式 `ln(1 + (N−df+0.5)/(df+0.5))`——**恒正**（含标准 BM25 在 df 接近 N 时的负分病，不作出手修复，直接取恒正形）。`N` 与 `avgdl` 取**全部读到的文件**（BM25 的集合级量；只拿命中面算会把基准挪到命中面上），`df` 只需命中文件计数（未命中文件词频恒 0，不进 df）——故仍是**一遍扫面**，不做两遍。
- **词频饱和**：`tf·(k1+1)/(tf + k1·norm)`，k1 = 1.2。旧口径的每出现一次 +1 是线性的，于是「同一篇里刷十遍」比「另一篇写对了一次」更值钱。
- **长度归一**：`norm = 1 − b + b·dl/avgdl`，b = 0.75（字符长度口径——本仓无分词器，CJK 用字符长度是唯一可用且可复现的 dl）。
- **标题字段加权**：标题命中计 `TITLE_FIELD_BOOST = 3`（旧核 +3/+1 的数量关系以字段加权形式保留）。标题**不做长度归一**：短字段命中即信号，标题之间的字数差没有信息量。
- **未调参**（如实登记）：k1/b 取文献常用默认值，本仓零相关性标注语料，**没有能力**调参。改这两个数 = 改打分口径 = 改本 ADR，不是「顺手调一下」。同理摘录窗口从「词表里第一个命中的词」改为「权重 × IDF 最大的命中词」——旧口径下同一篇笔记换个词序摘出来的就不是同一段。

### 2. 查询扩展：概念登记表别名 + 易混概念，低权重并入，只做一级

`expandPriorTerms(terms, entries)`：基础词保底权重 1；词面能经**精确解析**（`resolveConcept`，与概念面同口径）落到条目上时，并入其 `aliases`（`ALIAS_TERM_WEIGHT = 0.5`）与 `confusable`（`CONFUSABLE_TERM_WEIGHT = 0.35`）。三处设计约束：

- **扩展词是召回线索，不是同义断言**——故低权重而非同权：规范词命中的笔记要排在「只在别名上命中」的笔记之前。
- **同名取更高权重那一档**（基础词 > 别名 > 易混对）：同一个词面在打分面只出现一次，不会被打两遍分。
- **只做一级，非递归**：别名的别名不再并入（登记表是人工受控词表，二级扩展会把词面炸开，且「相关」的传递性没有保证）。

检索词派生的**唯一出口**是 `priorQueryTerms(raw, entries)`（三个检索入口共用）：两处各拼一份词表必然漂移。

### 3. 可观测性：每次检索必产审计，随生成任务记录带出（ADR-0004）

`VaultPriorAudit` = `{ terms, expanded, scanned, matched, scanTruncated, hitsTrimmed, zeroHit, hitPaths, expansionError? }`。三条要点：

- **零命中与两种截断必留痕**：`zeroHit`（注入面整体缺席；**无检索词**与**检索了没命中**两条静默路径合流到同一读数）、`scanTruncated`（扫描面被截）、`hitsTrimmed`（命中数超 limit，只带前 limit 条）。命中文件清单 `hitPaths` 一起带出——「这次生成读了学习者哪几篇笔记」是生成回执该有的信息。宿主 `priorNoteOf` 把它折进 `GenJob.message`（正文/单节重写/纯出题/种子起草/目标反编译五条路径）。
- **审计走注记回调（`onPrior`），不占返回值**：`contentPack` / `questionGenerate` / `questionGenerateSections` 的返回面被路由与工具行为快照、以及宿主 12 处引擎桩固化，改形状要迁移整张网，而审计是**观测面不是产物**（`onTolerated` / `usageSink` / `corpus.record` 同族先例）。图域两站（种子起草/目标反编译）本就带 `prior_hits` 字段，直接**升为结构审计** `prior: VaultPriorAudit`（agent 工具面随之可见；「未选配先验」= 字段缺席，与「零命中」是两件事，不合并）。
- **登记表 Broken 时降级不静默**：概念登记表是**检索增益不是生成前置**——Broken 不拦生成（降级为基础词），但错误经 `expansionError` 随审计带出。理由：Broken 的登记表已由 data-check 与概念消费面（出题对表）报出，检索面再拦一道会把可选增益变成生成前置，代价与收益不成比例。

审计**形状**住中立词汇层 `src/engine/types.ts` 而非检索核：它同时被检索核与消费子系统引用，而 question-bank → note-source 已有边——形状若住检索核就成环（`note-source → question-bank → vault-prior → note-source`，R7 执法，实测栽过一次）。形状与实现分居两处是本仓既有形态。

### 4. maxFiles 截断改 mtime 优先（顺带）

读取面仍封 `maxFiles`（默认 2000，防超大 vault 拖垮生成入口），但**选哪 2000 篇**改为按 mtime 降序（并列按路径定序）——旧口径的字典序截断是系统性偏斜，而新近改动的笔记更可能是本次生成的先验。收集面另有一个更宽的窗口（`maxFiles × MTIME_WINDOW_FACTOR = 10`）：窗口外仍按字典序前段截取，因为 **walk 的算力上界不能由 vault 规模决定**（旧实现让 maxFiles 同时兼任这两件事，于是 mtime 优先无从谈起）。未触顶时根本不看 mtime（常见路径零额外 IO）。端口面为此 +1：`VaultFs.statMtimeMs`（engine 内零 `node:fs` 的 G8 纪律不变，实现仍住 `host/vault-fs.ts`）。

## 登记与代价

- **G3/G4 窄面棘轮**：`ContentDeps`/`ProjectDeps` 各 +1 声明/实用/接线/`handles`（`concepts: Pick<ConceptRegistry,'load'>`——查询扩展要读课程登记表），同提交迁移基线。
- **G5 文件规模**：`vault-prior.ts` 149→347（新核与审计主体）、`content-subsystem.ts` 1046→1057、`projects.ts` 1413→1423、`question-bank.ts` 1558→1568、`graph-subsystem.ts` 604→608、`host/jobs.ts` 1212→1241（注记函数 + 五站接线）、`io.ts`/`vault-fs.ts`/`index.ts` 各 +1～3。
- **行为快照**：`host-routes-snapshot.json` **3 条探针**的引擎调用参数变化（`content2.contentPack("1","1")` → `content2.contentPack("1","1",{})`——注记回调被探针序列化丢弃），status/响应体**逐字不变**，diff 逐条人审；`host-tools-behavior.json` 零变化。**工具面/路由面调用点与响应形状零改动**（审计不走返回值）。
- **未做**：嵌入/混合检索（宿主 API 未提供，换核接口已留）、块索引缓存（非当前主要矛盾）——同 #229 票面「明确不做」。

## 验收链

- 打分口径：`tests/vault-prior.test.ts` 按可判读命题断言——IDF（罕见词文档压过常见词文档）、长度归一（短文档分高）、词频饱和（tf 3 > tf 1 且 < 3×tf1）、标题字段加权。
- 扩展：别名命中可复现（**不扩词零命中 → 扩词召回**的对照）、扩展词低权重（规范词命中排在别名命中之前）、同名取高档、一级非递归、`queryEntriesFor` 的 Missing/Broken 两态。
- 审计：无词（零扫描）、零命中（有扫描面读数）、结果面截断、扫描面截断 + **mtime 优先实跑**（`utimes` 拉开时间戳断言取到新文件）、扩展词清单、Broken 错误带出。
- 入口贯通：`contentPack` / `questionGenerate` / `questionGenerateSections` 的 `onPrior` 审计（含登记表别名在生成入口生效的端到端样本）。
- ADR-0010：个人笔记零写入断言照旧（既有测试保留）。
