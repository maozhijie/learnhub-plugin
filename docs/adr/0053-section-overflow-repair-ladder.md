# 节内容溢出的修复阶梯：预算校准、压缩修复、大纲拆节与 partial 续跑

正文管线的失效链在实机上走通了一次完整死法（档 2 节「演示：从『买了3袋苹果』到『3×6=18』」606 字 > 拒收线 500 = 250×2）：**给模型的信息自相矛盾**——上下文包 §6 规范约束残留整课旧管线的「正文 ≤ 2500 字」，与 §9「单节 ≤250 字」并存，模型写 606 字恰好落在两口径之间；**修复轮指令不可执行**——finding 让模型「把内容拆成多个节」，而节 prompt 硬约束是「只输出一节」、修复指令是「其余内容原样保留」，拆节在节内结构上不可能，真正可行的动作（压到多少字以内、按什么口径数）从未直说；**预算数字本身拍脑袋**——「一节 = 学习页 1–2 屏」折算约 400–800 字，锚点 150/250/400 只够半屏。死局收尾同样成立：一节失败 fail-fast 中止整节点（余节全部不生成），失败横幅是纯文本零按钮，报错建议的「单节重写」对失败节不存在（未落盘不渲染）、「面板人工修正」无面板编辑器——用户「什么都做不了」。本 ADR 定四层修复的语义：**预算校准**（引擎锚点）、**修复阶梯**（压缩→拆节）、**partial 续跑**（一节失败不处死节点）、**失败恢复入口**（结构化失败信息 + 动作按钮）。

理由：四层共享同一个根因——「一次门禁失败 = 终局」把修复成本全部转嫁给了用户，而修复所需的信息（哪节、超多少、压到多少、怎么重拉）系统全都有，只是既没告诉模型（提示词矛盾）也没告诉面板（纯文本横幅）。修复阶梯与既定模式同族：门禁修复轮、大纲护栏反馈轮、生长批回灌重裁（ADR-0050）都是「携带死因的修复轮、恰一轮封顶」——本 ADR 把这族模式补齐到「压缩不足以修复」的溢出场景，拆节就是溢出的结构出路：大纲本来就是模型规划的，把「拆成多个节」从不可执行的建议变成真实的管线动作。

关键裁决：

- **预算锚放宽为 250/400/600（低/中/高），警告 ×1.3、拒收 ×2 倍率不动。** 单一旋钮：`TIER_ANCHORS.sectionWordBudget` 改一处，§9 预算行、finding 文案、阈值全部派生；节区间、题量锚、大纲护栏零改动。**计数口径锁死**：正文字数 = 去空白、去公式（`$…$`/`$$…$$`）、去可视化与交互块（全部是围栏机块，剥围栏即剥块）后的纯文字数——交互件行数再多不计入篇幅，口径写进 finding 与修复指令，防止「模型以为的超长」与「质检判定的超长」是两个数。§6 的「正文 ≤ 2500 字」整课遗留口径删除，篇幅语义唯一出处是 §9 复杂度档案。
- **长度 finding 的修复轮升格**：修复指令直说目标「压缩到 ≤ 预算 X 字（X = 本节档位预算）」并附计数口径；「拆成多个节」只留在给人看的 finding 文案里，修复轮明确「拆节由管线负责，此处只压缩」。修复轮 effort 升一档（fast→中）——用与失败同档的配置盲试是已知死法；块级修补失败后的整节修复回灌**块级修补合并后的原文**（修掉「初跑原文配合并清单」的定位错位）。单节重写通道改用与管线相同的剥围栏 seam。
- **压缩仍超 → 自动拆节**：长度 finding 修复一轮仍超拒收线时，管线调模型产 2–3 个子节（title/type，可带 points/tier），替换原节在 manifest 中的位次，随后逐子节照常生成（子节各有常规修复资格）。**深度 1**（子节不再拆）；拆后总节数 > `MAX_SECTIONS` 不拆、按失败节处理；子节 id 引擎派生（原节 id 前缀 + 序号）保证唯一；拆节发生在运行中、无确认步骤——它是修复动作不是结构承诺，节的数量与划分的结构权威仍在罗盘与生长批。journal 与任务 message 留痕（「节 X 溢出，已拆为 X-1/X-2」）。非长度 finding（坏 JSON、缺预测门等）不触发拆节，照旧块级修补/整节修复。
- **一节失败不再中止整节点（continue → partial）**：逐节循环捕获单节终局失败，余节照常生成；自动出题只对就绪节做 + 综合题照出；终态 partial（既有词条语义），失败节清单结构化落任务记录 `failures`（code/sectionId/sectionTitle/finding），message 带档位与预算数字。续跑语义 = 重新入队即断点续跑（ready 节跳过，既有行为升格为正式词条「续跑」），失败节在续跑中重走完整阶梯。
- **失败恢复入口**：学习页失败横幅从纯文本改为结构化错误 + 动作——**重试续跑**（重新入队）、**定点重写失败节**（`failures[].sectionId` 走单节重写，失败节在大纲里从未消失，只是 UI 按 `##` 解析看不到）、**转 AI 修复**（预填失败原文开 dsh 会话，复用生成页「与 AI 讨论」机制）、**关闭**（存 UI 本地——任务注册表如实反映账面、不掺视图状态，关闭是视图操作）。生成页 failed/partial 行补「重试」按钮（对齐 ADR-0050 生长批重试按钮先例）：内容任务重走 POST /generate（即续跑），出题任务重走 POST /question-generate。

边界：

- **质检门清单零改动**：门照旧执法，本 ADR 只修「给模型的信息」与「失败之后的路」；拒绝「超限警告落盘」的放门方案——一节 = 学习页 1–2 屏是产品契约。
- 重试纪律不变：压缩修复恰一轮、拆节深度恰一层，无指数退避、无自动重试环（ADR-0050 同判）；阶梯走完仍失败 = partial + 恢复入口，处置权交人。
- 大纲初次生成与大纲护栏零改动；拆节不复用 `outlineApply` 的整清单覆盖路径（那会动别的节的 ready 状态），走定点替换。
- 失败信息结构化是磁盘子格式演变（生成任务.json 加可选字段）：宣告式断裂纪律下子格式在主版本内灵活演变，恢复侧对缺字段旧档案按「无失败信息」读。

替代方案（否决）：

- **超限警告落盘（放门）**——放弃篇幅契约，把「一节 1–2 屏」变成空头支票；预算过紧的正确修法是校准锚点，不是废掉门。
- **节内直接输出拆节**——违反「只输出一节」契约，装配器按节 id 对位，节内拆节没有落点。
- **长度超标直接拆节、跳过压缩**——多数溢出可一次压缩成功，压缩是一轮调用、拆节是 1+N 轮；阶梯按成本升序。
- **失败自动重试 N 次**——无人监督的烧 token 环；携带死因的修复轮与盲目重跑的区别即 ADR-0050 已裁决的区别。
- **「关闭横幅」标记进任务记录**——注册表是账面（如实反映、不做视图过滤），已读/已关是视图状态，进账面就破了 ADR-0039 以来的记录纪律。
