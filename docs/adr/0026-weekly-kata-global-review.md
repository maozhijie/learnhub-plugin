# 周复盘 Weekly Kata：全局每周一张的五问复盘，有界/无界两区的铰链

决议（#73 Not-yet-specified 收口，2026-09-09，grill 会话）：U-4 Kata 周层的挂接方式落定为**周复盘（Weekly Kata）**入 CONTEXT.md——全局每周一张的结构化复盘（五问：目标条件/现状/障碍/下一实验/预期所学），系统用真实数据填「现状」。证据口径沿用需求池：kata 直接证据弱（Rother 2009 书，标注），机制借 debrief 双元分析（T&C 2013 d=0.67；Keiser & Arthur 2021 d=0.79），有效配方=客观媒体+对齐+学员主导——引擎供客观媒体（现状自动填），学员主导（四问自答）。裁决细目：

1. **挂接粒度：全局每周一张，不 per-project**：同一张复盘里有界（进行中项目各一节+课程区概览）与无界（习惯、技能条目）相遇——「铰链」语义落在同屏；项目多时不至于复盘爆炸。与项目区的挂接=项目是复盘的一节，不是复盘挂在项目下。
2. **学习周**：日历周按学习日折叠（学习日词条口径）；复盘对象=上一完整学习周；不引入滚动窗口。
3. **记录载体**：新记录类型（五问结构）；**现状=引擎自动填真实数据**，其余四问学习者作答；落学习中心我的产出区（V-3 输出区）。归 **Learner Output 域**：零 XP、不进 Mastery/canonical、本身不做 FSRS 卡——复盘是产出不是测量。「复盘对象可被调度」走既有 V-1 注册通道（可注册为笔记源），引擎不强推。
4. **「下一实验」出口（U 区↔D 区正式接口）**：v1 自由文本+两个可选一键转换——(a) 转 N-of-1 实验提案（ADR-0023 的自然入口）；(b) 转执行意图挂目标偏好（既有机制）。
5. **提醒立场：无推送**（ADR-0017 习惯先例+反需求清单「提醒器形态」）：入口在项目/首页周视图常驻；未复盘不惩罚、不清零任何 streak。引擎的贡献是「复盘时把现状填好」，不是「催你复盘」。

同批被拒：per-project 周复盘（项目多时复盘爆炸，铰链语义散掉）；滚动 7 学习日窗口（与日历直觉拧，且学习周折叠已解决凌晨归属）；kata 记录做 FSRS 卡（Learner Output 域边界，ADR-0009）；给复盘记 XP（同域先例：讲解稿/自注解释零 XP；时长判据让位于产出域一致性）；引擎催办（反需求清单）。

工程影响（供执行票消费，非本决议约束）：学习周折叠与现状数据聚合纯函数优先；记录 schema 与产出区落盘随交付票定；Blocked by V-3（输出区约定先行）。
