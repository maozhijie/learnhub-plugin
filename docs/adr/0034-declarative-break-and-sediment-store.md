# schema 演进走宣告式断裂，学习模型状态落沉淀层

schema 主版本升级的唯一通道是**宣告式断裂**：版本 bump + 旧课程树整体移入存档（`学习中心/存档/pre-v<来源版本>/<日期>/`，只增不删、读侧永不读取）+ **零兼容代码**——不迁移、无双读、不降级，引擎启动校验 `learnhub.json` 的 `schema.version` 硬门，不符即拒载指引 cutover。配套**沉淀层**（第四存储域）：学习模型状态——FSRS 参数、校准画像、速度韧性剖面、内容质量结论（按提示词版本归因）、复诊结局、图修复史、概念级先验——**出生即写入**追加 jsonl 正典（`学习中心/沉淀/沉淀.jsonl`，小到单文件可抄走），以登记表概念地址书写（跨断裂存活），消费一律从沉淀折叠读取、禁止再读内容层旧居所。

理由：兼容层让每次演进变成永久负债——旧语义的影子跟着之后每一个新功能走，代码里永远有两种世界观的 if；存档不读把断裂成本从「迁移工程」降为「移动目录」，换来的是引擎永远只伺候一种语义。沉淀层出生即写（而非断裂时抢救）则让「最有价值的数据天然住在会存活的层」成为结构保证而非操作纪律：内容层可以断裂、重生成、剪除、甚至被文件系统硬删除，泛用模型数据无损——课程树只保留代表自己**个性**的东西（图、正文、题目、卡、实例记忆），一切泛用模型状态归沉淀。断裂不变性的边界随之划清：**先验连续，实例记忆不连续**——卡级 FSRS 记忆随内容层归档不迁移（迁移即兼容），合成初始化改从沉淀取先验；模型的脾气跨断裂不变，卡的记忆在新内容上重新长。

落地与代价。版本标记为 `schema` 对象（version 启动硬门、breaks 追加断裂史、formats 子格式独立演变——子格式破坏性变更仍走主版本断裂）；断裂时的沉淀引导档（从存档机械蒸馏）是 v1→v2 的一次性桥，v2 起出生即沉淀、断裂零蒸馏。已认账的代价：每次主版本断裂，学习者的卡级进度（调度记忆、mastery 实例）归零——这是「系统洁净」对「学习者连续」的明码标价，补偿只能走新图生长策略（如从沉淀的概念级先验反推优先铺什么），不做任何形式的兼容读取。行为流水（中心级混流文件）原地保留、以「报表只查现课」实现不读——不搬走是为了不连坐无界域（习惯/技能条目/我的卡复习）的 streak。
