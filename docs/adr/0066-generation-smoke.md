# ADR-0066: 生成冒烟（临时 vault 全管线 + 结构断言报告）

日期：2026-09-13 ｜ 票：#215 ｜ 总纲：#212 ｜ 依赖：#213（语料与 usage 计量）

## 背景与问题

离线测试网是全确定性的：门（G1–G9）、467→471 条路由探针、脚本化假端口剧本、手写合成样本——**实捕模型输出语料为 0**（#212 §一.5）。这条纪律换来了「测试不依赖模型」的稳定，代价是**模型升级/换供应商导致的格式漂移**没有任何自动化信号：解析器、提示词、契约门之间的真实交互只有人起宿主手点。

「#212 §五」的结构化路线与后续各票（#217 修复轮、#218 契约后置、#220 changelog 纪律）都需要一个共同的落点：**改完提示词/解析器，怎么知道模型还认得这笔契约？** 答案不能是「再手点一遍」。

## 裁决

### 1. 管线本体住宿主（`src/host/smoke.ts`），驱动脚本只做三件事

真 provider 只在宿主 ctx 上（`ctx.llm`），所以冒烟必须跑在宿主进程里。分层：

- **`src/host/smoke.ts`**：`runGenerationSmoke(ctx, req)` —— 临时 vault（`mkdtemp`，结束即删）→ 种子起草（真生成站）→ 提案直通（脚本内人审等价：`proposalApply('seed')` + `afterGraphApply` 的入队联动，走生产 apply 路径而非复制一份）→ 正文管线（**生产入队/执行路径**，不复制管线）→ 复跑既有门 → 汇总报告。
- **路由** `POST /learnhub/api/smoke`（命令注册表 `smoke` 条目，无引擎 · 无引擎型白名单）：宿主在场才有意义，参数 `goal/course/quizCount/quizAuditRate/jobTimeoutMs` 全可选。
- **驱动** `scripts/gen-smoke.mjs`（`npm run smoke`）：找宿主（`--base`／`LEARNHUB_BASE`，缺省 3080）→ POST → 人读渲染 → 退出码。拿不到报告时**不静默**：按失败形态打印可执行指引（编译 / 起宿主 / junction 补齐 / 端口占用 / vault 配置）。

### 2. 三块报告 + 三态裁决

- **各站成功率与失败码分布**：读语料捕获（#213 已是「每调用一文件」），按站汇总 ok/tolerated/failed 与失败码计数；
- **token 消耗**：语料 frontmatter 的 usage 三值逐站求和（消费 #213 的计量）；
- **产物结构断言**：复跑**既有门**，不重造判据——`contentCheck`（质检门）、契约注册表 `validateByContract`（大纲/题目 shape）、`bank.load`（读回即过 `validateBank`）。每项带判据出处（报告的 `by` 列），并各自 try/catch：门因前置缺席跑不动时如实记成失败断言（含门抛出的原文），**报告不因断言自身出错而整体坍掉**。

裁决三态：`ok` = 任务 `done` + 结构门全过；`partial` = 任务终态 `partial`（管线的「未完成全部必需阶段」——有节失败或出题整批失败，死因逐条列出）；`failed` = 站级异常（`stageError`）或结构门未过。驱动退出码 0/2/1。

**partial 不算跑通**：冒烟是「干净环境跑通」检查，不是「进程没崩」检查——但死因（节标题 + 失败码 + 语料引用）已在报告里，人读不必翻日志。

### 3. 失败也要出报告（诊断面不给 500）

种子站提案未受理、正文任务失败/超时/消失——都在冒烟自己的 catch 里收口成 `pipeline.stageError`，**照出报告**（站统计 + 死因 + 语料引用），不用 `{error}` 500 打发调用方。站级解析失败的语料补标在冒烟 catch 里做（生产在 `jobs.ts` 的 `failCorpus` 补标；冒烟直调种子站不经队列，同款纪律落在冒烟自己身上），读站统计前 `corpus.flush()`（写盘是异步 fire-and-forget，不放干会把刚补标的失败样本读成 ok）。

### 4. 成本纪律：只跑生成四站

- **挡泵不挡在途**：正文任务开跑后置 `queuePaused`——生成泵排空时的教练生长批（生产行为）会另花真实额度、还可能连锁再生成正文；暂停旗标让后续自动入队的批安静排队（随临时目录丢弃），在跑的管线照常到终态。
- 综合批题量封顶（`GenJob.quizCount`，缺省 4；逐节批按档位默认）；第二意见门缺省关（`quizAuditRate: 0`）。
- 实测量级（1 节点，deepseek-v4-flash）：**11–16 次调用 / 24k 入 + 10–15k 出 token / 55–77s**（含一次真实模型把「思维」节的 `learnhub-predict` 块写坏、修复轮失败 → `partial` 的样本）。

### 5. 自测：解析回归必须现形

`tests/gen-smoke.test.ts` 两条（路由式假 provider 驱动真实管线，零网络）：全绿路径（四站齐全、token > 0、断言全过）与解析回归路径（非法大纲应答 → 站行出现失败码、产物断言失败、`verdict=failed`）。真实链路的注入自测（#215 验收项）实测记录：

```
把 src/engine/yaml.ts 的 parseModel 改成抛错 → npm run build → 重启宿主 → npm run smoke
报告：判定 ✗ 失败；任务终态 failed｜…｜语料 生成语料/种子起草/bad-<ts>.md
站行：种子起草 2 调用 1 成功 1 失败 50%｜失败码 SEED_GATE_FAILED×1
还原后重跑：判定 ✓ 跑通
```

## 影响

- 新增宿主文件 `src/host/smoke.ts`（G5 受控）、新路由（路由清单 127→128、探针 469→471、状态码分布 +2×500）、新命令（注册表 156→157）、面基线漂移三条（`content2.contentCheck` 转两面共享、`bank.load`／`paths.courseRoot` 进路由面）——全部随本提交迁移并登记于门册。
- nightly 挂接留后续（本票手动触发）；宿主要求「已编译 + 在跑」写在驱动脚本的指引分支里。
- worker 侧不改管线语义：`GenJob.quizCount` 是新增可选字段（缺省 = 今行为）。
