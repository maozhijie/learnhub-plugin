# 架构门清单、阈值来源与棘轮时序

#165 把三类架构债（子系统依赖面没有约束也没有测量、宿主零测试无法抽层、没有类型门）变成**会失败的东西**：门清单 + 阈值 + 棘轮机制。本 ADR 定门的清单、每条阈值的来源、棘轮的刚性，以及**时序**——顶层重划（ADR-0044／0045／0046）落地前，门**只作棘轮**（冻结现状、只许降不许升），不收紧到目标值。

理由：**门的形状比门的数量重要**，两条教训都指向形状。① **R3 曾恒过**：规则写了，但收集器只收相对说明符，于是从未触发——**一个恒过的门比没有门更坏**，它给出虚假的安全感。② **宿主抽离漏 14 个标识符**时，707 个测试全绿、`npm run build` 通过（esbuild 只剥类型）、`node --check` 只验语法——**只有运行时才会炸**。所以三条硬规定：**所有门零依赖**（文本／加载／编译层面、`node:test` 原生、随 `npm test` 全量执行；ADR-0042 已否决为静态规则引 eslint／dependency-cruiser）；**每个门必须带自检**（构造必然违规的样本、断言门会失败；收集器类门另须断言它能看见目标形态）；**阈值必须是实测数字**，来源写进 ADR 与票面。

## 门清单与档位

硬门＝零容忍；棘轮＝不高于基线。（编号与全量清单以 `docs/agents/architecture.md` §4 与门册为准，此后增补的门见门册。）

| 门 | 内容 | 档位 |
|---|---|---|
| **G1** 未定义标识符 | 剥注释与字符串后，「被当函数调用却未声明未导入」即失败（`scripts/undefined-scan.mjs`）。#170 起由 G7 的 TS2304 接管（同形态的编译期权威判据），本门保留作零依赖兜底 | 硬门 |
| **G2／G2b** 宿主装配面 | 动态 import `src/index.ts` 与 `host/*`；入口三件套齐备、技术层导出在。**G2 的加载冒烟不可退役**——tsc 看不见模块级初始化路径 | 硬门 |
| **G2c** 宿主模块级可变状态 | 宿主受控面（`src/index.ts` + `src/host/**/*.ts`，**动态发现**）除常量外零模块级 `let`；带自检与面塌断言 | 硬门 |
| **顶层不变量** | 只有教练层能调用图写原语；白名单＝`proposals.ts` | 硬门 |
| **窄面三向一致** | deps 声明 ↔ 类体 `this.e.X` 实用 ↔ 门面 `new XSubsystem({...})` 提供的键，任一方向多出或缺失即失败（dead／missing／unwired／surplus） | **四向全部硬门 0** |
| **窄面宽度** | 按三槽位卡上限（**顶层成员计，嵌套子面不计**） | 棘轮；`handles ≤12 / facade ≤20 / fns ≤10` 是**非活动目标** |
| **文件规模** | `src/`（`.ts`／`.tsx`）逐文件行数；白名单 `engine/views/`（类型面）、`engine/types.ts`（共享类型与枚举大表）、`engine/prompts/`（文本大表，ADR-0075） | 棘轮；`src/engine/*.ts` ≤600／宿主单文件 ≤900 是**非活动目标** |
| **类型门（G7）** | `tsc --noEmit` 按**文件**错误数棘轮 | 棘轮（现值 0 处 / 0 个涉错文件，基线 `typeErrors` 空表） |

档位依据：可棘轮化的债（宽度、规模、类型错误数）走逐文件／逐子系统基线；**装配断裂类（四向）不进基线**——它们是缺陷而非债，直接卡 0（一个恒须为空的清单留在基线里只会沉淀成幽灵条目，「接了一条没声明的线」本该当场失败）。

## 棘轮机制（刚性）

一份仓内基线记录每个受控量的实测值，门要求**实际 == 基线**：涨了失败，**降了但未同步下调基线也失败（过期即失败）**；基线只在清理提交里下调。理由：单侧棘轮（只拦上涨）的基线会沉淀成**永久余量**、逐条恒过，与 R3 恒过的教训同构；精确匹配是唯一不会腐烂的形状，代价只是每次清理顺手改一行。落地形态：基线 `scripts/arch-baseline.json` + 比较与重写 `scripts/arch-baseline.mjs`（`--update` 只在清理提交里用）。

**基线要自检**：门断言「基线里的每一项都对应一个受控对象」（防删除对象后留下永不复位的幽灵条目）——子系统、受控文件、规模白名单三类条目各有自检。

**测量口径**：测量在 `scripts/scan-*.mjs`；四向装配判定与文案只有一处（`scan-deps-face.mjs::faceViolations`，门与 CLI 共用）。类型门测量必须同时取回逐文件错误数与**受控面文件集**，并断言「`src/` 里每个 `.ts`／`.tsx` 都被 tsc 读到」（只看错误数分不清「干净」与「根本没扫」——R3 恒过的形状）；tsc 只报无文件位置的错误（tsconfig 写坏）时测量**抛错**而非静默返回空集。TLA 教训：测量脚本**不得**反向 import 基线模块（ESM 循环 + 顶层 await 死锁）。

## 时序与重划的关系

**顶层重划落地前，门只降不升。**与顶层重划冲突的门 → 记入 ADR 并标注「重划后重推阈值」，**不就地改阈值**。已知需重推的项：**文件规模**（重划改文件归属）、**窄面宽度**（三槽位分组改槽位归属）、**窄面三向**（子系统边界可能变）。600／900／12／20／10 因此在本 ADR 里**只是目标与记录，不是活动阈值**——用旧形状的阈值去绑定新边界，正是 #165 顶层判断要避免的事。

**类型门的四阶段**：① `src/` 基线建档并进门（允许存量错）→ ② 清**接线类**错误（未定义引用、字段声明丢失、指向不存在方法的接线）→ ③ 基线压到 0 并转 `strict: true` → ④ 收纳 `tests/`、评估 `ui/`。①②已落地（#178 四批把 `src/` 压到 0 处、根 tsconfig 已转 `strict: true`）；③④待开票。`tests/` 与 `ui/` 的类型面不在首期扫描面（各自配置另开步）。

## 修订登记

- **#158（2026-09-12）守卫消息契约的有意变更**：参数守卫错误消息从 `missing required field: <key>` 改为中文并以 `ParamError` 抛出（`缺少必填参数：<key>`），`handleApi` 统一 catch 追加 `（路由 <method> <route>）`；状态码语义（统一 500 出口）不变。**证据契约的措辞从此是「响应形状与守卫消息与基线一致」**——基线随每次有意的公共契约变更同提交迁移，而非永久冻结重构前的字面量。
- **#185（2026-09-12）可选参数收紧为 fail loud**，取代上条「可选参数宽松语义不动」：`host/params.ts` 十个可选守卫改为「键在场但类型不符即抛 `ParamError`」；`GEN_JOB_PHASES` 命名统一（持久化值变更）同票落地，走读侧别名迁移。详情见 ADR-0045 的后续裁决段与门册。

## 替代方案（否决）

- **单侧棘轮**（只在实际 > 基线时失败）——省事，但基线会沉淀成永久余量、逐条恒过，与 R3 恒过的教训同构。**这是本 ADR 最核心的否决。**
- **两套机制**（声明预算冻结成不可变的硬上限 + 独立基线文件只许降）——多一套机制、收益与「基线只许降且过期即失败」完全相同，还给「预算与基线谁先失效」留下解释空间。
- **无自检的门**——恒过比没有门更坏（虚假的安全感）；自检是门的一部分，不是可选项。
- **把 600／900／12／20／10 直接当活动阈值**——今天会立刻全红（8 个 engine 文件 + 宿主都超），与「门要先行且全绿」相抵，也会用旧形状的阈值去绑定新边界。
- **重划落地后一次性收紧所有阈值**——涨落会跨多个票同时到期，无法归因到具体改动；逐文件基线 + 过期即失败能让每次下调都落在产生它的那次清理里。
- **用聚合值（如「engine 总行数」）代替逐文件基线**——一个文件长、另一个缩就相互抵消，看不见病灶；门清单本就是按文件与按子系统下的。

## 边界

- **门的实现落点**：规则族进 `tests/import-rules.test.ts`（R1–R7）与 `tests/arch-guards.test.ts`（G 族）；测量在 `scripts/scan-deps-face.mjs`／`scan-budget.mjs`／`scan-invariant.mjs`／`scan-host-state.mjs`；门册 `tests/README.md` 同步登记。
- **不为门引入任何依赖**：不引 eslint／dependency-cruiser／prettier／zod（ADR-0042 替代方案段已否决）。
- **不设「零死导出」门**：实测零引用导出 0 条，此面无需门。
- **自检不止「违规会失败」**：收集器类门还要断言**扫描面没塌**（G3 断言收集到的 `XDeps` 集合与基线一致、G5 断言受控文件数 > 50）——R3 恒过的根因正是收集器静默收空。
- 本 ADR 不裁宿主 runtime 的设计（见 ADR-0048），只裁门的清单与刚性。

**历史读数**：#166–#171、#167、#168、#169 等逐票落地的实测数字（接线数 197／30／10、宽度 9／20／1、逐文件行数、错误码分布）已随清理推进失效——**当前实测一律以 `scripts/arch-baseline.json` 与 `node scripts/arch-baseline.mjs` 输出为准**；逐票落地叙述见各票票面与 `git log`。
