# 概念身份跨课程化：中心级登记表与全库联合唯一

#285 远期池的配套悬案「概念身份跨课程化」于 2026-09-16 拾起裁决（grilling 12 问，代码核验先行）。外部学习行为归因到概念时，课程级登记表即裂缝：外部行为没有课程边界，而沉淀层已用概念地址书写——概念地址天然该是中心级通用坐标。

## 裁决

1. **挂载层级上移**：登记表从「每课程一份（`课程根/概念登记表.yaml`）」上移为**中心级一份**（vault 根/概念登记表.yaml）。vault 是主权边界，登记表本就是全库坐标；「宣告式断裂」词条已特批登记表跨断裂存活，中心级位置与该地位一致。课程脚手架不再给每课程建空登记表。
2. **唯一性全域化**：全部名字的联合唯一从课程内扩为**全库**——一个名字全库至多属一条目。与「身份=条目、名字=地址、永不模糊匹配」公理直接连贯；引入名字作用域的方案否决（resolveConcept / 别名并入 / Vault 先验扩词全要带课程上下文，复杂度不可控）。
3. **无迁移直改**：项目高速迭代期、无存量数据需要迁移，不做读旧写新，直接改存储形状；子格式版本 bump（v0.3 → v0.4）留痕语义变更，不写任何兼容代码。
4. **归并走人审**：跨课程同名撞上（往往意味着同名不同义）是领域判断，铸名提案撞名一律走人工裁决（canonical 归谁、败方名字降级为别名），复用既有「提案 + 人确认」两段式；机器默认并入的方案否决。
5. **条目级语义原样上移**：别名、易混对、废弃生命周期（ADR-0084）、量级纪律、候选派生提案（#265）语义一字不改，仅取值域从「本课程」变「全库」（#232 的「同课程在册」措辞随之全局化）。
6. **消费面零改动**：四处只读消费方（分组轴概念轴 / Vault 先验扩词 / 教练工具 / growth-subsystem）经注入接口隔离，行为零改动是验收标准；growth-subsystem 的「每课程」展示措辞同步修正，文案不得撒谎。

## 影响

- 改动面集中：`paths.ts`（conceptRegistryPath）、`concepts.ts`（头注与唯一性）、`proposals.ts`（铸名撞名检测与脚手架）、`engine/index.ts`（挂载）；四个只读消费方不动。图查询证据：`ConceptRegistry` 入边分布与 grep 一致，影响面闭合。
- 词条：「概念坐标系（Concept Coordinate System）」入 `CONTEXT.md`；「概念」「概念登记表」两条同步修订。
- 实现票：从 #285 池勾出本项独立成票；#285 B 区「学习者模型作为宿主公共服务」依赖本悬案，其启动时标 blocked-by。

## 背景

远期池出处与四条配套架构悬案见 #285；本 ADR 只裁「概念身份跨课程化」一条，canonical 污染防线、外部结构不镜像成图、摄入流准入纪律三条仍停池中，拾起 A 区任何一条前再分别裁决。

## 修订（2026-09-16 二轮：同名异实、正名与引用面复核）

二轮 grilling 推翻本 ADR 原裁决 4 的方向——原判「跨课程同名撞上 = 同一身份候选，走人审归并」，把三类不同的事读成了一类。原裁决保留于上（不改写历史），以下为准。

**裁决 4 更正——分立是默认，归并要证据；且此默认只约束「新名入座」。** 同名撞上分三类，各走各的：① **同实异辞**（一个概念不同说法）→ 别名收编，无争议；② **同源异实**（词同源义不同、纠缠未断，如数学/编程的「函数」）→ **铸新条目 + 易混对**；③ **偶然撞名**（不同词翻译撞车，如代数的「域」与 DNS 的「域」）→ 铸新即可。归并必须证据驱动、人审、不可逆声明；默认方向由不可逆性的不对称决定（分立可逆、归并不可逆），与「条目禁删只并入」「账本只增不删」是同一条保守性纪律。并入还会**抹平 invokes 的诊断粒度**（合并后「你在函数上卡点」说不清是映射语义还是作用域），那是概念层最有价值的粒度。**边界（防精神泄漏）**：本默认只约束「新名入座」场景；**引用既有在册名字是合法首选**，不做对称要求——只有判据显示语义不同才铸新，不得让模型产生「没错也要被迫新建」的压力。

**裁决 7——撞名门带底细（成败点）。** 铸名精确撞名硬拒时，拒收文案必须携带在册条目底细：canonical、definition（缺席显式写「（无定义）」并注明判据不足）、足迹摘要（哪些节点/课程 teaches 它、invokes 分布）；并写明缺省动作：**判据不足 → 不得引用，改铸消歧名**。近似名预检提示行同时明示两个出口（**别名收编**＝同实异辞 / **分立**＝同源异实或偶然撞名）。理由：教练回合默认注入包（「登记表档位」区块）只含名字+档位、**不含定义**，不补底细则模型撞名时手里没有判据。

**裁决 8——引用面「跨课首引复核提示」（非阻，永不触发修复轮）。** 判据（纯读侧派生、零落盘、天然去重）：本批引用的概念在**本课程图**内 teaches/assumes 足迹为空（该课程首次引入它）。呈现于受理回执的 **findings/warns 面**（与近似名预检同形，**不得混入 errors**——混入即被读成拒收并触发重裁）；文案三段：① 语义现状（canonical + 定义或「（无定义）」+ 该条目现有足迹所在节点与 invokes 分布）；② **豁免句：「若本批内容真实调用的就是它，无需任何改动——本条只是可见性留痕」**；③ 仅当语义不同时的出口（按命名规范改铸消歧名）。一条概念在本课程只报一次（落盘后足迹非空自消）。理由：跨课引用是中心化的目的与常态（课程深度广度任意），不是异常；但受理一刻是全系统唯一「判据在场」的时刻——事后纠正面很薄（invokes 是出生字段、存量回填已裁取消、人侧无概念足迹可见面）。

**裁决 9——正名（Re-canonicalization）：只在撞名现场触发的最小人审动作。** 语义：在册条目 canonical 降为别名、新名升为主名（旧地址照旧解析、名字联合唯一不破、旧裸名仍占名位不可再铸）。两种用法同一动作：**追加别名**（同实异辞收编）／**换主名**（裸名澄清）。实现 = 一个纯函数（与 `mergeConceptEntries` 同层同规格）+ 一次 save + journal 一行；**人审直动作**（同废弃标记规格），不立提案 kind、不设独立入口、不做常态扫描；AI 侧提议沿用既有 `note.reason` 一句话先例，**AI 不得自行改在册名**；**可逆**，不写不可逆声明。呈现：铸名撞名的受理回执把它列为三选一（**引用** ／ **铸消歧名** ／ **正名既有条目**）。

**裁决 10——消歧名命名规范。** `基名（限定语）`，**全角括号**；限定语取**语义领域词**（数学/编程/代数），不用课程名（课程只是引用方集合、会漂）；基名原样保留在名前（近似名预检持续可命中）；禁嵌套超过一级（超过说明该拆概念）；消歧名可再正名。

**裁决 11——命名规范只进撞名回灌文案，不改提示词。** AI 只在撞名现场起消歧名，规范随拒收文案给到即可 → 零模板变更、零 `prompt-bump` 过门。判据驱动：若实测发现它在无撞名场景也乱起消歧名，再补提示词。**例外**：若最终仍改 `prompts/` 常量，则按章程 §8 补 `PROMPT_CHANGELOG` + 两条过门并收尾点名；门文案（引擎代码、模型可见）一并登记。

**裁决 12——AI 侧零新机制。** 撞名后自行改铸（提示词已有「已能用就不铸」）、顺手 `suggest_confusable`（执行官站既有糖算子，发布后自动展开为易混对候选待人审）、`note.reason` 一句话提议收编——三条都是现成机制，本票不新增任何 AI 侧能力。

**明确不做（附理由，防重复发明）**：① 新提案 kind `concept_rename`——AI 无提议的合理场景；② 图字段回写字面——别名解析已兜底，显示不齐后补（若做，复用回声通道的富化覆盖层，不是新机制）；③ 清单 canonical 归一注入——正名后裸名已精确定义，歧义已消，归一只是显示美化；④ 引用面的机器门——语义不可机器判，且会误杀正当跨课引用；⑤ 面板新页——执行面先备，面板接面另票。

**已识别缺口登记（本票不做，另票）**：① 人侧无概念足迹可见面（`concept_footprint` 只给 AI 读，无路由无页面）；② 题目的 `invokes` 无编辑通道（出生字段 + 存量回填已裁取消）——误引的事后纠正面因此很薄，这正是把判据前移到受理时刻（裁决 7/8）的理由。
