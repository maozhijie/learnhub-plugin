# 架构与门：面向 agent 的章程

本仓库的架构约定不只是注释和 ADR——**它们会失败**：分层规则（R1–R7）、架构门（G1–G9）、命令注册表八道门、类型门与各类棘轮，全部随 `npm test` 全量执行。这篇是它们的地图；每道门的阈值来源与实测链的唯一登记处在 [`tests/README.md`](../../tests/README.md)（门册），裁决与理由在 `docs/adr/`。

## 1. `npm test` 的真实构成

`npm test` = **`npm run typecheck` 先串行跑**（= `node scripts/arch-baseline.mjs --types` 类型门对照 + `node scripts/scan-ui-types.mjs` UI 类型门），然后才是全部测试。

**`npm run build` + `npm run check` 通过 ≠ 运行时安全**：esbuild 只剥类型、不查未定义全局，`node --check` 只验语法。实测教训（#152）：宿主抽离漏了 14 个标识符时，707 个测试全绿、build 通过——只有运行时才会炸。所以 G2 的动态 import 加载冒烟**不可退役**，tsc 看不见模块级初始化路径。

## 2. 棘轮的刚性

类型门、文件规模、窄面宽度等受控量走**精确匹配棘轮**：实测 == 基线——**涨了失败；降了但没同步下调基线也失败（过期即失败）**。两个直接后果：

- 遇到「基线不匹配」的失败**不是 bug，是门在执法**。不要绕过它，先读下面印出的违规行。
- 「我把错误改少了怎么反而失败」是正常现象：修好了就同一次提交里把基线一并下调。看当前实测与违规：`node scripts/arch-baseline.mjs`。按实测重写基线：`node scripts/arch-baseline.mjs --update`——**只在产生这次变更的提交里用**；涨了先看这行长在哪、能不能不长，确实该长（有登记的行为变更/新功能）才同步基线。

## 3. 规则族在哪、怎么单跑

| 规则族 | 测试文件 | 内容 |
|---|---|---|
| R1–R7 分层 | `tests/import-rules.test.ts` | host 只走 engine 门面、engine 禁引宿主与 `@deepseek-ai/*`、views 纯类型、io.ts 零依赖叶子、子系统不回引门面、src 全图零环 |
| G1–G9 架构门 | `tests/arch-guards.test.ts` | 未定义标识符、宿主装配面/模块级 let、窄面三向与宽度、文件规模、顶层不变量、类型门、适配器面、写入单元 |
| 注册表八道门 | `tests/commands.test.ts` | 命令声明的 engine 存在性、队列 phase、唯一性、handler 覆盖、指南投影、零运行时依赖、零行为漂移、声明与面一致 |

单跑脚本（都在 `scripts/`，输出与门一致）：`undefined-scan.mjs`／`scan-deps-face.mjs`（窄面三向+宽度）／`scan-budget.mjs`（文件规模）／`scan-invariant.mjs`（顶层不变量）／`scan-host-state.mjs`（模块级 let）／`scan-types.mjs`（类型清单）。命令注册表声明在 `src/commands/`。

## 4. 加新门／改阈值的纪律

- **每个门必须带自检**：构造必然违规的样本、断言门会失败；收集器类门另须断言它能看见目标形态。血的来源：R3 曾因收集器只收相对说明符而**恒过**；G3 的第三方向（门面接线）落地前脚本退出 0，对 30 条多余接线完全不可见。**恒过的门比没有门更坏。**
- **阈值必须是实测数字**，来源写进 ADR 与票面；不拍脑袋写「应该 ≤ N」。
- **与顶层重划冲突的门**：记 ADR 并标注「重划后重推」，不就地改阈值（600/900/12/20/10 这类目标值因此只是记录，不是活动阈值）。

## 5. 分层与顶层不变量（一句话版）

四层：`ui/` → 宿主（`src/index.ts` + `src/host/`）→ engine 门面（`src/engine/index.ts`）→ 子系统。方向规则见 R1–R7；顶层不变量：**只有教练层 `proposals.ts` 能调用图写原语**（`GraphStore.writeRegionDoc`，白名单唯一成员）。裁决见 ADR-0042（分层与规则执法）、ADR-0044（顶层分层与不变量）、ADR-0049（门面终态）。

## 6. 「公共面零改动」的正确读法

这是**逐刀纪律，不是永久不变量**（ADR-0049 更正）：每一刀重构不改公共面，使提交可独立回滚——但产品演化可以有意变更它。真正不可碰的面是**产品契约**：路由路径与响应形状、工具名与 schema、磁盘格式。要动它们 = **行为变更**，必须：票面逐条登记 → 探针快照/基线**同提交迁移**（快照是「变更前 vs 变更后」的唯一证据，`tests/helpers/regen-fixtures.mts` 重录、diff 逐条人审、status 漂移零容忍）→ ADR 登记（参见 ADR-0045 §#185 与 ADR-0047 §修订的先例）。
